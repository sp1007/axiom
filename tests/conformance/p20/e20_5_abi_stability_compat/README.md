# E20.5 Conformance Suite — ABI Stability Tiers, Versioned Symbol Contracts, `.axmeta` Binary Compatibility & `axiomc abi-check` (`SPEC-114`)

This directory contains the Phase 20 (`E20.5` / `T869`) end-to-end conformance suite for `spec/SPEC-114-abi-stability-versioning-binary-compat.md`:
- `e20_5_abi_stability_compat_oracle.test` & `e20_5_abi_stability_compat_oracle.py` — Master conformance oracle validating:
  1. Live bundled execution of `compiler/abi/stability/mod.ax`, `compiler/abi/fingerprint/mod.ax`, `compiler/abi/compat_diff/mod.ax`, and `compiler/driver/abi_cmd/mod.ax` (plus kernel, source, span, interner, diag, format, json, and query DB dependencies) with `e20_5_abi_stability_compat_probe.ax.in` across `--interp` and native `-O0` compilation (compiled at most once per `<120s` resource budget),
  2. Differential verification (`--interp` vs native `-O1 --verify-each`) across all 4 standalone `.ax` conformance fixtures,
  3. Production binary invariance and clean artifact audits confirming zero leaked `.axmeta`, `.axdb`, `.axmir`, `.axoracle`, or `.axlto` metadata sections or tokens in linked production `.exe` images.
- `abi_tiers_and_opaque_handle_evolution.ax` — 3-tier ABI separation (Tier 1 internal `extern "axiom"` with open-world optimizations, Tier 2 `.axmeta` package interface, Tier 3 `@abi(stable, version = "1.0")` frozen binary boundary; `AXS-ABI-001..003`), opaque handle evolution (private field additions, size changes, and alignment shifts behind `@opaque` pointer handles without invalidating downstream consumers or altering public `AbiFingerprint`; `0104 §11-12`, `tasks/0452 §193.16-17`, `AXS-ABI-013`, `INV-SABI-001`), and compile-time rejection of `@opaque` by-value instantiation (`AX_ABI_OPAQUE_BY_VALUE`).
- `boundary_type_rejection_firewall.ax` — Stable ABI firewall boundary verification (`AXS-ABI-004`, `REQ-ECO-8734`), allowed stable types (scalars, pointer handles, canonical `StableView<T>`, `StableStr`, allocator-paired `StableBuffer<T>`; `AXS-ABI-010..015`), compile-time rejection of unstable types with `AX_ABI_UNSTABLE_TYPE` (capturing closures, unrepr'd ADTs, uninstantiated generics, bare fat pointers `view`/`mut_view`/`Str`, raw slices by value, `dyn Trait`, unallocated `String`/`Vec`; `AXS-ABI-017`), raw generic export rejection (`AX_FFI_GENERIC_EXPORT`; `AXS-ABI-016`), and extensible struct header verification (`AX_ABI_EXTENSIBLE_MISSING_HEADER`; `AXS-ABI-011`).
- `fingerprint_triple_and_symbol_versioning.ax` — Three independent 128-bit BLAKE3 fingerprint domains (`ApiFingerprint`, `SemanticFingerprint`, `AbiFingerprint`; `AXS-ABI-020..024`, `tasks/0583 §324.2`, `tasks/0739 §493.21-23`, `INV-SABI-002`), invariance under non-inlined private edits vs inlined MIR vs physical layout shifts, deterministic `@symbol_version` mangling (`axiom_<pkg>_<mod>_<ident>@<version>` vs `@@<version>`), Windows PE/COFF `.edata` export aliases (`ident_v1_0` vs `ident`), multi-version coexistence in shared libraries, and duplicate symbol version rejection (`AX_ABI_SYMBOL_VERSION_DUPLICATE`; `AXS-ABI-030..032`).
- `abi_check_semver_compliance_matrix.ax` — `axiomc abi-check` SemVer compliance matrix (`AXS-ABI-040..042`, `REQ-PKG-022`, `REQ-PKG-024`), 3-way change classification (`compatible`, `minor-additive`, `major-breaking`), policy enforcement across patch, minor, major, downgrade, and no-semver modes with exact exit codes (0=PASS, 1=`AX_ABI_BREAKING_CHANGE`, 2=`AX_ABI_SEMVER_MISMATCH`), and JSON/text diagnostic report serialization.
