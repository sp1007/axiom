# E20.1 Conformance Suite — Canonical Build Graph, Declarative `axiom.toml` Workspace & Driver Orchestration (`SPEC-110`)

This directory contains the Phase 20 (`E20.1` / `T853`) end-to-end conformance suite for `spec/SPEC-110-build-graph-driver.md`:
- `e20_1_build_graph_driver_oracle.test` & `e20_1_build_graph_driver_oracle.py` — Master conformance oracle validating:
  1. Live bundled execution of `compiler/build/manifest/mod.ax`, `compiler/build/workspace/mod.ax`, `compiler/build/cache/mod.ax`, `compiler/build/graph/mod.ax`, and `compiler/driver/workspace_cmd/mod.ax` (plus kernel, source, diag, and query DB dependencies) with `e20_1_build_graph_driver_probe.ax.in` across `--interp` and native `-O0` compilation (compiled at most once per `<120s` resource budget),
  2. Differential verification (`--interp` vs native `-O1 --verify-each`) of all 4 standalone `.ax` conformance fixtures,
  3. Production binary invariance and clean artifact audits confirming zero leaked `.axmeta`, `.axdb`, `.axmir`, `.axoracle`, or `.axlto` sections or magic bytes in linked production `.exe` images.
- `workspace_dag_and_worker_invariance.ax` — Multi-package workspace DAG construction, path-independent `PackageIdentity` (`REQ-PKG-005`, `REQ-PKG-018`), deterministic topological ordering (`AXS-BLD-006`), worker-count invariance (1 vs 4 workers produce identical execution orders and aggregate output digests, `AXS-BLD-025`, `REQ-PKG-010`, `REQ-PKG-022`), and filesystem enumeration order (`readdir`) independence (`0168 §16-17`, `tasks/0411 §47`).
- `package_cycle_vs_intra_module_scc.ax` — Inter-package dependency cycle rejection with `AX_DRIVER_BAD_MANIFEST` (`data.kind = "package_cycle"`, `data.cycle = "alpha -> beta -> alpha"`, `AXS-BLD-003`, `REQ-PKG-008`, `AXS-BLD-050`) vs legal intra-package declaration SCC evaluation in `CompilerDB` (`REQ-PKG-009`, `SPEC-21`, `tasks/0356 §12`, `tasks/0661 §6`), and intra-package module import cycle rejection (`AX_NAME_IMPORT_CYCLE`, `SPEC-03`).
- `feature_cfg_and_semantic_firewall.ax` — Feature integrity and semantic non-interference (`REQ-PKG-025`, `INV-BLD-001`, no silent feature dropping, metadata never alters core language semantics), closed feature namespace and conflict rejection (`AXS-BLD-014..015`), `dev-dependencies` firewall (isolated to test/bench/examples, never leaking into downstream consumers or `lib` targets, `AXS-BLD-005`), and `Host` vs `Target` feature split.
- `cross_target_cache_and_driver_cli.ax` — Strict `Host`/`Target` cross-compilation split (`AXS-BLD-020..021`, rejection with `AX_LINK_ARTIFACT_TARGET_MISMATCH` = 220), 4-tier content-addressed build cache (`AXS-BLD-030`, `REQ-PKG-022`, `REQ-PKG-024`), interface early-cutoff cascade suppression (`AXS-BLD-031`), cache-poisoning/truncation defense with transparent recomputation (`AXS-BLD-032`), atomic staging (`AXS-BLD-033`), and `axiomc build|check|run|clean|graph --format=json|dot` CLI subcommands and exit codes (`AXS-BLD-040..042`, `INV-BLD-002`, `INV-BLD-003`).
