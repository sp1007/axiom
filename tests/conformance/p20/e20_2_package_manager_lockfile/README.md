# E20.2 Conformance Suite — Canonical `AXPACKAGE` Package Manager, SemVer 2.0 Resolution, Monotonic Feature Unification, Reproducible `axiom.lock` & Offline Vendoring (`SPEC-111`)

This directory contains the Phase 20 (`E20.2` / `T857`) end-to-end conformance suite for `spec/SPEC-111-package-manager-resolution-lockfiles.md` (`REQ-ECO-8736`, `REQ-PKG-022`, `REQ-PKG-024`, `REQ-PKG-025`, `INV-PKG-003`):

- `e20_2_package_manager_lockfile_oracle.test` & `e20_2_package_manager_lockfile_oracle.py`: Master conformance oracle validating:
  1. Live bundled execution of `compiler/pkg/semver/mod.ax`, `compiler/pkg/resolver/mod.ax`, `std/pkg/lockfile/mod.ax`, `std/pkg/store/mod.ax`, and `compiler/driver/pkg_cmd/mod.ax` (plus compiler kernel, diagnostic ux2, and build manifest dependencies) with `e20_2_package_manager_lockfile_probe.ax.in` across `--interp`, `-O0 --verify-each`, `-O1 --verify-each`, and `-O2 --verify-each` with byte-for-byte identical output parity.
  2. Differential verification (`--interp` vs native `-O1 --verify-each`) across all 5 standalone `.ax` conformance fixtures in this suite.
  3. Production binary invariance and clean artifact audits confirming zero leaked `.axmeta`, `.axdb`, `.axmir`, `.axoracle`, or `.axlto` metadata sections or tokens in linked production `.exe` images.
- `semver2_diamond_and_conflict_derivation.ax` — SemVer 2.0 total precedence ordering, caret/tilde/wildcard/range constraint evaluation, pre-release isolation rules (`AXS-PKG-004..005`, `1065 §9`), diamond dependency resolution within compatible SemVer tracks (`CompatTrack`, `AXS-PKG-011`), and deterministic human-readable PubGrub conflict derivation trees with step-by-step causal chains (`AXS-PKG-012`, `AXS-PKG-050`, `AX_DRIVER_BAD_MANIFEST` with `data.kind = "version_conflict"` and `data.derivation_chain`).
- `order_invariance_and_reproducible_lockfile.ax` — Manifest declaration-order invariance and filesystem candidate ordering invariance (`AXS-PKG-010`, `REQ-PKG-020`, `REQ-PKG-022`), canonical `axiom.lock` v1 schema and lexicographical sorting by `(namespace, name, version, source, env)` (`AXS-PKG-030`), deduplicated and sorted feature and dependency arrays, deterministic SHA-256 `graph_hash` binding, and exact byte-for-byte serialization reproducibility.
- `monotonic_feature_unification_and_rejection.ax` — Monotonic additive feature unification as the least fixed point union $F(P, \text{env}) = \bigcup \text{RequestedFeatures}(e)$ plus transitive implications (`AXS-PKG-023`), strict `Host` (`build`/`comptime`) vs `Target` (`normal`/`dev`) environment isolation, `dev-dependencies` scope isolation from production builds (`REQ-PKG-007`), explicit optional dependency activation, and immediate rejection (`AX_DRIVER_BAD_MANIFEST`) of undeclared features, mutually conflicting features (`conflicts_with`), or missing required features (`AXS-PKG-024`, `REQ-PKG-025`).
- `side_by_side_major_isolation_and_type_identity.ax` — Incompatible major version coexistence (`pkg@1.x` and `pkg@2.x`) in the same workspace (`AXS-PKG-020`, `REQ-PKG-011`), disjoint symbol mangling prefixes preventing link-time collisions, nominal type isolation (`TypeId(pkg@1, T) != TypeId(pkg@2, T)`) and compile-time rejection of cross-version type confusion (`AXS-PKG-021`, `AX_TYPE_MISMATCH` with `data.reason = "distinct_package_versions"`), explicit `public = true` `pub use` re-export bridging (`AXS-PKG-022`), and singleton native `links` exclusion (`AXS-PKG-020 §3`).
- `air_gapped_offline_vendor_and_drift_audit.ax` — `--locked` / `--frozen` lockfile drift detection against manifest constraints (`AXS-PKG-031`), SHA-256 `graph_hash` tamper detection rejecting byte modification (`data.kind = "lockfile_corrupt"`), SHA-256 content-addressed package store path formatting and mandatory pre-use digest verification (`AXS-PKG-032`), sandboxed extraction rejecting path-traversal (`..`, `/`, `C:\`) and archive quota limits, `axiomc pkg vendor` materialization of `vendor/` and `vendor/axiom-vendor.toml` (`AXS-PKG-033`), and hermetic air-gapped `--offline` execution with offline missing package detection (`data.kind = "offline_missing_package"`).
