# E20.4 Conformance Suite — Hermetic Build Sandbox, Cross-Directory Bit-for-Bit Reproducibility, Supply-Chain Trust & Ed25519 Signing (`SPEC-113`)

This directory contains the Phase 20 (`E20.4` / `T865`) end-to-end conformance suite for `spec/SPEC-113-hermetic-builds-supply-chain-trust.md` (`REQ-PKG-022`, `REQ-PKG-024`, `INV-HERM-001`, `INV-HERM-002`, `INV-HERM-003`, `INV-DET-002`):

- `e20_4_hermetic_supply_chain_oracle.test` & `e20_4_hermetic_supply_chain_oracle.py`: Master conformance oracle validating:
  1. Live bundled execution of `compiler/build/sandbox/mod.ax`, `compiler/build/repro/mod.ax`, `std/pkg/trust/mod.ax`, and `compiler/driver/trust_cmd/mod.ax` (plus compiler kernel, diagnostic ux2, workspace, and lockfile/store/archive dependencies) with `e20_4_hermetic_supply_chain_probe.ax.in` across `--interp`, `-O0 --verify-each`, `-O1 --verify-each`, and `-O2 --verify-each` with byte-for-byte identical output parity.
  2. Differential verification (`--interp` vs native `-O1 --verify-each`) across all 5 standalone `.ax` conformance fixtures in this suite.
  3. Production binary invariance and clean artifact audits confirming zero leaked `.axmeta`, `.axdb`, `.axmir`, `.axoracle`, or `.axlto` metadata sections or tokens in linked production `.exe` images.
- `bit_for_bit_reproducibility_and_path_remapping.ax` — Bit-for-bit identical executables, libraries, `.axmeta`, and `.axpkg` outputs under distinct host filesystem paths (`--remap-path-prefix`), virtual mount prefixes (`@pkg/...`, `@ws/`, `@std/`, `@gen/...`, `@out/`), residual host-path leak auditing, 12-component `HermeticBuildFingerprint` invariance across distinct checkout locations, worker counts (`--jobs 1` vs `--jobs 4`), environment noise, and locales, component sensitivity testing, and two-run differential reproducibility verification producing structured `ReproducibilityResult` reports (`REQ-PKG-022`, `SPEC-113 §3`, `AXS-HERM-020`..`023`).
- `hermetic_sandbox_isolation_and_boundary_defense.ax` — Hermetic build sandbox host isolation: canonicalize-before-authorize path resolution (`sandbox_normalize_path` -> resolve -> authorize), parent path traversal rejection (`../`, `..\\`, `/../`, ending `..`), unauthorized host absolute path rejection (`C:\...`, `/etc/...`), read-only protection of `/source`, `/dependencies`, and `@std` sysroot, confined artifact destination `/output` and `/build` scratch, ambient host environment scrubbing with empty `PATH = ""` and allowlist checking, deterministic virtual clock (`ClockPolicy.Frozen` and `Deterministic`), deterministic PRNG derived from package identity vs OS entropy denial, unconditional compile-time network ban (`NetworkPolicy.Denied`), and unauthorized subprocess lockdown (`ProcessPolicy.Denied`) (`REQ-PKG-022`, `REQ-PKG-024`, `SPEC-113 §2`, `AXS-HERM-010`..`015`).
- `dependency_capability_escalation_auditor.ax` — Supply-chain trust model (`Safe ≠ Trusted`, `Signed ≠ Correct`, `Hash ≠ Trust`), six canonical package capabilities (`unsafe`, `ffi`, `net`, `fs`, `process`, `asm`), bitmask representation and CSV parsing, package manifest declaration vs actual semantic usage, pre-build audit rejecting undeclared package capabilities (`TRUST_STATUS_UNDECLARED_CAPABILITY`), root workspace `[trust.policy]` allowlist enforcement, transitive capability closure fixed-point iteration, and immediate rejection of transitive capability escalation (`TRUST_STATUS_CAPABILITY_ESCALATION`) with detailed causal dependency path reporting (`REQ-PKG-024`, `SPEC-113 §1`, `AXS-HERM-001`..`004`).
- `ed25519_signature_trust_and_provenance.ax` — Deterministic Ed25519 digital signature generation (RFC 8032), public key fingerprinting (`HexLower(SHA256("AXKEY-ED25519-v1\0" || pk)[0..16])`), domain-separated package signature transcript generator (`"AXIOM-SIG-v1\0"`), cryptographic transcript signing and verification with small-order and malleability rejection, tamper detection rejecting modified Merkle root, SIF, ABI fingerprint, or signature bytes, workspace `TrustStore` enforcing active signer validity and rejecting untrusted or revoked keys, dual-signed `KeyRotationCert` key rotation, SLSA JSON build provenance attestation (`axiom.provenance.v1`) emission and verification, and Diverse Double-Compilation (DDC) 3-stage fixed-point verification ($\text{SHA256}(C_{2A}) == \text{SHA256}(C_{2B}) == \text{SHA256}(C_3)$) defeating self-propagating bootstrap backdoors (`SPEC-113 §4`, `AXS-HERM-030`..`035`).
- `trust_cmd_cli_and_diagnostic_contract.ax` — Axiom compiler supply-chain CLI subcommands (`axiomc trust keygen`, `sign`, `verify`, `rotate`, `axiomc audit`, `axiomc provenance emit|verify|inspect`), argument parser validation, deterministic exit codes (`TRUST_EXIT_OK`, `TRUST_EXIT_USAGE_ERROR`, `TRUST_EXIT_AUDIT_ERROR`, `TRUST_EXIT_SIGNATURE_ERROR`, `TRUST_EXIT_PROVENANCE_ERROR`), and canonical diagnostic mapping to `AX_DRIVER_BAD_MANIFEST` with structured `data.kind` discriminants (`"undeclared_package_capability"`, `"capability_escalation_denied"`, `"sandbox_fs_violation"`, `"sandbox_net_violation"`, `"sandbox_env_violation"`, `"sandbox_clock_or_rng_violation"`, `"sandbox_process_violation"`, `"repro_host_path_leak"`, `"repro_mismatch"`, `"signature_invalid"`, `"unsigned_package_rejected"`, `"untrusted_signer"`, `"revoked_signing_key"`, `"provenance_mismatch"`, `"ddc_mismatch"`) (`SPEC-113 §5`, `AXS-HERM-040`, `AXS-HERM-050`..`053`).
