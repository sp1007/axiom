# E20.7 Conformance Suite — Dynamic Components, Plugin Discovery, Cross-Boundary Ownership/Capability Isolation & Hot-Reload State Migration (`SPEC-115`)

This directory contains the Phase 20 (`E20.7` / `T873`) end-to-end conformance suite for `spec/SPEC-115-dynamic-components-plugins-hot-reload.md` (`REQ-ECO-8734`, `INV-COMP-001`, `INV-COMP-002`):

- `e20_7_dynamic_components_hot_reload_oracle.test` & `e20_7_dynamic_components_hot_reload_oracle.py`: Master conformance oracle validating:
  1. Live bundled execution of `compiler/component/interface/mod.ax`, `compiler/component/verify/mod.ax`, `std/component/loader/mod.ax`, and `std/component/hot_reload/mod.ax` (plus compiler kernel and ABI stability dependencies) with `e20_7_dynamic_components_hot_reload_probe.ax.in` across `--interp`, `-O0 --verify-each`, `-O1 --verify-each`, and `-O2 --verify-each` with byte-for-byte identical output parity.
  2. Differential verification (`--interp` vs native `-O1 --verify-each`) across all 4 standalone `.ax` conformance fixtures in this suite.
  3. Production binary invariance and clean artifact audits confirming zero leaked `.axmeta`, `.axdb`, `.axmir`, `.axoracle`, or `.axlto` metadata sections or tokens in linked production `.exe` images.
- `interface_negotiation_and_capabilities.ax` — Dynamic plugin discovery, pre-flight `.axcomp` section header inspection without executing arbitrary component initialization code (`AXS-COMP-010`), v1.0 -> v1.1 compatible interface negotiation and SemVer 2.0 Caret (`^`) range compatibility (`AXS-COMP-011`), cryptographic dual verification of `AbiFingerprint` (BLAKE3-128) and `TargetTripleFingerprint` against host environment with rejection of mismatches (`AX_COMP_ABI_MISMATCH` = 236, `AX_COMP_TARGET_MISMATCH` = 234; `AXS-COMP-012`), `ComponentId` format validation (`<vendor>.<namespace>.<name>`, `AXS-COMP-002`) and duplicate registration rejection (`AX_COMP_DUPLICATE_REGISTRATION` = 233), capability manifest verification, host granted capability subset enforcement, monotonic attenuation, and runtime revocation (`AXS-COMP-013`, `AXS-COMP-014`, `AX_COMP_CAPABILITY_DENIED` = 237, `AX_COMP_CAPABILITY_REVOKED` = 245), and type-safe interface acquisition via 128-bit `InterfaceFingerprint` dispatch binding (`AXS-COMP-015`).
- `boundary_firewall_and_allocator_isolation.ax` — `@component_interface` and `@plugin_export` boundary verification (`AXS-COMP-003`, `AXS-COMP-004`), compile-time and runtime rejection of raw pointer escapes (`*T`, `*mut T`) with `AX_COMP_RAW_POINTER_ESCAPE` (238; `AXS-COMP-020`), rejection of plain host heap allocations (`Box<T>`, `Vec<T>`, `String`) across dynamic boundaries with `AX_COMP_CROSS_ALLOCATOR_VIOLATION` (239), safe boundary crossing modes (scalars, `ComponentBox<T>`, `ComponentHandle<T>`, opaque pointers, and epoch-leased views), cross-boundary `ComponentBox<T>` originating-heap deallocation routing via `AllocatorVTable` (`AXS-COMP-021`), and generational `ComponentHandle<T>` table (`ComponentHandleTable`) slot allocation, retrieval with generation check, slot release & generation bump, detection of stale generation access (`AX_COMP_STALE_HANDLE` = 240), and detection of stale epoch access after epoch advance (`AXS-COMP-022`).
- `epoch_leases_and_unload_protection.ax` — `EpochTracker` and `ComponentLease` reference counting for borrowed views (`LEASE_KIND_BORROW`), background tasks (`LEASE_KIND_TASK`), ephemeral callbacks (`LEASE_KIND_CALLBACK`), and GPU fences (`LEASE_KIND_GPU_FENCE`) (`AXS-COMP-023`, `AXS-COMP-024`), strict unload prevention blocking physical library unmapping while `active_leases > 0` with `AX_COMP_UNLOAD_ACTIVE_LEASES` (241), quiescence phase transition rejecting new inbound lease acquisitions with `AX_COMP_COMPONENT_QUIESCING` (246), ephemeral callback detachment during quiesce, and verified clean unload upon full lease draining.
- `multi_epoch_hot_reload_and_state_migration.ax` — 5-phase deterministic hot-reload coordinator (`HotReloadManager`: `Quiesce` -> `ExportState` -> `LoadNewEpoch` -> `MigrateState` -> `Resume`; `AXS-COMP-030`..`037`), multi-epoch progression (Epoch 1 -> Epoch 2 zero-copy fast-path identity when `StateSchemaId` matches, Epoch 2 -> Epoch 3 schema evolution with registered migration hook; `AXS-COMP-034`), transactional rollback guarantees on quiesce timeout (`AX_COMP_QUIESCE_TIMEOUT` = 242), schema mismatch without hook (`AX_COMP_HOT_RELOAD_SCHEMA_MISMATCH` = 243), and migration hook failure (`AX_COMP_HOT_RELOAD_MIGRATION_FAILED` = 244) with zero state loss (`AXS-COMP-036`), and deferred physical unmapping of retired epochs once all active leases reach zero (`AXS-COMP-037`).
