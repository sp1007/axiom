# E20.6 Conformance Suite — Native SDK/Sysroot, AXTOOLCHAIN Distribution & Two-Machine Lockfile Reproducible Multi-Package Workspace (`SPEC-116`)

This directory contains the Phase 20 (`E20.6` / `T877`) end-to-end conformance suite for `spec/SPEC-116-sdk-sysroot-toolchain-distribution.md` (`REQ-ECO-8736`, `REQ-PKG-022`, `INV-SDK-001`, `INV-SDK-002`, `INV-SDK-003`) and certifies the **Phase P20 overall exit criterion** (`ROADMAP.md` §3):

> **Phase P20 Exit Criterion**: `multi-package workspace builds reproducibly from lockfile on two machines` (`REQ-PKG-022`, `AXS-SDK-055`).

---

## Suite Components

- `e20_6_sdk_toolchain_workspace_oracle.test` & `e20_6_sdk_toolchain_workspace_oracle.py`: Master conformance oracle validating:
  1. Live bundled execution of `compiler/sdk/sysroot/mod.ax`, `compiler/sdk/toolchain/mod.ax`, `compiler/driver/sdk_cmd/mod.ax`, `std/sdk/bundle/mod.ax`, `compiler/build/sandbox/mod.ax`, and `compiler/build/repro/mod.ax` (plus compiler kernel, diagnostic ux2, workspace, and lockfile/store dependencies) with `e20_6_sdk_toolchain_workspace_probe.ax.in` across `--interp`, `-O0 --verify-each`, `-O1 --verify-each`, and `-O2 --verify-each` with byte-for-byte identical output parity.
  2. Differential verification (`--interp` vs native `-O1 --verify-each`) across all 5 standalone `.ax` conformance fixtures in this suite.
  3. Physical two-machine multi-package workspace reproducibility verification: building a multi-package workspace (containing `lib_core`, `app_server`, `precomp_math`, and `plugin_codec`) from `axiom.lock` inside two completely isolated simulated machine environments (distinct root paths, usernames, temp dirs, environment variables, clock offsets, and thread counts) producing bit-for-bit identical binary artifacts (`REQ-PKG-022`, `AXS-SDK-055`).
  4. Production binary invariance and clean artifact audits confirming zero leaked `.axmeta`, `.axdb`, `.axmir`, `.axoracle`, or `.axlto` metadata sections or host path strings in linked production images.
- `cross_target_declarative_sysroot_and_crt.ax` — C-free cross-target compilation & declarative `.axsdk` sysroots across 6 canonical targets (`x86_64-windows`, `aarch64-windows`, `x86_64-linux`, `aarch64-linux`, `aarch64-macos`, `wasm32`), subsystem CRT startup contracts (`console` -> `main`, `windows` -> `WinMain`, `posix`/`freestanding` -> `_start`, `reactor` -> `_initialize`), dynamic import stubs resolution (PE DLL, ELF shared objects, Mach-O stubs, WASI stubs), hermetic ambient host OS path detection and fail-closed rejection (`AX_SDK_HOST_FALLBACK_DENIED`), compile-time OS API availability gating (`@available`) with `AX_SDK_API_UNAVAILABLE`, and domain-separated `SdkFingerprint` calculation & tamper rejection (`AX_SDK_FINGERPRINT_MISMATCH`) (`SPEC-116 §§1, 2`, `AXS-SDK-001`..`024`, `AXS-SDK-035`).
- `axtoolchain_bundle_packager_and_distribution.ax` — `AXTOOLCHAIN` target descriptor matrix covering Tier-1 and Tier-2 targets, triple alias normalization, ABI configuration, domain-separated `ToolchainFingerprint` calculation (`AXIOM_TOOLCHAIN_FINGERPRINT_V1\0`), deterministic archive packaging with normalized `mtime = 0` and `0755`/`0644` permissions, path traversal guards (`..`, absolute paths, drive letters), Merkle tree root calculation, Ed25519 digital signature verification with untrusted/revoked key rejection, side-by-side isolated install cache paths, and air-gapped offline mirror verification (`--offline`, `--mirror`) (`SPEC-116 §§3..5`, `AXS-SDK-025`..`034`, `AXS-SDK-043`..`046`).
- `lockfile_pinning_drift_and_tamper_defense.ax` — Multi-target `[sdk."<triple>"]` and `[toolchain]` table parsing and serialization in `axiom.lock`, strict `--locked` / `--frozen` verification, fail-closed rejection of tampered `SdkFingerprint` or `ToolchainFingerprint` with `AX_SDK_LOCK_MISMATCH`, missing target triple handling, and action cache key composition folding `ActionCacheKey = BLAKE3(PackageInputHash || SdkFingerprint || ToolchainFingerprint || BuildFlagsHash)` (`SPEC-116 §4`, `AXS-SDK-037`..`042`).
- `two_machine_reproducible_workspace_build.ax` — Phase P20 exit criterion simulation (`ROADMAP.md` §3, `REQ-PKG-022`, `AXS-SDK-055`): building a 4-package workspace (`lib_core` library, `app_server` binary, `precomp_math` precompiled interface, and `plugin_codec` dynamic component) from `axiom.lock` inside two completely isolated machine environments (Machine A: `/home/user_alice`, jobs 4, UTC; Machine B: `/srv/ci_worker_bob`, jobs 16, Asia/Tokyo) producing bit-for-bit identical binary digests, verifying canonical path prefix remapping (`@pkg`, `@ws`, `@std`, `@gen`, `@out`), and confirming zero host path leaks.
- `sdk_toolchain_cli_workflow_contract.ax` — Axiom compiler CLI subcommand engine (`axiomc sdk list|install|verify|pack|pin`, `axiomc toolchain list|info|verify|pack`), option parsing (`--available`, `--json`, `--all`, `--offline`, `--locked`, `--frozen`, `--mirror`, `-o`, `--target`, `--key`), deterministic exit codes (`SDK_EXIT_OK`, `SDK_EXIT_USAGE_ERROR`, `SDK_EXIT_VERIFY_ERROR`, `SDK_EXIT_SIGNATURE_ERROR`, `SDK_EXIT_IO_ERROR`), and canonical diagnostic mapping to `AX_SDK_*` codes (`SPEC-116 §5`, `AXS-SDK-047`..`054`).
