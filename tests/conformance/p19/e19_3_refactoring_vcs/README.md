# E19.3 Conformance Suite — Semantic Refactoring Engine, LSP `codeAction` / `codeAction/resolve`, and `AXDIFF` / `AXMERGE` / `AXPATCH` / `AXHISTORY` / `AXVCS` (`SPEC-102`)

This directory contains the Phase 19 (`E19.3` / `T811`) end-to-end conformance suite for `SPEC-102-refactoring-engine-semantic-vcs.md`:
- `e19_3_refactoring_vcs_oracle.test` & `e19_3_refactoring_vcs_oracle.py` — Master conformance oracle validating:
  1. Live bundled execution of `std/editor/mod.ax`, `std/vcs/mod.ax`, `compiler/query/db/mod.ax`, `compiler/lsp/protocol/mod.ax`, `compiler/lsp/vfs/mod.ax`, `compiler/lsp/handlers/mod.ax`, `compiler/refactor/transforms/mod.ax`, `compiler/refactor/code_actions/mod.ax`, `compiler/refactor/vcs/diff.ax`, `compiler/refactor/vcs/merge.ax`, `compiler/refactor/vcs/patch.ax`, `compiler/refactor/vcs/mod.ax`, and `compiler/driver/refactor_cmd/mod.ax` with `e19_3_refactoring_vcs_probe.ax.in` across `--interp` and native `-O0` compilation (compiled at most once per `<120s` resource budget),
  2. Differential verification (`--interp` vs native `-O1 --verify-each`) of all 4 standalone `.ax` conformance fixtures.
- `refactoring_semantics_preservation_before_after.ax` — Before-vs-after executable behavioral equivalence (`eval_before == eval_after`) across `extract_function` (`Copy` by value, `!Copy` read-only by `view<T>`, `!Copy` mutated by `mut_view<T>`, and `async` / `! Error` effect propagation), `extract_variable`, precedence-preserving `inline_variable` (`let y = x + 1` into `y * 2` -> `(x + 1) * 2`), `populate_match_arms`, `organize_imports`, `change_signature`, `move_item`, and `convert_capability_view`.
- `compiler_db_verification_gate_and_code_actions.ax` — Precondition & `CompilerDB` verification gate (`AX_MOVE_USE_AFTER_MOVE`, `AX_CAP_OUTLIVES_OWNER`, `AX_NAME_DUPLICATE`, `AX_BORROW_CONFLICT`, `let mut` inline rejection, non-exhaustive match rejection), `unsafe` synthesis firewall (`AX_UNSAFE_REQUIRED` + transactional `AXEDITOR` rollback), and LSP `textDocument/codeAction` / `codeAction/resolve` ranking, precondition filtering, and stale-revision `-32801 ContentModified` rejection.
- `axdiff_and_axmerge_three_way_semantic_vcs.ax` — `AXDIFF` tree-vs-text formatting neutrality (`formatting_only == true`), intra-module declaration reordering (`Moved`, `Exact`), cross-name refactoring (`Renamed`, `Strong` — never `Exact`), receiver capability breaking change (`CapabilityChanged`, `Breaking`), `@repr(C)` layout change (`LayoutChanged`, `AbiImpact.Breaking`), 9-state lattice `Incomparable != Identical`, and `AXMERGE` three-way AST merge (commutative `use` import union, idempotent convergence, simultaneous rename+body auto-merge, structural `RenameIdentityConflict` / `SignatureConflict` with canonical `<<<<<<<`/`|||||||`/`=======`/`>>>>>>>` markers, and post-merge `CompilerDB` `SemanticConflict` downgrade).
- `axpatch_axhistory_and_axvcs_determinism.ax` — `AXPATCH` span-independent AST relocation (`AppliedRelocated`), exact inversion (`axpatch_reverse`), transactional rollback on `CompilerDB` failure, algebraic composition (`axpatch_compose`), and semantic rebase (`axpatch_rebase`); `AXHISTORY` multi-hop lineage (`Created -> Renamed -> Moved -> ExtractedFrom`), property-level blame skipping formatting-only commits, and non-resurrected recreation stop (`HISTORY-INV-14`); and `AXVCS` timestamp-independent revision hashes, permutation-invariant `Tree`/`Semantic` snapshots, BLAKE3 integrity verification, atomic CAS ref updates, fast-forward push checks, Git adapter mapping, and CLI exit codes (`0`, `1`, `2`).
