Tiếp tục với **BOOTSTRAP-031 — Generics, Traits, Associated Types, Specialization & Monomorphization**.

Đây là phần rất quan trọng vì generic/trait system có thể quyết định Axiom đạt được **zero-cost abstraction** hay biến thành một type system nặng nề.

Tôi đề xuất Axiom đi theo hướng:

> **Generics mạnh, traits rõ ràng, static dispatch mặc định, monomorphization mặc định, specialization có kiểm soát; không xây một hệ thống trait solver quá phức tạp chỉ để mô phỏng mọi khả năng của C++/Rust.**

---

# 1. Generic là compile-time abstraction

Ví dụ:

```axiom
fn max<T: Ord>(a: T, b: T) -> T {
    if a > b { a } else { b }
}
```

`T` không phải runtime type.

Compiler tạo specialization:

```text
max<i32>
max<f64>
max<MyType>
```

nếu cần.

Sau optimization, generic abstraction có thể biến mất hoàn toàn.

---

# 2. Generic không tạo runtime metadata mặc định

Không có mặc định:

```text
TypeInfo
vtable
reflection object
generic context
```

được truyền vào function.

Ví dụ:

```axiom
fn add<T: Add>(a: T, b: T) -> T
```

với `i32` có thể compile trực tiếp thành:

```asm
add eax, ebx
```

Không cần:

```text
runtime type lookup
virtual dispatch
boxing
```

---

# 3. Trait là constraint + behavior

Trait:

```axiom
trait Add {
    fn add(self, other: Self) -> Self
}
```

không phải:

```text
class
interface object
runtime object
```

Nó mô tả:

```text
type supports this semantic contract
```

---

# 4. Trait implementation

```axiom
impl Add for Vec2 {
    fn add(self, other: Vec2) -> Vec2 {
        ...
    }
}
```

Compiler biết:

```text
Vec2 → Add
```

tại compile time.

---

# 5. Trait không tạo vtable

Đây là default:

```text
T: Trait
    ↓
static dispatch
```

Không:

```text
object
 ├── data
 └── vtable
```

trừ khi programmer sử dụng:

```axiom
dyn Trait
```

---

# 6. `dyn Trait` là dynamic dispatch explicit

Ví dụ:

```axiom
fn render(x: dyn Renderable) {
    x.render()
}
```

lúc này programmer **đã yêu cầu dynamic dispatch**.

Compiler có thể sử dụng representation kiểu:

```text
data pointer
+
dispatch metadata
```

nhưng layout không bị đóng băng ở Core.

---

# 7. Không có implicit boxing để satisfy trait

Đây là điểm quan trọng.

Không cho compiler tự biến:

```axiom
render(my_struct)
```

thành:

```text
heap allocation
boxing
vtable
```

chỉ vì function yêu cầu `dyn Renderable`.

Nếu dynamic representation cần thiết, programmer phải đi qua abstraction tương ứng.

Điều này bảo vệ performance predictability.

---

# 8. Trait bounds

Có thể viết:

```axiom
fn sort<T: Ord>(items: mut_view<[T]>)
```

hoặc nhiều constraint:

```axiom
fn process<T: Read + Write + Send>(x: T)
```

Compiler tạo obligation:

```text
T implements Read
T implements Write
T implements Send
```

---

# 9. Trait bound không phải inheritance

Không có:

```text
Animal
   ↑
Dog
```

Thay:

```text
trait Animal { ... }

impl Animal for Dog { ... }
```

`Dog` vẫn là `Dog`.

Không có subtype relationship mặc định.

---

# 10. Trait composition

Có thể:

```axiom
trait ReadWrite: Read + Write {
}
```

Semantic:

```text
ReadWrite<T>
    ⇒ T: Read
    ⇒ T: Write
```

Không cần runtime multiple inheritance.

# 11. Associated type

Đã xác định Axiom hỗ trợ.

Ví dụ:

```axiom
trait Iterator {
    type Item

    fn next(self: mut_view<Self>) -> Option<Self.Item>
}
```

Implementation:

```axiom
impl Iterator for Range {
    type Item = i32

    fn next(...) -> Option<i32> {
        ...
    }
}
```

---

# 12. Associated type khác generic parameter

Generic:

```axiom
trait Convert<T> {
    fn convert(...)
}
```

cho phép nhiều `T`.

Associated type:

```axiom
trait Iterator {
    type Item
}
```

mỗi implementation xác định một `Item`.

Điều này làm API:

```axiom
Iterator<Item = Token>
```

rõ hơn.

# 13. Associated constants

Cho phép:

```axiom

    const ONE: Self
```

Compiler có thể materialize thành constant.

Không runtime metadata.

# 18. Generic không có runtime erasure bắt buộc

```text
 ↓
```

# 19. Monomorphization

Mặc định:

```text
Generic MIR
    ↓
substitute concrete types
    ↓
specialized MIR
    ↓
optimization
```

Ví dụ:

```axiom
fn sum<T: Add + Zero>(xs: view<[T]>) -> T
```

sinh:

```text
sum<i32>
sum<f32>
sum<f64>
```

nếu được sử dụng.

---

# 20. Nhưng không tạo duplicate code vô hạn

Compiler cần **generic instance deduplication**.

Ví dụ nhiều module cùng dùng:

```text
Vec<i32>
```

không được sinh 15 bản copy.

Compiler có:

```text
InstantiationKey
```

đại diện:

```text
module
generic declaration
type arguments
const arguments
configuration
```

→ một specialization.

---

# 21. Cross-module generic instantiation

Ví dụ package:

```text
lib
 └── Vec<T>
```

application:

```text
Vec<MyType>
```

Compiler cần có generic semantic representation trong module interface.

Không cần source code của library nếu semantic generic body đã được đóng gói dưới dạng compiler-readable artifact.

Điều này rất quan trọng cho incremental compilation.

---

# 22. Generic body phải được compiler kiểm tra thế nào?

Có hai tầng.

### Generic definition checking

Compiler kiểm tra:

```text
T: Ord
```

thì chỉ được sử dụng API mà `Ord` đảm bảo.

### Instantiation checking

Khi:

```text
T = MyType
```

compiler verify:

```text
MyType: Ord
```

# 23. Không cho "duck typing"

Không:

```text
có method add() → tự coi là Add
```

Axiom dùng nominal trait implementation.

Phải có:

```axiom
impl Add for MyType
```

hoặc compiler-known structural mechanism nếu sau này explicitly thêm.

Điều này làm compiler deterministic.

---

# 24. Trait coherence

Một trait implementation phải có owner rõ ràng.

Không để hai package độc lập cùng tạo:

```text
impl ExternalTrait for ExternalType
```

rồi compiler không biết chọn cái nào.

Quy tắc:

> Ít nhất trait hoặc type phải thuộc package/module đang định nghĩa implementation.

Đây là orphan/coherence rule.

---

# 25. Vì sao cần coherence?

Nếu:

```text
Package A:
    impl Serialize for User

Package B:
    impl Serialize for User
```

thì:

```text
Serialize(User)
```

không deterministic.

Axiom không nên giải quyết bằng "chọn implementation gần nhất".

---

# 26. Không có arbitrary specialization v1

Đây là một quyết định quan trọng.

Không nên ngay lập tức cho:

```axiom
impl<T> Foo for T { ... }

impl Foo for i32 { ... }

impl<T: Special> Foo for T { ... }
```

với hàng đống overlap rules.

Trait solver sẽ rất phức tạp.

---

# 27. Specialization có kiểm soát

Tôi đề xuất v1:

```text
generic implementation
+
concrete implementation
```

chỉ được phép nếu compiler có quy tắc ưu tiên deterministic.

Ví dụ:

```axiom
impl<T: Numeric> Zero for T
```

và:

```axiom
impl Zero for BigInt
```

`BigInt` chọn concrete implementation.

Nhưng không cho arbitrary overlapping generic implementations.

---

# 28. Có thể thêm specialization sau

Về sau:

```axiom
@specialize
impl<T> ...
```

nhưng nó phải là compiler feature có luật rõ ràng.

Không đưa vào Core v1 chỉ vì muốn tối ưu.

Không cần programmer viết:

```axiom

```

Optimization không phải specialization semantic.

# 41. Trait object safety


# 50. Erased generics chỉ khi cần

# 67. Generic + GPU

Ví dụ:

```axiom
@kernel
fn add<T: Numeric>(
    a: view<[T]>,
    b: view<[T]>,
    out: mut_view<[T]>
)
```

Compiler instantiate:

```text
add<f32>
add<f16>
add<i32>
```

sau đó target GPU lowering.

Trait resolution xảy ra **trước** GPU machine lowering.

GPU backend không cần hiểu trait system.

# 68. Generic + SIMD

Ví dụ:

```axiom
fn add<T: Numeric, const N: usize>(
    a: Vec<T, N>,
    b: Vec<T, N>
)
```

Compiler có thể biết:

```text
N = 4
T = f32
```

và generate SIMD.

Không cần programmer viết intrinsic cho abstraction-level code.

Intrinsic vẫn tồn tại khi cần kiểm soát machine-level.

```text
   comptime
```

```text
class inheritance
virtual method
RTTI
```

làm nền tảng.
