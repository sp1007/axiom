Tiếp tục. Tôi sẽ khóa **Execution + Concurrency Model v0.1** theo hướng: compiler hiểu đủ để đảm bảo ownership/suspension và tạo machine code tốt, nhưng **không biến scheduler/executor thành runtime bắt buộc**.

# 1. Tách 5 khái niệm

Axiom cần phân biệt tuyệt đối:

```text
Function
    = code chạy tuần tự

Thread
    = execution context thực

Task
    = logical unit of work

Async state machine
    = representation của task có thể suspend

Executor/Scheduler
    = cơ chế quyết định task nào chạy ở đâu
```

Đây là:

```text
code ≠ thread ≠ task ≠ executor
```

---

# 2. Function

Function bình thường:

```axiom
fn add(a: i64, b: i64) -> i64 {
    a + b
}
```

không có concurrency semantics.

Compiler có thể:

```text
inline
tail-call
vectorize
constant-fold
```

hoàn toàn bình thường.

---

# 3. Thread

Thread là execution resource.

Ví dụ library:

```axiom
let h = thread.spawn(|| {
    work();
});
```

Semantic:

```text
current execution
        │
        └── spawn
              ↓
        independent execution
```

Thread là OS/platform concept, không phải compiler runtime bắt buộc.

---

# 4. Task

Task không nhất thiết có thread riêng.

```text
1000 tasks
      ↓
4 OS threads
```

là hoàn toàn hợp lệ.

Do đó:

```text
Task ≠ Thread
```

---

# 5. Async

`async` biểu diễn:

> Function có thể suspend và tiếp tục sau đó.

Ví dụ conceptual:

```axiom
async fn fetch() -> Result<Data, Error> {
    let x = await read();
    process(x)
}
```

Compiler biến thành state machine.

---

# 6. Async state machine

Conceptually:

```text
struct FetchState {
    state: StateId
    x: ...
    temporary_data: ...
}
```

và:

```text
fn poll(state: mut_view<FetchState>) -> Poll<Result<Data, Error>>
```

Nhưng đây chỉ là **compiler lowering**, không nhất thiết là source-visible struct.

---

# 7. Async không cần runtime

Đây là quyết định quan trọng:

```text
async fn
    ↓
state machine
```

không tự kéo:

```text
executor
thread pool
event loop
reactor
timer runtime
```

vào executable.

Nếu programmer muốn chạy:

```text
block_on(task)
```

thì library cung cấp executor.

---

# 8. Async function return type

Source:

```axiom
async fn foo() -> i64
```

Semantic không nhất thiết là:

```text
i64
```

runtime.

Nó conceptually là:

```text
Future<Output = i64>
```

nhưng tôi đề xuất compiler có thể coi `Future` là một compiler-known lowering concept, trong khi public `Future` trait/API thuộc library.

# 9. `await`

`await` là nơi compiler bắt buộc phải hiểu.

```text
expression
 ↓
may suspend
 ↓
state machine split
```

Mỗi `await` tạo một potential suspension point.

---

# 10. Không phải function call nào cũng suspend

```axiom
let x = foo();
```

nếu `foo` sync:

```text
CALL
```

Nếu:

```axiom
let x = await foo();
```

thì:

```text
CALL
 ↓
obtain suspendable operation
 ↓
POLL
 ↓
Pending → save state + suspend
Ready → continue
```

# 11. Async ABI

Compiler có thể lower:

```text
async fn foo(...)
```

thành một hidden state machine type.

Ví dụ conceptually:

```text
foo(args)
 ↓
FutureState
```

Nhưng representation hoàn toàn compiler-controlled.

Không cần heap allocation mặc định.

---

# 12. Async allocation

Một async function:

```axiom
async fn small() -> i64 {
    ...
}
```

có thể:

```text
caller stack
register
inline state
```

Không cần:

```text
heap allocation
```

trừ khi executor/library yêu cầu task escape.

---

# 13. Đây là điểm Axiom có thể mạnh hơn nhiều async runtime

Ví dụ:

```text
async fn process() -> i64
```

nếu compiler biết:

```text
không escape
single caller
```

thì có thể eliminate phần lớn state-machine overhead.

```text
Abstraction
    ↓
async lowering
    ↓
optimization
    ↓
ordinary control flow
```

nếu không thực sự cần suspension.

---

# 14. Suspension semantics

Trước `await`:

```text
local x
```

nếu `x` được dùng sau await:

```text
await foo()
use(x)
```

thì `x` phải tồn tại qua suspension.

Compiler có thể:

```text
register
→ state field
```

hoặc stack frame/state object.

---

# 15. Nếu local không sống qua await

```axiom
let x = compute();
use(x);
await foo();
```

thì `x` có thể biến mất trước suspension.

Compiler không cần lưu nó trong state machine.

Đây là **liveness analysis**.

---

# 16. Ownership qua await

Ví dụ:

```axiom
let file = open()?;
await network();
use(file);
```

`file` sống qua await.

Compiler phải preserve ownership:

```text
OWNED
 ↓
SUSPEND
 ↓
OWNED
```

Không được Drop trong lúc task suspended.

---

# 17. `mut_view` qua await

Đây là case nguy hiểm:

```axiom
let v = mut_view(buffer);

await network();

use(v);
```

Trong v0.1, tôi đề xuất:

> **Reject nếu `mut_view` còn sống qua suspension.**

Trừ khi compiler chứng minh ownership/execution context an toàn một cách chắc chắn.

Lý do rất đơn giản: tránh tạo ra một capability mutable treo trong state machine.

---

# 18. `view` qua await

`view<T>` có thể tồn tại qua await nếu compiler chứng minh:

```text
owner vẫn sống
owner không bị mutate/conflict
provenance valid
task có quyền giữ capability
```

Ví dụ owner là static:

```axiom
static TABLE: Array<u8, 256>;

async fn foo() {
    let v = view(TABLE);
    await something();
    use(v);
}
```

có thể hợp lệ.

---

# 19. Async task migration

Một task có thể:

```text
thread 1
   ↓
await
   ↓
thread 4
```

Nếu executor cho phép migration.

Khi đó captured state phải thỏa:

```text
Send
```

---

# 20. `Send`

`Send<T>` nghĩa:

> Ownership của `T` có thể chuyển sang execution context khác.

Ví dụ:

```text
Box<Data>
```

nếu `Data: Send`:

```text
thread A
   ↓ MOVE
thread B
```

OK.

---

# 21. `Share`

`Share<T>` nghĩa:

> `T` có thể được safely shared for concurrent read/access according to its synchronization semantics.

Quan trọng:

```text
Send != Share
```

Ví dụ conceptual:

```text
T: Send
T: !Share
```

hoàn toàn hợp lệ.

---

# 22. `Arc<T>` không tự biến T thành thread-safe

Ví dụ:

```text
Arc<UnsafeMutableState>
```

không tự nhiên trở thành safe.

Cần:

```text
Arc<Mutex<State>>
```

hoặc atomic abstraction.

Nguyên tắc:

```text
shared ownership
    ≠
synchronized mutation
```

---

# 23. Thread spawn

Ví dụ:

```axiom
thread.spawn(|| {
    work(data);
});
```

Compiler phân tích closure:

```text
closure environment
 ├── data
 └── captures
```

Nếu thread có thể outlive caller:

```text
captured values must be owned
```

Không được capture reference/view tới local sắp chết.

---

# 24. Ví dụ sai

```axiom
fn foo() {
    var x = 10;

    thread.spawn(|| {
        println(x);
    });
}
```

Nếu spawn detached:

```text
foo returns
x dies
thread still runs
```

→ reject nếu closure chỉ giữ view/reference tới `x`.

---

# 25. Move capture

Có thể:

```axiom
thread.spawn(move || {
    println(x);
});
```

Khi đó:

```text
x
 ↓ MOVE
closure environment
 ↓
thread
```

Ownership rất rõ.

---

# 26. Nhưng Axiom có cần keyword `move`?

Tôi nghĩ:

> **Có, nhưng chỉ như một explicit override.**

Mặc định compiler infer capture mode.

Ví dụ closure chỉ đọc `x`:

```axiom
|y| x + y
```

→ READ capture.

Nếu cần force ownership:

```axiom
move |y| x + y
```

→ MOVE capture.

Điều này giữ source đơn giản nhưng vẫn có escape hatch.

---

# 27. Detached task

Structured concurrency nên là default library design.

Ví dụ:

```text
scope.spawn(...)
```

task được join trước khi scope kết thúc.

Nếu muốn detached:

```text
detach(task)
```

phải explicit.

Lý do:

```text
detached task
+
captured resource
```

là lifetime hazard.

---

# 28. JoinHandle

`thread.spawn` có thể trả:

```text
JoinHandle<T>
```

Handle sở hữu logical task handle.

```axiom
let h = thread.spawn(...);
let result = h.join()?;
```

Nếu `JoinHandle` bị Drop thì semantics cần quyết định.

Tôi đề xuất:

> **Drop handle không tự động kill thread.**

Nó chỉ release quyền join.

Nếu muốn cancellation:

```text
h.cancel()
```

explicit.

---

# 29. Thread cancellation

Không cho:

```text
kill_thread(h)
```

như safe primitive.

Arbitrary thread kill có thể bỏ qua:

```text
locks
resources
invariants
partial writes
```

Cancellation nên cooperative.

---

# 30. Async cancellation

Tương tự.

Task có thể:


Library có thể thiết kế:

```text

```

nếu API muốn.

Cancellation không phải language-level exception.

# 38. Parallelism

Axiom cần phân biệt:

```text
Concurrency
Parallelism
```

Concurrency:

```text
task A
task B
interleaved
```

Parallelism:

```text
CPU 1 → A
CPU 2 → B
```

Language semantics chủ yếu đảm bảo safety.

Scheduler quyết định actual parallel execution.

# 39. Parallel loops

Có thể để library:

```text

```

Compiler không nhất thiết có:

```text
parallel for
```

primitive.

Nếu sau này compiler có optimization:

```text
auto-vectorize
auto-parallelize
```

thì đó là optimization, không thay đổi semantics.

# 40. Data parallelism

Ví dụ:

```axiom
for i in 0..n {
    output[i] = input[i] * 2;
}
```

Compiler có thể vectorize.

Nếu iteration regions độc lập:

```text
output[i]
input[i]
```

compiler có thể chứng minh noalias.

Không cần programmer viết parallel annotations.

# 41. Nhưng auto-parallelization không nên là semantic guarantee

Nếu compiler hôm nay:

```text
single-thread
```

và ngày mai:

```text
8 threads
```

thì observable behavior phải vẫn hợp lệ.

Vì vậy race-free semantics là bắt buộc.

Nếu:


# 51. Async state machine + Drop

Đây là chỗ compiler cần cực kỳ cẩn thận.

Ví dụ:

```axiom
async fn foo() {
    let a = ResourceA();
    await x();
    let b = ResourceB();
    ...
}
```

Nếu task bị cancelled tại suspension:

```text
state machine Drop
```

phải drop:

```text
a
```

và những resource hiện đang initialized.

Compiler phải generate:

```text
cleanup states
```

tương tự function return.

---

# 52. Async Drop state

Conceptually:

```text
State 0:
    a uninitialized

State 1:
    a owned
    suspend

State 2:
    a owned
    b owned
    suspend
```

Drop handler:

```text
State 1 → drop a
State 2 → drop b, then a
```

Không được double-drop.

---

# 53. Async + partial move

Nếu:

```axiom
let resource = Resource { a, b };
move resource.a;
await x();
use resource.b;
```

state machine phải giữ partial ownership state.

Đây là lý do ownership verifier phải chạy **trước/sau async lowering** theo cách phối hợp.

```text

      ↓
```

```text
optimizer erases abstractions
      ↓
runtime exists only where demanded
      ↓
machine code
```

Điều này giải quyết đúng nỗi lo ban đầu của bạn về **GC / borrow checker / runtime overhead**:

- Không GC.
- Không RC ngầm.
- Không lifetime annotation.
- Không borrow syntax kiểu Rust.
- Không async runtime bắt buộc.
- Không thread runtime bắt buộc.
- Không object header.
- Không heap allocation bắt buộc.
- Không dynamic dispatch mặc định.

Nhưng compiler vẫn có thể thực hiện ownership/lifetime/alias analysis rất sâu ở phía sau.
