# 155. Một nguyên tắc thống nhất: mọi control-flow edge đều phải chạy cleanup

Ví dụ:

```axiom
fn f() -> Result<i32, Error> {
    let file = open()?
    let value = compute()?
    return Ok(value)
}
```

Tất cả đường:

```text
normal return
early return
?
panic
```

đều phải được compiler biến thành các CFG edge có cleanup tương ứng.

MIR conceptually:

```text
                 ┌───────────────┐
                 │     BODY      │
                 └───────┬───────┘
                         │
              ┌──────────┼──────────┐
              │          │          │
           return        ?        panic
              │          │          │
              └──────────┼──────────┘
                         ↓
                     CLEANUP
                         ↓
                      EXIT
```

# 168. Panic trong Drop

Đây là edge case nguy hiểm.

Nếu:

```axiom

    ...
```

# 185. Channel

# 208. Control-flow freeze

| Edge | Cleanup | Suspension |

| return | yes | no |

# 209. Một refinement rất quan trọng về `abort`

> `abort` không cleanup.

- Process termination xảy ra ngay theo target/runtime contract.
- Compiler không phải giữ unwind cleanup path.

Nhưng nếu OS/runtime có cleanup khi process exit thì đó là external behavior, không phải Axiom Drop guarantee.

### Case 1


→ **không đoán** → error.

### Case 3

```axiom

```

Không rõ closure có thể escape.

Compiler biết từ API `spawn` rằng closure escapes.

→ yêu cầu ownership capture.

### Case 4

```axiom
await work()
use(view_x)
```

Compiler biết capability crosses suspension.

→ reject.

### Case 5

```axiom
dyn Trait
```

Programmer explicit dynamic dispatch.

→ compiler không đoán static/dynamic.

### Case 6

```axiom
let x = []
```

Type chưa đủ constraint.

→ ambiguous error.

Đúng nguyên tắc:

> **Không đoán programmer intent.**

---

# 213. Nhưng compiler được phép "đoán" implementation strategy

Đây là distinction quan trọng.

Compiler **được** tự quyết:

```text
stack vs heap
register vs memory
inline vs call
monomorphize vs share code
eliminate allocation
eliminate bounds check
vectorize
tail call
closure elimination
Future elimination
```

vì chúng không thay đổi semantic intent.

Do đó nguyên tắc hoàn chỉnh:

> **Compiler may infer implementation strategy, but may not infer semantic intent.**

Tôi đề nghị đưa câu này vào phần Philosophy của Axiom.

Đến đây các phần khó nhất đã khá ổn:

```text
Memory / Ownership       ████████████████████
Type System              ████████████████████

Async                    ████████████████████
```

Còn hai vùng cần audit cuối:

### Pass #5
**ABI / FFI / Representation / Object Layout / Native Binary**

### Pass #6
**GPU / Package / Build / Compile-time / Reflection / Tooling**

Sau đó mới thực hiện **Global Semantic Freeze**, trong đó tôi sẽ dựng một bảng duy nhất:

```text
Rule

```

và loại bỏ những invariant trùng lặp hoặc nằm sai tầng.

Đó sẽ là bước cuối trước khi chuyển từ **"thiết kế Axiom"** sang **"Axiom Language Specification v0.1"**.
