Tiếp tục **Semantic Freeze Audit — Pass #2**. Đây là vòng quan trọng nhất của memory/ownership model, vì nếu `Copy / Move / Drop / view / closure / receiver / generic` không nhất quán thì toàn bộ Axiom sẽ lung lay.

# 63. Trục semantic duy nhất

Ta cần xác định rõ một value tại một thời điểm có thể ở trạng thái nào.

```text id="e1a8c4"
UNINIT
  ↓
OWNED
  ├── COPY ───────────────► OWNED + OWNED
  ├── MOVE ───────────────► MOVED
  ├── PARTIAL MOVE ───────► PARTIAL
  └── DROP ───────────────► DROPPED
```

Capability là một trục **khác**:

```text id="j7f31a"
OWNED
  │
  ├── view()     → READ capability
  └── mut_view() → WRITE capability
```

Do đó không nên đưa `READ/WRITE` vào ownership state.

### Freeze

**Ownership state** và **capability state** là hai state machines độc lập nhưng có quan hệ ràng buộc.

---

# 64. Copy

`Copy` phải có một định nghĩa cực kỳ hẹp:

> Một type `T: Copy` có thể tạo một value độc lập từ value hiện tại mà không tạo thêm cleanup obligation cần được xử lý bởi compiler.

Ví dụ:

```axiom
let a: i32 = 10
let b = a
```

Sau đó:

```text
a = OWNED
b = OWNED
```

Cả hai đều hợp lệ.

---

# 65. Copy không đồng nghĩa immutable

Một type có thể Copy nhưng mutable:

```axiom
struct Point {
    x: i32
    y: i32
}
```

```axiom
var a = Point { x: 1, y: 2 }
var b = a

b.x = 99
```

Không ảnh hưởng `a`.

Đây là lý do:

> Axiom không có implicit shared mutable aliasing.

---

# 66. Điều kiện để một type là Copy

Ta nên freeze rule:

Một type chỉ là `Copy` nếu:

1. tất cả thành phần semantic đều Copy;
2. không có custom Drop;
3. không chứa ownership obligation không-Copy;
4. không chứa capability mà việc duplicate capability vi phạm safety;
5. không phụ thuộc runtime identity độc quyền.

Do đó:

```text id="9xg4v1"
i32              → Copy
Point            → Copy
Array<i32, 10>   → Copy
Text             → !Copy
Vec<T>           → !Copy
Box<T>           → !Copy
File             → !Copy
mut_view<T>      → !Copy
view<T>          → Copy-like
```

---

# 67. `view<T>` có phải `Copy` trait không?

Tôi khuyên **không**.

Đây là điểm nên khóa.

`view<T>` là compiler-known capability type. Việc duplicate READ capability là **language intrinsic rule**, không nên bắt nó phụ thuộc vào user-visible `Copy`.

Nếu biến:

```axiom
let a = view(data)
let b = a
```

thì compiler biết:

```text id="0w2s3q"
READ capability
READ capability
```

hợp lệ.

Nhưng không có nghĩa:

```text
view<T>: Copy
```

theo trait system thông thường.

### Lý do

Nếu sau này user tự định nghĩa trait:

```axiom
trait Copy { ... }
```

hoặc generic algorithm dựa vào `Copy`, capability semantics không được phép bị thay đổi.

### Freeze

**ACAP-27 — Capability Duplication Is Intrinsic To Capability Semantics, Not A User Trait**

# 68. `mut_view<T>` không Copy

```axiom
let a = mut_view(data)
let b = a
```

là MOVE:

```text id="8b6w2p"
a → MOVED
b → WRITE capability
```

Điều này cực kỳ tiện.

Programmer không cần:

```text
&mut
borrow_mut
lifetime
```

nhưng vẫn giữ được exclusive mutation.

# 69. Có được tạo hai `mut_view` disjoint không?

Có.

Ví dụ:

```axiom
let x = mut_view(data.left)
let y = mut_view(data.right)
```

Nếu compiler chứng minh:

```text id="x6c4qz"
Region(left) DISJOINT Region(right)
```

thì hợp lệ.

Điều này rất quan trọng cho hiệu năng.

Ví dụ:

```axiom
fn update(
    a: mut_view<Vec3>,
    b: mut_view<Vec3>
)
```

không nhất thiết phải cấm hai argument.

Compiler chỉ cần xác định:

```text
Region(a) ∩ Region(b)
```

# 70. UNKNOWN thì sao?

Đây là điểm cần freeze.

Nếu compiler không chứng minh được:

```text id="3f9qv0"
DISJOINT
```

thì không được giả định disjoint.

Ví dụ:

```axiom
fn f(a: mut_view<i32>, b: mut_view<i32>)
```

Caller:

```axiom
f(mut_view(x), mut_view(y))
```

Nếu `x` và `y` là hai local khác nhau:

```text
DISJOINT
```

→ PASS.

Nếu:

```axiom
f(mut_view(array[i]), mut_view(array[j]))
```

mà `i` và `j` runtime:

```text
UNKNOWN
```

→ compiler không được tự đoán.

Trong safe code, phải reject hoặc API phải dùng abstraction bảo đảm disjointness.

### Đây là nguyên tắc rất quan trọng:

**ACAP-28 — Unknown Aliasing Cannot Be Assumed Disjoint In Safe Code**

---

# 71. Nhưng điều này có làm Axiom phiền như borrow checker không?

Không, nếu thiết kế API tốt.

Compiler có thể prove nhiều trường hợp:

```axiom
mut_view(a[0..4])
mut_view(a[4..8])
```

→ static disjoint.

Struct fields:

```axiom
mut_view(x.a)
mut_view(x.b)
```

→ disjoint.

Separate locals:

```axiom
mut_view(a)
mut_view(b)
```

→ disjoint.

Chỉ những trường hợp thực sự không chứng minh được mới bị chặn.

# 72. `mut_view` return

Ví dụ:

```axiom
fn first(v: mut_view<Array<i32>>) -> mut_view<i32> {
    ...
}
```

Hợp lệ nếu returned capability có provenance:

```text id="l9c5xm"
returned region ⊆ input region
```

và lifetime không vượt quá input capability/owner.

Nhưng:

```axiom
fn bad() -> mut_view<i32> {
    var x = 10
    mut_view(x)
}
```

→ reject.

Không cần programmer viết:

```text
'a
```

Compiler tự biết:

```text id="6bq7k3"
x dies before returned capability
```

# 73. Capability lifetime không được trở thành API syntax

Đây là điểm cần bảo vệ rất mạnh.

Không cho:

```text

```

hoặc:

```text

```

trong Core v0.1.

Compiler có lifetime graph nội bộ:

```text id="c5by2n"
Capability C1
   │
   ├── depends on owner O1
   └── valid until last use
```

Nhưng source language không expose nó.

### Freeze

**ALIFE-20 — Lifetime Analysis Is Compiler Semantics, Not Source Syntax**

# 78. Closure capture

# 79. Capture inference

Nếu closure escape:

```text id="7c5x9m"
compiler có thể capture value nếu Copy
hoặc
```

# 80. `move` closure


được freeze như:

Sau:

```text id="3o2i5y"

f owns captured x
```

# 85. Async closure


thực chất:

```text id="l2b6c7"
   ↓
```

# 86. Generic + closure

# 91. Một vấn đề mới: API generic có thể cần non-overlap contract

Nếu nhiều algorithm cần:

Tuy nhiên **không nên thêm `noalias` syntax vào v0.1**.

Thay vào đó:

Nếu không prove được:


→ reject safe call.

> explicit semantic boundary, implicit compiler machinery.

# 92. Copy + capability

Một vấn đề tinh vi:

```axiom

let y = x
```

Nếu `x` hết use:

```text id="3k4v8c"
x dead
y READ
```

Không có "ownership transfer" vì capability không owner.

Compiler có thể thậm chí canonicalize hai capability thành một internal capability nếu không observable.

# 93. Move + capability

Ví dụ:

```axiom
let x = mut_view(data)
let y = x
```

Đây là:

```text id="j7f9d2"
x → MOVED
y → WRITE
```

Không phải duplicate.

Điều này tạo một quy tắc cực sạch:

```text
view<T>     → duplicable READ capability

```

# 94. Drop + active capability

Nếu:

```axiom

```

→ reject.

Nếu:

```axiom

```

→ hợp lệ.

Điều này cho thấy `drop(data)` thực chất là một operation yêu cầu:


**ADROP-21 — Explicit Drop Requires No Live Dependent Capability**

Compiler-generated Drop tất nhiên cũng chịu rule này vì compiler kiểm soát lifetime.

# 95. Explicit `drop(x)` có nên tồn tại?

Tôi đề nghị **có**.

Không phải:

```text
free(x)
```

mà:


nghĩa:

Cho phép resource release sớm.

# 98. Custom Drop và partial move

vì:

# 101. Có nên cấm `Copy` với compiler-derived Drop?

Có.

Tôi đề nghị rule tổng quát:

> **Any type with a semantic Drop obligation is not Copy.**

Dù Drop là derived hay custom.

Như vậy:

```text
struct Foo { String }
```

→ !Copy.

Không phải vì `String` "không copy được" một cách tùy ý, mà vì copy sẽ tạo ownership obligations.

# 102. Clone là gì?

Đây là chỗ nên tách:

```text
Copy
Clone
Move
```

- `Copy`: implicit semantic duplication.
- `Clone`: explicit potentially-expensive duplication.
- `Move`: ownership transfer.

Ví dụ:

```axiom
let b = a.clone()
```

có thể allocate/copy/deep-copy.

Không có implicit clone.

### Freeze

**AOWN-22 — Clone Is Explicit And May Have Arbitrary Resource Cost**

```text
          ┌────────┼─────────┐
```

# 105. Một kết luận lớn hơn

```text

WRITE
MOVE
DROP
```

và hai loại capability:

Còn:

Đây là điểm tôi đánh giá rất quan trọng đối với mục tiêu ban đầu của Axiom:

> **Không cố làm language core nhỏ bằng cách bỏ semantic power; thay vào đó làm semantic primitives ít nhưng mạnh.**

Compiler có thể xây hàng nghìn rule nội bộ trên bốn operation này, nhưng programmer chỉ cần hiểu:

**đọc — sửa — chuyển quyền — giải phóng.**

Vòng tiếp theo nên chuyển sang phần còn lại có nguy cơ phá semantic freeze:

**`Trait / Generic / Type Inference / Method Resolution / `impl Trait` / `dyn Trait` / Coherence / Operator Overloading / Associated Type / specialization`.**

Đặc biệt tôi muốn kiểm tra một câu hỏi rất quan trọng:

> **Axiom có thể giữ được generic + trait rất mạnh nhưng vẫn khiến compiler resolution hoàn toàn deterministic, không biến thành một phiên bản C++ template hell hay không?**

Đây sẽ là vòng cuối của **type-system freeze** trước khi chuyển sang **control-flow + concurrency + ABI freeze**.
