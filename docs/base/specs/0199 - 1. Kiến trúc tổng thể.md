Tiếp tục với **ANDROID-PACK-001 — APK Packaging**.

Điểm cần chốt trước: **APK packaging phải là một subsystem độc lập với compiler, ELF linker và Android platform ABI**. APK là container/package artifact; `.so` bên trong đã được tạo xong trước đó.

Android yêu cầu APK phải được ký trước khi cài đặt; các scheme v2/v3 đặt signing block trước ZIP Central Directory, còn v4 tạo thêm file `.idsig` riêng và phục vụ incremental installation. citeturn0search6turn0search9turn0search0

# 1. Kiến trúc tổng thể

```text
Axiom Source
    ↓
Axiom Compiler
    ↓
libfoo.so
    ↓
Android Packager
    ├── Manifest
    ├── Native libraries
    ├── Resources
    ├── Assets
    ├── DEX / Java artifacts (nếu có)
    └── APK
          ↓
      APK Signer
          ↓
      Signed APK
```

Tuyệt đối không:

```text
ELF Linker → APK
```

mà:

```text
ELF Linker → ELF artifact
APK Packager → APK
APK Signer → signed APK
```

# 3. APK semantic model

Không coi APK đơn giản là:

```text
ZIP(files)
```

vì APK có thêm signing semantics.

Tạo:

```text
ApkPackage {
    manifest
    entries[]
    native_libraries[]
    resources
    signing_policy
}
```

Sau đó:

```text
ApkPackage
    ↓
ApkLayout
    ↓
ZipImage
    ↓
SigningBlock
    ↓
FinalApk
```

# 4. APK entry

Generic:

```text
ApkEntry {
    path
    source
    compression
    alignment
    mode
}
```

Ví dụ:


```text
lib/arm64-v8a/
```

```text

```

# 6. Multi-ABI APK

Một APK có thể chứa:

```text
lib/
├── arm64-v8a/
│   └── libfoo.so
├── armeabi-v7a/
│   └── libfoo.so
└── x86_64/
    └── libfoo.so
```

Axiom packager nên hỗ trợ:

```text
ArtifactSet {
    abi → native_library
}
```

Compiler không cần compile lại toàn project semantic.

Ví dụ:

```text
build
 ├── aarch64-android
 ├── x86_64-android
 └── armeabi-v7a
```

→ một APK.

# 15. Alignment

APK có những yêu cầu alignment nhất định; Android 11 trở lên còn có yêu cầu riêng đối với `resources.arsc`, trong đó tài liệu Android nêu trường hợp target API 30+ không được để `resources.arsc` bị nén và phải được align đúng. citeturn0search7

Do đó:

```text
APKAlignmentEngine
```

phải tồn tại độc lập.

```text
Entry
 ↓
AlignmentPolicy
 ↓
ZIP layout
```

Không patch byte offsets sau khi ZIP đã hoàn thành.

V2 ký toàn bộ APK blob theo signing scheme, với signing block nằm trước Central Directory. citeturn0search12

```text

     ↓
```

# 28. Target consistency

Nếu:

```text
APK target = arm64-v8a
```

nhưng chứa:

```text
lib/arm64-v8a/libfoo.so
```

với:

```text
ELF machine = x86_64
```


# 29. API compatibility

Manifest:

```text
minSdk = 26
targetSdk = 35
```

native library:

```text

```

Nếu library thực sự dùng platform API 30 mà app minSdk 26, verifier/compiler cần biết policy.

Không phải lúc nào cũng reject — có thể cho phép nếu code path được guarded.

Nhưng MVP:


# 31. Cache boundary

Không cache:

```text

```

```text
APKContentHash
+
SigningIdentity
+
SigningPolicy
```

```text

```

Đây là một optimization quan trọng.

# 33. Reproducibility

Có hai khái niệm:

```text
Content reproducibility
Signing reproducibility
```

Unsigned APK:

```text
same inputs → same bytes
```

Signed APK:

```text
same inputs
+
same signing identity
+
same algorithm/config
→ same bytes
```

Nếu external signer có nondeterministic behavior thì reproducibility phải được ghi rõ.

## 43. Bước tiếp theo: ANDROID-JNI-001

Native `.so` và APK packaging đã có abstraction. Bây giờ mới xử lý **JNI**:

```text
Android Java/Kotlin
        ↓
       JNI
        ↓
Axiom C-compatible ABI
        ↓
Axiom function
```

Milestone đó sẽ giải quyết kỹ:

- `JNIEnv*`;
- `jobject`, `jclass`, `jstring`, arrays;
- local/global/weak-global references;
- JNI method signatures;
- native registration;
- `JNI_OnLoad`;
- thread attachment;
- exception state;
- UTF-8/UTF-16 boundary;
- ownership/capability wrapper;
- tránh để JNI handle bị hiểu nhầm là raw pointer an toàn;
- và quan trọng nhất: **xây JNI hoàn toàn bằng library/platform layer, không thêm JNI primitive vào Axiom Core**.
