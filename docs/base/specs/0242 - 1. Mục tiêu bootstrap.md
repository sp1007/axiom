Tiếp tục **BOOTSTRAP-001 — Axiom Bootstrap Strategy**.

Đây là thời điểm nên chuyển từ “thiết kế compiler” sang **thiết kế cách compiler đầu tiên được sinh ra**.

Mục tiêu không phải viết một compiler tạm bợ rồi vứt đi, mà là tạo một **bootstrap compiler đủ nhỏ để tự chứng minh kiến trúc Axiom** và sau đó chính Axiom thay thế nó từng phần.

---

# 1. Mục tiêu bootstrap

Ta muốn đạt trạng thái:

```text
Existing host compiler/toolchain
        │
        ▼
Bootstrap Axiom Compiler
        │
        ▼
Axiom Compiler written in Axiom
        │
        ▼
Axiom Compiler tự compile chính nó
```

Cuối cùng:

```text
axiom compiler
     │
     ├── compiler written in Axiom
     ├── linker written in Axiom
     ├── object writer written in Axiom
     └── machine encoder written in Axiom
```

Không còn phụ thuộc LLVM/GCC/Clang để **build compiler chính thức**.

# 4. Stage 0

Stage 0 là compiler viết bằng ngôn ngữ host.

Có thể tạm dùng:

```text
C
C++
Rust
```

hoặc LLVM làm backend.

Nhưng Stage 0 **không phải Axiom compiler cuối cùng**.

Nó chỉ có nhiệm vụ:

> compile được Axiom đủ nhiều để xây Stage 1.

---

# 5. Tôi đề xuất Stage 0 bằng C

Lý do:

- dễ bootstrap
- ABI rõ
- dependency thấp
- dễ chạy Linux/Windows
- dễ build compiler nhỏ
- dễ viết object writer
- dễ kiểm soát memory
- phù hợp với mục tiêu cuối cùng của Axiom

Nhưng:

> **C chỉ là bootstrap substrate, không phải kiến trúc phụ thuộc của Axiom.**

---

# 6. Không dùng LLVM làm backend chính của Stage 0

Có thể dùng LLVM để differential-test.

Nhưng nếu:

```text
Axiom → LLVM IR → LLVM → executable
```

thì rất dễ vô tình thiết kế Axiom theo LLVM.

Tốt hơn:

```text
Axiom → Axiom MIR → Axiom backend
```

ngay từ đầu.

Stage 0 chỉ cần backend nhỏ.

# 11. Bootstrap syntax

Chưa cần đóng băng toàn bộ syntax Axiom.

Nhưng cần một **Bootstrap Syntax Contract**.

Ví dụ:

```text
fn add(a: i32, b: i32) -> i32 {
    return a + b
}
```

Struct:

```text
struct Point {
    x: f64,
    y: f64,
}
```

Method:

```text
fn length(self: Point) -> f64 {
    return sqrt(self.x * self.x + self.y * self.y)
}
```

---

# 12. Value semantics

```text
let a = Point{1.0, 2.0}
let b = a
```

Nếu `Point` là Copy:

```text
a vẫn hợp lệ
```

Nếu non-Copy:

```text
a bị move
```

Bootstrap compiler phải kiểm tra được điều này.

---

# 13. `view`

Ví dụ:

```text
fn sum(v: view<i32>) -> i32 {
    ...
}
```

Gọi:

```text
let x = [1, 2, 3]
sum(view(x))
```

Có thể cho phép ephemeral:

```text
sum(x)
```

khi parameter rõ ràng yêu cầu `view`.

# 32. Test thứ tám

Disjoint fields:

```text

    a: i32,
    b: i32,
}
```

Compiler phải cho phép các capability độc lập nếu vùng thực sự disjoint.

Đây là một test rất quan trọng cho triết lý Axiom:

> không phải cứ có nhiều mutable capability là compiler cấm; nó phải hiểu region.
