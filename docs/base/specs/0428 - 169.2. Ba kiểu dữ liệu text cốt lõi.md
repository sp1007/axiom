## BOOTSTRAP-169 — String, Unicode, Text, Encoding & Internationalization
**FROZEN / COMPLETED**

### 169.1. Nguyên tắc nền tảng

Axiom coi **text và bytes là hai miền dữ liệu khác nhau**:

```text
String / Str
    = UTF-8 text hợp lệ

Bytes
    = dữ liệu byte tùy ý

char
    = một Unicode Scalar Value

grapheme cluster
    = đơn vị người dùng nhìn thấy như một ký tự
```

Nguyên tắc:

> **UTF-8 là mặc định của Axiom, nhưng Unicode không được phép biến mọi thao tác string thành thao tác "ký tự".**

Điều này rất quan trọng cho hiệu năng.

Axiom không giả định:

- 1 ký tự = 1 byte
- 1 ký tự = 1 `char`
- độ dài Unicode = số byte
- indexing Unicode phải O(1)
- mọi text đều có thể chuyển thành C string
- mọi chuỗi đều cần normalization
- mọi so sánh chuỗi đều là so sánh Unicode theo ngôn ngữ tự nhiên.

---

# 169.2. Ba kiểu dữ liệu text cốt lõi

### `String`

Owned, mutable UTF-8 text.

```ax
let name: String = "Nguyễn Văn A";
```

Semantic properties:

```text
owned
mutable
UTF-8 valid
growable
!Copy
Drop
```

Compiler có thể biểu diễn vật lý bằng:

```text
pointer + length + capacity
```

nhưng đây **không phải ABI/representation bắt buộc**.

---

### `Str`

Non-owning UTF-8 view.

```ax
fn print_name(name: Str) {
    ...
}
```

`Str` tương đương về mặt semantic với:

```text
READ capability
+ UTF-8 validity
+ provenance
+ region
```

Không allocation.

Không ownership.

Có thể có representation kiểu:

```text
pointer + length
```

nhưng representation không phải định nghĩa semantic.

Ví dụ:

```ax
fn greet(name: Str) {
    println("Hello, {name}");
}

let s = String("Hùng");
greet(s);
```

Compiler có thể tạo `Str` ephemeral mà không tạo object trung gian.

---

### `Bytes`

Raw byte sequence.

```ax
let data: Bytes = ...;
```

Không có Unicode invariant.

Có thể chứa:

```text
00 FF 80 C3 A9 ...
```

mà hoàn toàn hợp lệ.

Do đó:

```text
Bytes ≠ Str
Bytes ≠ String
```

Đây là phân biệt rất quan trọng cho file, network, compression, crypto, image, executable, protocol...

---

# 169.3. `char`

`char` là:

> **Unicode Scalar Value**

Không phải byte.

Không phải grapheme cluster.

Không phải "một ký tự mà người dùng nhìn thấy".

Ví dụ một grapheme có thể gồm nhiều Unicode scalar values.

Do đó:

```ax
for c in text.chars() {
    ...
}
```

duyệt Unicode scalar values.

Nếu cần đơn vị hiển thị:

```ax
for g in text.graphemes() {
    ...
}
```

Đây là hai API khác nhau.

---

# 169.4. UTF-8 invariant

Mọi `String` và `Str` trong safe Core/stdlib phải chứa UTF-8 hợp lệ.

Invariant:

**ASTR-20**

> `String` luôn biểu diễn một chuỗi UTF-8 hợp lệ.

**ASTR-21**

> `Str` luôn là một view vào vùng dữ liệu UTF-8 hợp lệ.

**ASTR-22**

> `Bytes` không có yêu cầu Unicode validity.

Điều này cho phép compiler/library dựa vào invariant UTF-8 mà không cần validate lại ở mỗi thao tác.

---

# 169.5. Chuyển đổi `Bytes → Str`

Không được phép tự động.

```ax
let bytes: Bytes = ...;

let text = bytes.as_str();
```

Kết quả:

```ax
Result<Str, Utf8Error>
```

Nếu dữ liệu chắc chắn hợp lệ thông qua một contract:

```ax
unsafe {
    Str::from_utf8_unchecked(bytes)
}
```

nhưng unsafe chỉ thiết lập trusted precondition.

Verifier vẫn tiếp tục theo dõi `Str` như một capability hợp lệ.

---

# 169.6. `String → Bytes`

Trường hợp read-only có thể zero-copy.

Ví dụ semantic:

```ax
let text: String = ...;

let bytes: view<u8> = text.as_bytes();
```

Không cần copy.

Nhưng mutable byte access phải bị hạn chế vì:

```text
String invariant = valid UTF-8
```

Nếu cho phép:

```ax
mut_view<u8>
```

tùy ý vào backing storage thì programmer có thể phá invariant.

Vì vậy:

```text
String.as_bytes()
    → view<u8>
```

safe.

Trong khi:

```text
String.as_bytes_mut()
```

không mặc định cho phép arbitrary mutation.

Có thể cung cấp API kiểm soát mutation hoặc unsafe API.

---

# 169.7. Indexing

Axiom **không định nghĩa**:

```ax
text[i]
```

là "Unicode character".

Thay vào đó:

```text
bytes()
chars()
graphemes()
```

có semantic rõ ràng.

Ví dụ:

```ax
text.bytes()
```

→ UTF-8 bytes.

```ax
text.chars()
```

→ Unicode scalar values.

```ax
text.graphemes()
```

→ extended grapheme clusters.

Điều này tránh một lượng lớn confusion và không buộc `String` phải có cấu trúc dữ liệu đắt tiền để hỗ trợ character indexing O(1).

---

# 169.8. Slicing

Safe slicing phải tôn trọng UTF-8 boundary.

Ví dụ semantic:

```ax
text.slice(byte_range)
```

chỉ thành công nếu boundary hợp lệ.

Nếu boundary nằm giữa một UTF-8 sequence:

```text
Result<Str, Utf8BoundaryError>
```

Không có hành vi undefined trong safe code.

Unsafe/system API có thể tạo byte-level view nếu programmer chịu trách nhiệm.

---

# 169.9. Iteration

Axiom chuẩn hóa ba tầng:

```text
Bytes
 ↓
Unicode Scalar Values
 ↓
Grapheme Clusters
```

API:

```ax
text.bytes()
text.chars()
text.graphemes()
```

Compiler có thể inline/fuse iterator như các iterator khác.

Không tạo iterator object heap-allocated bắt buộc.

---

# 169.10. Mutation và relocation

`String` có thể grow:

```ax
s.push(...)
s.append(...)
```

Growth có thể relocation backing storage.

Do đó nếu có:

```ax
let v = s.as_str();
```

thì compiler phải theo dõi capability.

Mutation có thể bị chặn nếu nó có khả năng invalidating `v`.

Ví dụ semantic:

```ax
let v = s.as_str();

s.append("abc"); // có thể bị reject nếu relocation/invalidation xảy ra

use(v);
```

Programmer không cần viết lifetime.

Compiler tự biết:

```text
s
 ↓
v
 ↓
read capability
```

và kiểm tra relocation/mutation.

---

# 169.11. String không có stable address mặc định

Axiom không hứa:

```text
String address remains constant
```

Nếu cần stable storage:

```text
Box
Arena
stable buffer
explicit pinned/storage abstraction
```

phải được sử dụng.

Điều này cho phép compiler/library tối ưu relocation mà không phá semantic contract.

---

# 169.12. C string

Axiom **không coi NUL-terminated string là string primitive**.

FFI có kiểu riêng, ví dụ:

```text
CStr
CString
```

với semantic rõ:

```text
CStr
    non-owning
    NUL terminated
    encoding contract explicit

CString
    owning
    NUL terminated
    interior-NUL policy explicit
```

Không có implicit:

```text
String → char*
```

và không có giả định:

```text
String → NUL terminated
```

Điều này loại bỏ một class lớn lỗi FFI.

# 169.13. Encoding

UTF-8 là default, nhưng Axiom không giới hạn hệ thống vào UTF-8.

Các encoding khác nằm ở library:

```text
UTF-8
UTF-16
UTF-32
Latin-1
ASCII
Windows code pages
custom codecs
```

Ví dụ conceptual:

```ax
let decoder = Utf16Decoder.new();

let text = decoder.decode(bytes)?;
```

Encoding/decoding có thể là streaming:

```text
Bytes
 ↓
Decoder state
 ↓
Text chunks
```

Điều này quan trọng với file/network lớn vì không cần materialize toàn bộ dữ liệu.

---

# 169.14. Invalid encoding

Không silently thay thế dữ liệu mặc định.

Ví dụ:

```ax
decode(bytes)
    -> Result<String, DecodeError>
```

Các policy như:

```text
Strict
Replace
Ignore
```

phải được chọn explicit.

Không được biến lỗi encoding thành dữ liệu khác mà programmer không biết.

---

# 169.15. BOM

BOM handling thuộc decoder/encoding policy.

Không được để:

```text
String
```

tự động có semantic BOM.

Decoder có thể:

```text
accept BOM
reject BOM
consume BOM
preserve BOM
```

tùy encoding contract.

---

# 169.16. Unicode normalization

Axiom **không normalize implicit**.

Có các operation rõ ràng:

```text
NFC
NFD
NFKC
NFKD
```

Ví dụ:

```ax
let normalized = text.normalize(NFC)?;
```

hoặc API tương đương.

Lý do:

- có chi phí CPU
- có thể allocation
- thay đổi representation
- không phải mọi protocol đều muốn normalization.

Do đó:

```text
byte equality
≠
code-point equality
≠
normalized equality
≠
locale collation equality
```

---

# 169.17. Equality và hashing

Axiom phân biệt:

```text
String byte equality
Unicode scalar equality
normalized equality
locale-aware comparison
```

`String == String` mặc định phải có semantics đơn giản, ổn định và không tự ý gọi locale.

Hashing phải tương ứng với equality contract.

Nếu programmer muốn:

```text
NFC-equivalent strings
```

thì phải sử dụng explicit normalized comparison/hash abstraction.

Không được có tình trạng:

```text
a == b
```

hôm nay đúng nhưng thay đổi theo locale hệ thống.

# 169.18. Case conversion

Phân biệt:

```text
Unicode simple case mapping
locale-sensitive casing
case-insensitive comparison
```

Không có implicit:

```ax
text.to_lower()
```

mang semantic locale ngầm.

Locale-sensitive operation phải nhận locale/context rõ ràng hoặc đi qua external state abstraction.

# 169.19. Grapheme

Grapheme segmentation là library functionality.

Một grapheme cluster có thể chứa:

```text
base character
+ combining marks
+ modifiers
+ joined sequences
```

Do đó:

```text
grapheme count
```

không phải:

```text
byte count
```

và cũng không nhất thiết bằng:

```text
char count
```

Grapheme segmentation có thể tương đối tốn CPU và Unicode-data dependent; không đưa vào Core primitive.

# 169.22. OS-native strings

Axiom **không ép OS phải dùng UTF-8**.

Platform layer cung cấp abstraction như:

```text
OsStr
OsString
Path
PathBuf
```

Ví dụ:

```text
Unix
    → native byte-oriented OS strings

Windows
    → native UTF-16-oriented APIs
```

Axiom application code không cần biết representation cụ thể nếu chỉ dùng API platform abstraction.

Không được có conversion ngầm:

```text
Path → String
```

nếu conversion có thể thất bại.

# 169.23. Path

`Path` không phải `String`.

Đây là quyết định quan trọng.

```text
Path
≠
String
≠
Str
≠
Bytes
```

Filesystem path là OS-level identifier.

Một path có thể không biểu diễn được chính xác bằng Unicode `String`.

Vì vậy:

```ax
fs.open(path)
```

nhận `Path`/`OsStr`, không yêu cầu programmer chuyển qua UTF-8 text.

# 169.26. Formatting

String formatting phải allocation-aware.

Không thiết kế:

```text

```

một cách bắt buộc.

Có thể có:

```text
Formatter
Writer
Display
Debug
```

và:

```ax
write_to(writer, value)
```

Ví dụ semantic:

```text

 ↓
Formatter
 ↓
Writer
```

thay vì:

```text

 ↓

 ↓
copy
 ↓
Writer
```

# 169.27. Interpolation

String interpolation:

```ax
"Hello {name}, value={x}"
```

là syntax được compiler hiểu.

Nhưng compiler có thể lower thành:

```text
Formatter + Writer
```

thay vì bắt buộc tạo nhiều temporary String.

Nếu context yêu cầu `String`, allocation vẫn xảy ra.

Nếu context là writer/stream, compiler/library có thể ghi trực tiếp.

# 169.28. `ToString`

Không nên có semantic:



```text
Formatter / Writer
```

# 169.29. Compile-time strings

String literals:

```ax
"hello"
```

là UTF-8.

Byte literals:

```ax
b"hello"
```

là bytes.

Comptime có thể thao tác với string:

```ax

```

hoặc compile-time generation.

Compiler có thể intern/deduplicate literals.

Không được giả định mọi string literal đều cần runtime allocation.

# 169.30. Serialization khác memory representation


# 169.31. Zero-copy là nguyên tắc tối ưu

Các API nên ưu tiên:

```text
Bytes → read-only view
String → Str
String → byte view
decoder → borrowed slices
```

Nhưng:

> Zero-copy không được phá ownership, capability, encoding validity hoặc storage lifetime.

Nếu decode cần copy thì copy là hợp lệ.

Không biến "zero-copy" thành semantic requirement.

# 169.34. Representation summary

```text

  ownership + UTF-8 validity

  READ capability + UTF-8 validity

  ownership/view + arbitrary bytes

char
  Unicode Scalar Value

  Unicode text segmentation unit
```

```text

```

nhưng compiler được tự do thay đổi representation nếu ABI/representation contract không bị expose.

# 169.38. Các invariant đóng băng

### String

- **ASTR-20** — `String` luôn chứa UTF-8 hợp lệ.
- **ASTR-21** — `Str` luôn là UTF-8-valid non-owning capability.
- **ASTR-22** — `Bytes` không có Unicode invariant.
- **ASTR-23** — `String` không mặc định NUL-terminated.
- **ASTR-24** — `String` không mặc định stable-address.
- **ASTR-25** — live `Str` có thể ngăn mutation/relocation làm mất validity.
- **ASTR-26** — `String` là `!Copy`; ownership semantics áp dụng như các owning types khác.
- **ASTR-27** — safe slicing không tạo UTF-8-invalid `Str`.
- **ASTR-28** — `String → read-only bytes` có thể zero-copy.
- **ASTR-29** — arbitrary mutable byte access không được phá UTF-8 invariant.
- **ASTR-30** — byte equality không tự động là Unicode-normalized equality.

### Unicode

- **AUNICODE-20** — `char` là Unicode Scalar Value.
- **AUNICODE-21** — `char` không phải grapheme.
- **AUNICODE-22** — grapheme iteration là library functionality.
- **AUNICODE-23** — Unicode normalization không implicit.
- **AUNICODE-24** — locale không implicit global semantic state.
- **AUNICODE-25** — Unicode version là build/compiler metadata khi ảnh hưởng semantic behavior.
- **AUNICODE-26** — Unicode security diagnostics không tự ý thay đổi language semantics.
- **AUNICODE-27** — case mapping, case-insensitive comparison và locale-aware casing là các operations khác nhau.

### Encoding

- **AENC-20** — UTF-8 là default Axiom text encoding.
- **AENC-21** — encoding khác thuộc library/platform.
- **AENC-22** — `Bytes → Str` cần validation hoặc trusted contract.
- **AENC-23** — invalid encoding không silently biến thành text khác trong strict APIs.
- **AENC-24** — BOM policy thuộc decoder/encoding contract.
- **AENC-25** — streaming encoder/decoder không bắt buộc materialize toàn bộ input.
- **AENC-26** — encoding/wire format độc lập memory representation.
- **AENC-27** — zero-copy decoding được phép nhưng không bắt buộc.

### OS text

- **AOSSTR-20** — OS-native text không mặc định là UTF-8.
- **AOSSTR-21** — `Path` không đồng nhất với `String`.
- **AOSSTR-22** — C strings là explicit FFI types.
- **AOSSTR-23** — implicit `String → C string` không tồn tại.

# 169.39. Kết luận thiết kế

Đây là mô hình phù hợp với mục tiêu Axiom:

> **UTF-8 mặc định nhưng byte-level vẫn là first-class. Unicode mạnh nhưng không áp đặt chi phí Unicode lên mọi thao tác.**

Đặc biệt, Axiom tránh được ba vấn đề thường gặp:

```text
Rust-style lifetime syntax
        ↓
không cần trong source

C-style raw char*
        ↓
không phải text primitive

High-level String abstraction
        ↓
không bắt buộc allocation / GC / runtime
```

Và compiler vẫn có đủ thông tin để tối ưu:

```text
UTF-8 validity
+ capability
+ alias
+ escape
+ effect
+ lifetime
+ storage
        ↓
zero-copy / inline / stack / register / allocation elimination
```
