Tiếp tục **OBJECT-001 — Machine Encoder & Object Writer**.

Đây là bước rất quan trọng vì từ đây Axiom bắt đầu **tự tạo binary**, thay vì phụ thuộc assembler bên ngoài.

# 1. Kiến trúc tổng thể

Tách rõ 3 tầng:

```text
Machine IR
    │
    ▼
Instruction Encoder
    │
    ▼
Machine Bytes
    │
    ▼
Object Writer
    │
    ▼
ELF / PE / Mach-O / WASM
```

Không nên để encoder biết ELF hay PE.

Ngược lại:

> **Encoder biết CPU instruction encoding. Object Writer biết object-file format.**

---

# 2. Encoder contract

Input:

```text
MachineInstruction
```

Output:

```text
EncodedInstruction {
    bytes
    relocations
    fixups
}
```

Ví dụ conceptual:

```text
ADD RAX, RBX
```

→ một dãy byte x86-64.

Nhưng nếu:

```text
LEA RAX, [symbol]
```

thì encoder chưa biết địa chỉ cuối cùng.

Nó tạo:

```text
bytes
+
Relocation {
    offset
    symbol
    type
    addend
}
```

---

# 3. Không dùng assembler text

Không:

```text
Machine IR
→ "mov rax, rbx"
→ assembler
→ object
```

Final compiler:

```text
Machine IR
→ encoder
→ bytes
```

Đây là một architectural requirement quan trọng của Axiom.

---

# 4. Instruction encoding database

Mỗi target backend cần dữ liệu kiểu:

```text
InstructionEncoding {
    opcode
    operand_pattern
    prefix_rules
    immediate_encoding
    register_encoding
    memory_encoding
    feature_requirements
    size
    relocation_rules
}
```

Ví dụ x86:

```text
ADD r64, r/m64
```

có:

```text
REX
opcode
ModRM
SIB?
disp?
```

---

# 5. x86-64 encoder

x86 phức tạp nhất trong nhóm backend ban đầu.

Instruction có thể gồm:

```text
Legacy Prefix
REX
VEX / EVEX
Opcode
ModRM
SIB
Displacement
Immediate
```

Không phải instruction nào cũng có tất cả.

---

# 6. ModRM

Machine operand:

```text
ADD RAX, RBX
```

có thể cần:

```text
ModRM {
    mod
    reg
    rm
}
```

Register IDs phải được chuyển thành encoding number.

Do đó:

```text
PhysicalRegister
```

không đồng nhất với:

```text
encoding number
```

Đúng với quyết định MACHINE-IR-002.

---

# 7. SIB

Memory operand:

```text
[RAX + RBX*4 + 16]
```

cần:

```text
SIB {
    scale
    index
    base
}
```

Machine IR đã có:

```text
base
index
scale
displacement
```

nên encoder chỉ cần chuyển representation sang x86 encoding.

---

# 8. AArch64

AArch64 dễ hơn về cấu trúc encoding vì instruction thường:

```text
32-bit fixed width
```

Encoder:

```text
instruction word
→ bit fields
→ little-endian bytes
```

Ví dụ conceptual:

```text
[31........0]
 opcode | Rn | Rd | ...
```

Không có ModRM/SIB.

---

# 9. RISC-V

RISC-V có:

```text
16-bit compressed
32-bit base
48/64/... optional extensions
```

Axiom nên model:

```text
InstructionEncoding {
    width
    fields[]
}
```

không giả định mọi instruction là 32-bit.

---

# 10. WASM

WASM khác hoàn toàn CPU machine code.

Không nên ép WASM vào CPU encoder abstraction quá sâu.

Pipeline:

```text
Axiom Machine/LIR
        ↓
WASM lowering
        ↓
WASM instruction encoder
        ↓
WASM binary
```

WASM có:

- opcode
- immediates
- block types
- local indices
- function indices
- memory indices
- table indices

nên cần backend riêng.

---

# 11. Fixup

Instruction:

```text
CALL foo
```

chưa biết offset cuối cùng.

Encoder tạo:

```text
Fixup {
    section
    offset
    kind
    target
    addend
}
```

Sau khi layout sections/symbols:

```text
fixup
→ relocation
→ patched bytes
```

---

# 12. Local branch

Ví dụ:

```text
JMP L1
```

Nếu L1 cùng function:

```text
target_offset - instruction_end
```

có thể resolve ngay.

Không cần object relocation.

# 13. External symbol

```text

```

nếu `printf` external:

```text

    symbol = printf

}
```

# 15. Name mangling

Axiom ABI phải có deterministic mangling.

Ví dụ conceptual:

```text

```

Không nên dùng tên C++ ABI.

Generic:

```text
foo<i32>
foo<i64>
```

phải tạo symbol khác nhau.

# 19. `.bss`

Nếu:

```text

```

```text

```

# 22. Alignment

```text

```

Object writer phải đảm bảo.

Không nên dùng padding tùy tiện.

# 23. Relocation abstraction

Đây là phần cần thiết kế rất kỹ.

Không dùng:

```text
ELFRelocation
```

ở Machine IR.

Dùng:

```text
RelocKind {
    Abs
    PcRel
    Got
    Plt
    Tls
    SectionRelative
    TargetSpecific(...)
}
```

Object backend map:

```text
Axiom RelocKind
→ ELF relocation
→ COFF relocation
→ Mach-O relocation
```

# 24. PC-relative

Ví dụ x86:

```text

```

thường dùng displacement tương đối:

```text

```


# 26. GOT/PLT

Shared library/PIC cần:

```text
GOT
PLT
```

Nó chỉ tạo relocation semantic:

```text
SymbolReference {
    model = Dynamic
}
```

ELF backend quyết định GOT/PLT representation.

# 29. TLS relocation


# 30. Weak symbols

Object abstraction:

```text
Binding {
    Local
    Global

```

---

# 31. COMDAT

Generic functions:

```text
foo<i32>
```

có thể được generate ở nhiều compilation units.

Không muốn duplicate machine code.

Axiom object model cần group/linkonce semantics:

```text
ComdatGroup {
    key
    selection
}
```

Windows COFF và ELF có cơ chế khác nhau, nhưng semantic abstraction giống nhau.

---

# 32. Incremental compilation

Axiom `.axm` intermediate artifact có thể cache:

```text
source
→ semantic IR
→ codegen artifact
```

Object file cần deterministic enough để cache.

Không embed timestamp ngẫu nhiên.


# 44. Machine Encoder invariants

Đóng băng:

### AENC-20
**Encoder Produces Exact Target Machine Bytes**

### AENC-21
**Encoder Accepts Only Legal Machine IR**

### AENC-22
**Instruction Encoding Is Target-Specific**

### AENC-23
**Physical Register IDs Map Deterministically To Encodings**

### AENC-24
**Register Aliases Are Encoded According To Target Rules**

### AENC-25
**Memory Operands Encode According To Target Addressing Rules**

### AENC-26
**Immediate Width Is Explicit**

### AENC-27
**Unsupported Immediate Forms Are Rejected Before Encoding**

### AENC-28
**Instruction Feature Requirements Are Validated**

### AENC-29
**Symbol References Produce Explicit Fixups**

### AENC-30
**Local Resolvable Branches May Be Fully Resolved By Encoder**

### AENC-31
**External Symbol References Become Relocations**

### AENC-32
**Encoder Does Not Depend On External Assemblers**

### AENC-33
**Encoder Does Not Depend On Object-File Format**

---

# 45. Object invariants

### AOBJ-20
**Object Writer Is Independent Of CPU Instruction Semantics**

### AOBJ-21
**Object Writer Receives Target-Independent Relocation Semantics**

### AOBJ-22
**Section Layout Is Deterministic**

### AOBJ-23
**Symbol Definitions Are Deterministic**

### AOBJ-24
**Relocations Are Explicit**

### AOBJ-25
**Alignment Is Explicit**

### AOBJ-26
**Zero-Fill Storage Does Not Require Physical File Bytes**

### AOBJ-27
**TLS Is Distinct From Ordinary Global Storage**

### AOBJ-28
**COMDAT/Linkonce Semantics Are Explicit**

### AOBJ-29
**Debug Metadata Is Non-Semantic**

### AOBJ-30
**Unwind Metadata Describes Actual Machine Control Flow**

### AOBJ-31
**Object Format Translation Does Not Change Program Semantics**

### AOBJ-32
**Object Generation Is Deterministic**

### AOBJ-33
**Object Writer Does Not Resolve External Symbols**

### AOBJ-34
**Linker Owns Final Address Assignment**

## Bước kế tiếp: `LINKER-001`

Sau Object Writer, hợp lý nhất là thiết kế **Axiom Linker**.

Ta sẽ khóa:

```text
Object files
   ↓
Symbol resolution
   ↓
Archive/static library
   ↓
COMDAT/weak
   ↓
Section merging
   ↓
Relocation
   ↓
Layout
   ↓
Entry point
   ↓
TLS
   ↓
Dynamic linking
   ↓
ELF executable
PE executable
Mach-O executable
```

Đặc biệt cần giải quyết một vấn đề rất quan trọng với mục tiêu của Axiom:

> **Làm thế nào để một chương trình Axiom đơn giản có thể tạo một ELF/EXE hoàn chỉnh mà không cần libc, CRT, GNU ld, lld hay linker hệ thống — nhưng vẫn hỗ trợ libc/dynamic libraries/OS APIs khi programmer muốn.**
