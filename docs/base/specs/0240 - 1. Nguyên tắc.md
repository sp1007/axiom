Tiếp tục **TOOLCHAIN-001 — Axiom Driver & Build System**.

Đây là tầng biến toàn bộ compiler backend chúng ta vừa thiết kế thành một compiler mà lập trình viên có thể dùng hàng ngày.

---

# 1. Nguyên tắc

Axiom build system phải đạt 4 mục tiêu:

1. **Build đúng**
2. **Build nhanh**
3. **Build có thể tái lập**
4. **Build không phụ thuộc toolchain bên ngoài trong kiến trúc cuối**

Đặc biệt:

> **Compiler quyết định semantic compilation; build system quyết định cái gì cần compile và theo thứ tự nào.**

Không trộn hai trách nhiệm.

# 5. `.axm`

Đề xuất:

```text
Axiom Module Artifact
```

chứa:

```text
Module identity
Target-independent semantic metadata
Public API fingerprint
Generic metadata
Comptime dependencies
Type metadata cần thiết
Trait metadata cần thiết
MIR/codegen cache nếu phù hợp
Debug mapping
Compiler version
ABI version
Dependency fingerprints
```

Không nên biến `.axm` thành một binary ABI cố định vĩnh viễn.

---

# 6. Public API fingerprint

Ví dụ:

```text
module math
```

thay đổi:

```text
fn internal_helper()
```

nhưng không thay đổi public interface.

Compiler không cần rebuild tất cả dependent modules.

Ngược lại:

```text
pub fn add(x: i32) -> i32
```

đổi thành:

```text
pub fn add(x: i64) -> i64
```

→ API fingerprint thay đổi.

# 8. Module identity

```text

```

# 10. Circular import

Axiom nên cho phép circular dependency ở mức module?

Tôi đề xuất:

**Không cho phép circular initialization dependency**, nhưng có thể cho phép một số dạng declaration cycle.

Ví dụ:

```text
A imports B
B imports A
```

không nên lập tức cấm nếu chỉ dùng type declarations.

Compiler cần phân biệt:

```text
Declaration dependency
Value dependency
Initialization dependency
```

---

# 11. Dependency graph hai tầng

```text
Type/API Graph
Runtime Graph
```

Ví dụ:

```text
A cần type B
```

không nhất thiết cần runtime code của B.

Điều này giảm rebuild và tăng khả năng dead-strip.

# 13. Parallel compilation

Nếu:

```text
A
B
C
```

độc lập:

```text
compile A ─┐
compile B ─┼─ parallel
compile C ─┘
```

Build scheduler nên dùng toàn bộ CPU.

# 14. Nhưng comptime có dependency

Ví dụ:

```text
A comptime-generates type B
```

thì:

```text
A → B
```

phải xuất hiện trong build graph.

Không được để dependency ẩn.

---

# 15. Comptime dependency tracking

Ví dụ:

```text
comptime {
    embed_file("assets/a.bin")
}
```

Artifact dependency:

```text
main.ax
 └── assets/a.bin
```

File đổi:

```text
assets/a.bin
```

→ invalidate compilation tương ứng.

---

# 16. Không hash toàn bộ filesystem

Comptime chỉ được truy cập filesystem thông qua capability.

Compiler biết:

```text
ReadFilesystem("assets/a.bin")
```

nên cache key chỉ phụ thuộc resource đó.

Không cần invalidate toàn project.

# 60. Một quyết định quan trọng tiếp theo

Đến đây chúng ta đã thiết kế gần như toàn bộ **native compilation pipeline**:

```text
Language
 ↓
HIR
 ↓
MIR
 ↓
LIR
 ↓
Machine IR
 ↓
Encoder
 ↓
Object
 ↓
Linker
 ↓
Executable
```

và:

```text
Driver
 ↓
Dependency Graph
 ↓
Incremental Build
 ↓
Cache
 ↓
Parallel Compilation
```

Bây giờ có một tầng **cực kỳ quan trọng trước khi bắt đầu viết compiler thật**:

## `TARGET-001 — Target Description & ABI Registry`

Nó sẽ định nghĩa chính xác cách Axiom biết:

```text
x86-64 Linux
x86-64 Windows
ARM64 Linux
ARM64 macOS
ARM64 iOS
ARM64 Android
RISC-V64
WASM
bare-metal
```

khác nhau ở đâu.

Đặc biệt ta cần thiết kế **một `TargetDescription` duy nhất** nối tất cả các tầng:

```text
Type/Layout
   ↓
ABI
   ↓
LIR
   ↓
Machine Legalization
   ↓
Register File
   ↓
Instruction Set
   ↓
Object Format
   ↓
Linker
   ↓
Executable Format
```

Nếu làm tốt tầng này, việc thêm một CPU/OS mới về sau sẽ chủ yếu là **thêm target data + backend**, thay vì sửa hàng loạt compiler logic. Đây nên là bước tiếp theo trước khi đi sâu vào bootstrap/self-hosting.
