# 107. Mô hình type system tổng quát

Axiom có thể chia type thành 6 nhóm:

```text
Primitive
Aggregate
Sum
Function
Trait
Dynamic
```

Cụ thể:

```text
i32
struct Vec2
enum Result<T,E>
fn(i32) -> i32
T: Trait
dyn Trait
```

Trong đó:

```text
Trait ≠ Type
```

Trait là **behavioral constraint**.

Ví dụ:

```axiom id="3gk8z2"
trait Add {
    fn add(self, other: view<Self>) -> Self
}
```

Không thể:

```axiom
let x: Add = ...
```

một cách implicit.

Muốn dynamic:

```axiom
let x: dyn Add = ...
```

Muốn generic:

```axiom
fn f<T: Add>(x: T)
```

Ba trường hợp này phải hoàn toàn khác nhau.

# 108. Generic là compile-time abstraction

```axiom id="0gq1rv"
fn max<T: Ord>(a: T, b: T) -> T {
    if a > b { a } else { b }
}
```

`T` không tồn tại như runtime metadata mặc định.

Compiler có thể generate:

```text id="x7v0dr"
max<i32>
max<f64>
max<MyType>
```

Đây là monomorphization.

Không cần:

```text id="2y0r1x"
type_id
virtual call
reflection
boxing
```

trừ khi programmer yêu cầu dynamic behavior.

Ví dụ **không được** cho phép:

```text id="8m7l0d"
    ...
```

trong language.

# 113. Trait coherence

```text id="7k1q4m"

OR
type is local
```

Không cho:

```text id="z0c6np"

+
foreign type
```


# 123. Generic associated types

# 124. `impl Trait`

Ví dụ:

```axiom id="6z2p7k"

    FileReader(...)
}
```

`impl Reader` nghĩa:

> một concrete type cụ thể do compiler biết, nhưng caller không cần biết identity source-level.

Không phải dynamic dispatch.

# 125. `impl Trait` có cùng concrete type qua các branch không?

Có một rule rất rõ:

```axiom id="8m3r5w"
fn f(x: bool) -> impl Reader {
    if x {
        FileReader(...)
    } else {
        MemoryReader(...)
    }
}
```

→ reject nếu hai branch có concrete types khác nhau.

Không tự động biến thành `dyn Reader`.

Programmer phải viết:

```axiom id="f6q8y1"
fn f(x: bool) -> dyn Reader
```

nếu muốn dynamic dispatch.

# 127. `dyn Trait`

Conceptually:

```text id="3z8m1q"
dyn Trait
 ├── data
 └── dispatch
```

Nếu:

```axiom id="y7p2k4"
Box<dyn Trait>
```

thì owned dynamic value.

Nếu:

```axiom id="m4v8c2"

```

thì borrowed dynamic capability.

Do đó dynamic dispatch không quyết định ownership.

# 128. `dyn Trait` object safety

Đây là nơi có thể phát sinh complexity.

Trait:

```axiom id="3j7x9m"
trait Foo {
    fn run<T>(self, x: T)
}
```

không thể tạo `dyn Foo` theo representation đơn giản, vì dynamic dispatch không biết T runtime.

Do đó v0.1 nên có rule:

> Chỉ trait thỏa object-safety rules mới được dùng với `dyn Trait`.

Compiler diagnostic:

```text id="p8w2r5"
AX_TRAIT_00xx:
trait cannot be used as dynamic trait object
```

Không cần runtime fallback.

# 131. Sized
