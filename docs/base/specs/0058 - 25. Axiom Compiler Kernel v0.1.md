Tiếp tục. Sau Genesis Trace, tôi nghĩ Axiom nên chuyển từ **“thiết kế compiler” sang “đặc tả compiler có thể bắt tay code ngay”**.

Điểm tiếp theo quan trọng nhất là **Compiler Kernel v0.1**.

# 25. Axiom Compiler Kernel v0.1

Mục tiêu của Kernel không phải tạo được mọi chương trình.

Nó phải chứng minh 4 thứ:

1. Source được hiểu đúng.
2. Semantic được biểu diễn chính xác trong MIR.
3. MIR có thể được kiểm chứng độc lập.
4. Backend có thể nhận MIR đã verified mà không phải tự hiểu semantic cấp cao.

```text
                       ┌─────▼─────┐
                       │    AST    │

                  ┌──────────▼──────────┐
                  │    Name Resolver    │
                  └──────────┬──────────┘

                           HIR
                             │
                  ┌──────────▼──────────┐

                  └──────────┬──────────┘
```

# 36. MIR Builder

Đây là module đầu tiên thực sự quan trọng về compiler architecture.


Tức MIR phải có:

# 46. Và tôi muốn thêm một invariant mới cho Axiom

Từ toàn bộ kiến trúc hiện tại, tôi đề xuất chính thức thêm:

### **ACK-01 — Semantic Oracle Independence**

> Semantic Oracle không được phụ thuộc vào target backend, machine instruction, ABI register allocation hoặc object format.

Và:

### **ACK-02 — Backend Differential Correctness**

> Với mọi chương trình được Semantic Oracle xác định là hợp lệ, backend native phải bảo toàn observable semantics.

Và:

### **ACK-03 — IR Phase Isolation**

> Một compiler phase không được sử dụng thông tin thuộc phase thấp hơn nếu thông tin đó không được khai báo qua một interface hợp lệ.

Ví dụ:

```text
TypeChecker → TargetCapabilities
```

có thể hợp lệ nếu cần.

Nhưng:

```text
TypeChecker → RAX
```

là architectural violation.

# 47. Một thay đổi nhỏ tôi khuyên chốt ngay

Trong các sơ đồ trước có lúc thứ tự:

```text

→ ABI MIR
→ LIR
```

và có lúc:

```text
Verified MIR
→ LIR
→ ABI
```

Ta nên **đóng băng rõ ràng**:

```text
Verified MIR
      ↓
Semantic Optimization
      ↓
ABI MIR
      ↓
Axiom LIR
      ↓
Target Legalization
      ↓
Machine IR
```

### Vì sao?

`ABI MIR` cần quyết định những thứ như:

```text

sret
argument classification
calling convention
tail-call eligibility
parameter expansion
```

trước khi LIR trở thành low-level representation.

Nhưng ABI MIR vẫn **không được biết RDI/RAX**.

Nó chỉ biết:

```text
IntArg(0)
IntArg(1)
IntReturn
SRet
StackArg(...)
```

Sau đó:

```text
ABI MIR
    ↓
Target ABI
    ↓
Machine IR
```

mới biết:

```text
RDI
RSI
RAX
stack offset
```

Điều này giúp Windows x64, SysV, ARM64, RISC-V... dùng chung phần lớn compiler.

# 49. Và đây nên là mốc Axiom Genesis thật sự

Không phải:

> “Compiler parse được Axiom.”

Mà là:

```text
┌──────────────────────────────────────────────┐
│              AXIOM GENESIS                  │
│                                              │
│ Source                                       │
│   ↓                                          │
│ Own AST/HIR/MIR                              │
│   ↓                                          │
│ Own Semantic Verifier                        │
│   ↓                                          │
│ Own Semantic Oracle                          │
│   ↓                                          │
│ Own LIR                                      │
│   ↓                                          │
│ Own x86-64 Machine IR                        │
│   ↓                                          │
│ Own Register Allocator                       │
│   ↓                                          │
│ Own x86-64 Encoder                           │
│   ↓                                          │
│ Own ELF Object Writer                        │
│   ↓                                          │
│ system linker                                │
│   ↓                                          │
│ Native executable                            │
│   ↓                                          │
│ 42                                           │
└──────────────────────────────────────────────┘
```

**Sau mốc này, Axiom đã thực sự tồn tại như một ngôn ngữ native**, dù chưa có struct, generic, ownership đầy đủ, async, concurrency hay standard library.

Và từ đây, hướng phát triển hợp lý nhất không phải “thêm thật nhiều syntax”, mà là **đưa từng semantic capability vào pipeline mà không phá Genesis**:

```text
G5
 ↓
Struct
 ↓
Copy
 ↓
Move
 ↓
Partial Move
 ↓
Drop
 ↓
view / mut_view
 ↓
Region analysis
 ↓
Closure
 ↓
Generic
 ↓
Trait/static dispatch
 ↓
Option/Result
 ↓
Vec/Text
 ↓
Concurrency
 ↓
Async
```

Đặc biệt, **Struct → Move → Drop → view/mut_view** sẽ là chuỗi tiếp theo quan trọng nhất, vì nó sẽ kiểm chứng xem mô hình **“compiler quản lý ownership/lifetime, lập trình viên không viết borrow/lifetime”** của Axiom có thực sự đơn giản và hiệu năng cao như mục tiêu ban đầu hay không.
