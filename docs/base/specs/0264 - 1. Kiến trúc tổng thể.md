## BOOTSTRAP-006 — AXIOM0-HARNESS

Đây là bước rất quan trọng. Từ đây Axiom không chỉ có compiler, mà có **một hệ thống tự kiểm chứng compiler** để AI agent có thể tự phát triển mà không làm kiến trúc bị trôi.

Nguyên tắc:

> **Compiler tạo ra kết quả. Harness quyết định kết quả có hợp lệ hay không.**

Và quan trọng hơn:

> **AI agent không được tự đánh giá “có vẻ đúng”. Mọi milestone phải được harness chứng minh.**

# 11. Snapshot normalization

MIR snapshot **không được phụ thuộc vào ID nội bộ không ổn định**.

Ví dụ không nên:

```text
FunctionId(0x7ff812345)
```

mà:

```text
fn main
```

Không nên:

```text
%tmp_918273
```

nếu ID đó thay đổi theo hash table.

Nên canonicalize:

```text
%0
%1
%2
```

Tương tự:

```text
BlockId → bb0
SymbolId → semantic name
TypeId → canonical type
```

Nhưng nếu test đang kiểm tra chính ID stability thì mới giữ nguyên.

# 14. Differential test: MIR Interpreter vs Native

Đây là một trong những vũ khí mạnh nhất của Axiom.

```text
source
  │
  ├────→ MIR → interpreter → result A
  │
  └────→ MIR → backend → native → result B
```

Harness kiểm tra:

```text
A == B
```

Ví dụ:

```axiom
fn main() -> i32 {
    return (20 * 3) - 18;
}
```

Interpreter:

```text
42
```

Native:

```text
42
```

Pass.

Nếu:

```text
interpreter = 42
native = 40
```

thì:

```text
AXIOM DIFFERENTIAL FAILURE
```

Đây sẽ cực kỳ hữu ích khi phát triển:

- instruction selection
- register allocation
- optimization
- ABI
- encoder

# 18. Trạng thái test

Chỉ nên có tập trạng thái nhỏ:

```text
PASS
FAIL
XPASS
XFAIL
SKIP
BLOCKED
CRASH
TIMEOUT
```

Trong đó:

### `FAIL`

Compiler chạy nhưng kết quả sai.

### `CRASH`

Compiler crash.

### `TIMEOUT`

Compiler hoặc executable treo.

### `BLOCKED`

Test chưa thể chạy do milestone/target chưa hỗ trợ.

### `XFAIL`

Được biết trước là chưa pass.

Nhưng **không được dùng XFAIL để che regression**.

Nếu một test đang:

```text
XFAIL
```

mà đột nhiên pass:

```text
XPASS
```

Harness phải báo để agent xử lý.

```text

 ↓
```

```text

```

# 27. Reproducible Build Check


và kiểm tra:

```text

same object

```


Đây cũng là lý do ngay từ đầu:

- ID deterministic
- symbol ordering deterministic
- section ordering deterministic
- hash iteration deterministic ở các bước output

## Và sau BOOTSTRAP-006

Thứ tự hợp lý tiếp theo là:

```text
BOOTSTRAP-007
    ↓
AXIOM0 Language Core Expansion
    ↓
BOOT-12 Variables
    ↓
BOOT-13 CFG
    ↓
BOOT-14 Functions + ABI
    ↓
BOOT-15 Struct + Layout
    ↓
BOOT-16 Arrays
    ↓
BOOT-17 Enum + Match
    ↓
BOOT-18 Result + Option
    ↓
BOOT-19 Ownership
    ↓
BOOT-20 Capability/View
    ↓
BOOT-21 Drop
    ↓
BOOT-22 Cleanup
```

**Điểm đáng chú ý:** từ đây tôi sẽ không tiếp tục mở rộng spec một cách vô hạn nữa. Kiến trúc Axiom hiện đã đủ sâu; giai đoạn tiếp theo nên chuyển từ **“thiết kế ngôn ngữ” sang “xây compiler thật”**. Việc tiếp theo nên là thiết kế **BOOTSTRAP-007 — Language Core Execution Model**, tức chốt chính xác semantics của `let/var`, assignment, expression, lvalue/place, function call, return và CFG để Stage-0 có thể thực sự bắt đầu compile chương trình Axiom đầu tiên.
