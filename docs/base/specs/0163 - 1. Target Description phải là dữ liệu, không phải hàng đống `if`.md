Tiếp tục. Bây giờ ta đi vào **X86-64 Backend v0.1**, với mục tiêu không phải “hỗ trợ x86 thật nhiều”, mà là tạo **vertical slice native đầu tiên**:

```text
Axiom source
 → AST
 → HIR
 → Typed HIR
 → Ownership
 → MIR
 → Verified MIR
 → LIR
 → x86-64 Machine IR
 → Machine bytes
 → ELF64
 → executable
```

Mục tiêu đầu tiên:

```axiom
fn main() {
}
```

→ một ELF64 chạy được trên Linux, **không LLVM/GCC/Clang**.

---

# 1. Target Description phải là dữ liệu, không phải hàng đống `if`

Không nên viết backend kiểu:

```text
if opcode == ADD:
    if x86:
       ...
```

Thay vào đó target được mô tả bằng database:

```text
Target
 ├── Architecture
 ├── ABI
 ├── RegisterFile
 ├── InstructionSet
 ├── CallingConvention
 ├── DataLayout
 ├── RelocationModel
 ├── ObjectFormat
 └── Features
```

Ví dụ:

```text
x86_64-linux-gnu
```

có:

```text
arch       = x86_64
pointer    = 64
endianness = little
object     = ELF64
abi        = SystemV
```

Sau này:

```text
x86_64-windows
```

chỉ thay:

```text
object = PE/COFF
abi    = Windows x64
```

Backend instruction selection vẫn dùng phần lớn code chung.

# 10. Instruction Selection

Ví dụ LIR:

```text
v2 = ADD v0, v1
```

instruction selector có thể tạo:

```text
MOV RAX, v0
ADD RAX, v1
```

Nhưng nếu:

```text
v1 = LOAD [RBX+8]
```

thì có thể tối ưu thành:

```text
MOV RAX, v0
ADD RAX, [RBX+8]
```

Không cần:

```text
LOAD RCX
ADD RAX, RCX
```

Đây là lý do Machine IR phải hỗ trợ memory operands.

# 12. Một điểm thú vị: `LEA`

`LEA` không chỉ để lấy địa chỉ.

Có thể dùng:

```text
LEA RAX, [RDI + RSI*4]
```

cho:

```text
rax = rdi + rsi*4
```

Optimizer có thể tận dụng nó cho integer arithmetic.

Vì vậy target optimizer nên hiểu idiom này.

# 25. Đừng viết encoder bằng chuỗi assembly

Không:

```text

```

→ gọi assembler.

Mà:

```text

    opcode: MOV
    operands: [
        Reg(RAX),
        Reg(RBX)

}
```

→ encoder → bytes.

Đây là điều kiện để Axiom cuối cùng thực sự độc lập toolchain.



```text
RAX
```

```text
    RDI

    R10
```

Nhưng production compiler cuối cùng:

```text
Axiom object writer
 → Axiom linker
```

không cần external linker.

# 50. Mốc cực kỳ quan trọng: SELF-HOST-0

Ngay sau khi backend x86 chạy:

```text
Axiom compiler written in C/Rust/whatever bootstrap
```

sẽ compile:

```text
Axiom source
```

Nhưng chưa self-host.

Mục tiêu kế tiếp:

```text
Bootstrap compiler
       │
       ├── compile Axiom compiler source
       ↓
Axiom compiler binary
       │
       └── compile itself
```

Chu trình:

```text
C-bootstrap compiler
        ↓
Axiom compiler v1
        ↓
Axiom compiler v2
        ↓
compare
```

Khi:

```text
Axiom compiler v2
```

có thể tự compile source của chính nó, ta đạt:

> **self-hosting bootstrap.**

### Việc kế tiếp nên làm ngay

Sau **x86-64 Target + ABI + Machine IR + Encoder + ELF Writer**, bước tiếp theo là **Axiom Linker v0.1**.

Không cần làm linker “khổng lồ” ngay. Ta sẽ thiết kế một linker đủ để:

```text
Axiom-generated .o
       +
Axiom-generated .o
       ↓
ELF executable
```

và xử lý được **symbols, sections, alignment, relocations, entry point, static linking**. Đây sẽ là mảnh cuối để Axiom bắt đầu có một **native toolchain độc lập thực sự**, thay vì chỉ là compiler sinh object file.
