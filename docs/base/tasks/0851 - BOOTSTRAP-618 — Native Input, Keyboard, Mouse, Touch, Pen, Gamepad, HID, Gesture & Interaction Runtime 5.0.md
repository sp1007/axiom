# BOOTSTRAP-618 — Native Input, Keyboard, Mouse, Touch, Pen, Gamepad, HID, Gesture & Interaction Runtime 5.0

**Status:** SPECIFIED  
**Layer:** Native Runtime / Input & Interaction  
**Depends on:** BOOTSTRAP-600 → 617

---

# 1. Purpose

BOOTSTRAP-618 defines Axiom's unified native input and interaction subsystem:

- keyboard;
- mouse;
- touch;
- pen/stylus;
- trackpad;
- gamepad;
- joystick;
- wheel;
- HID;
- raw input;
- text input;
- IME;
- gestures;
- pointer capture;
- focus;
- input routing;
- device hot-plug;
- controller mapping;
- multi-device interaction;
- event recording/replay;
- deterministic input testing.

The central design principle is:

> **Physical input and logical user intent are separate layers.**

Axiom must not force application code to understand platform-specific scan codes, window messages or device APIs.

---

# 2. Scope

618 handles:

```text
Physical Device
      ↓
Input Event
      ↓
Normalization
      ↓
Device State
      ↓
Focus / Capture
      ↓
Routing
      ↓
Gesture / Text / Action
      ↓
Application
```

Higher GUI frameworks may build controls and widgets on top.

---

# 3. Non-Goals

618 does not define:

- GUI controls;
- menus;
- buttons;
- application widgets;
- game engine gameplay;
- accessibility UI;
- high-level command systems.

Those belong to higher layers.

# 277. Architectural Decision

BOOTSTRAP-618 establishes **one unified input model without collapsing all devices into one abstraction**.

The critical separation is:

```text
Physical Device
      ↓
Raw Event
      ↓
Normalized Event
      ↓
Focus / Capture / Routing
      ↓
Text / Gesture / Action
      ↓
Application
```

This lets Axiom support a console application, desktop GUI, mobile application, game, drawing application, IDE or embedded device using the same underlying runtime while retaining access to low-level input when explicitly required.
