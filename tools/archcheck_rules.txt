# archcheck rules (T006). Read by tools/archcheck.py; one directive per line, '#' starts a comment.
# Owner: QA (T006). Changing a rule is an architecture decision: it needs an ADR or an architect
# task, because the rules are the machine form of spec/invariants.md (INV-LAYER-001..008).
#
# Directive syntax
#   src-root <dir>                      C sources of axiom0, relative to the repository root
#   std-root <dir>                      Axiom standard library root (INV-LAYER-008)
#   order <layer> <layer> ...           bottom to top; 'a|b' is one rank holding peers a and b
#   deny <INV> <from...> : <to...>      any of <from> must not include any of <to>
#   only <INV> <layer> : <layers...>    <layer> includes only these layers (and itself)
#   users <INV> <layer> : <layers...>   only these layers (and itself) include <layer>
#   areas <AREA...>                     the diagnostic areas of spec/diagnostics.md section 3 (AXD-020)
#   codes-dir <dir>                     diagnostic registry directory, relative to src-root
#   diag-macro <NAME...>                registration macros whose first argument is a diagnostic code
#   output-fn <fn...>                   functions library layers must not call (INV-LAYER-006)
#   output-stream-fn <fn...>            same, but only when the first argument is stdout/stderr
#   output-allow <glob> [<fn...>]       files (relative to src-root, fnmatch) allowed to call them
#
# Violations are matched most specific first: deny, only, users, then the layer order. A layer is
# the directory of a header/source under src-root (longest match among the layers named here).

src-root bootstrap/axiom0/src
std-root std

# INV-LAYER-001: a module includes its own layer or lower layers only. Peers of one rank
# (interp|opt) do not include each other either: both consume verified MIR independently.
# `objmodel` is outside the chain: a low layer, see the only/users rules below.
order kernel source diag lex syntax resolve hir types traits mir own verify interp|opt lir abi target/x64 obj link driver

only  INV-LAYER-001 kernel   : kernel
only  INV-LAYER-001 objmodel : kernel
users INV-LAYER-001 objmodel : target/x64 obj link driver

# INV-LAYER-002: obj and link stay below the IR. `link` reads objects through the readers that
# live in `obj`, so it may include `obj`; nothing else is allowed.
only  INV-LAYER-002 obj  : objmodel kernel diag
only  INV-LAYER-002 link : objmodel kernel diag obj

# INV-LAYER-003: oracle and optimizer independence.
deny INV-LAYER-003 interp : target/x64 lir abi obj link
deny INV-LAYER-003 opt    : syntax

# INV-LAYER-004: const evaluation goes through an interface declared in `types`.
deny INV-LAYER-004 types : interp

# INV-LAYER-005: the back end never sees the front end.
deny INV-LAYER-005 lir abi target/x64 objmodel obj link : lex syntax resolve hir

# INV-LAYER-006: library layers neither print nor terminate the process. The driver and the
# diagnostic renderers print; the ICE reporter (diag/*ice*) prints and aborts. A line that cannot
# follow the rule carries `archcheck:allow(INV-LAYER-006): <reason>` in a comment on that line or
# the line above (this is the only pragma archcheck honours).
output-fn        printf vprintf puts putchar exit _Exit _exit quick_exit abort
output-stream-fn fprintf vfprintf fputs fputc putc fwrite
output-allow driver/*
output-allow diag/*render*
output-allow diag/*ice*

# INV-LAYER-007: diagnostic codes live only in diag/codes/<AREA>.def (AXD-020, AXD-030).
areas LEX PARSE NAME TYPE TRAIT PAT MOVE INIT CAP DROP UNSAFE CONST VERIFY FFI LINK IO DRIVER ICE
codes-dir diag/codes
diag-macro AX_DIAG
