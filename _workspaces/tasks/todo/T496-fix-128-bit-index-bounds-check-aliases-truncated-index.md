# T496 — 128-bit index bounds check (ADR-0044 §1)

## Goal
`a[i]` and `a[lo..hi]` with an `i128`/`u128` index (or bound) trap `index out of bounds` (resp. the range-bounds
panic) for every value outside `0..len`, including values whose low 64 bits are a valid index
(`2^64 + 1`, `2^127 + 2`, `-(2^64) + 1`). Today the index is cast to `usize` first and the truncated value is
checked, so the access silently reads an unrelated element (a memory-safety-level soundness bug in the oracle and in native code, all modes).

## Scope
- `compiler/mir/builder.ax` `mb_emit_index_bounds_check` and `mb_emit_range_bounds_check` (and the index-operand cast they
  follow): when the index type has width > 64 bits, reinterpret the index as the unsigned type of the same width, compare
  `idx_u < Cast(len, u128)` in that width, assert (existing `index out of bounds` message), and only then emit the
  `Cast(IntToInt, idx, usize)` used by `MIR_PROJ_INDEX` (SPEC-40 AXS-INT-053 as amended by ADR-0044 §1). Widths <= 64 bits keep the
  current lowering (it is exact).
- MIR verifier invariant INV-INT-003 (homogeneous operands) must still hold: the compare's operands are both `u128`.
- Tests: remove the `xfail` argument for the three generated tests in `tests/run/numeric/mixed_int_matrix/gen_matrix.py`
  (`index_trap_u128_alias`, `index_trap_u128_alias_hi`, `index_trap_i128_alias`) and regenerate; delete the helper
  `repro_u128_index_alias.ax`; add `tests/run/index_128_range/` (slice range with a 128-bit bound that aliases, `a[lo..hi]` traps in interp, native -O0, native -O1;
  exact `stdout:`/`exit: 101`/`stderr-contains:`) and an in-range 128-bit index case that must still read the right element.
- Selfhost bundles are regenerated by `taskctl snapshot`/`accept`; do not edit, list or commit them. Keep the stage-2/stage-3 fixed point.
