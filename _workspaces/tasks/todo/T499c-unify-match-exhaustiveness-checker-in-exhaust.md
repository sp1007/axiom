# T499c — Single exhaustiveness checker

## Goal
Since T081 there are two copies of the match exhaustiveness checker: `tc_match_check_exhaustiveness` /
`tc_match_check_exhaust_bool_or_enum` in `compiler/types/typeck.ax` (live) and `match_check_exhaustiveness` /
`match_check_exhaust_bool_or_enum` in `compiler/types/exhaust.ax` (only referenced under `if false {}`). T499b added the
column-wise usefulness checker (`match_check_tuple_exhaustiveness`) in `exhaust.ax` and routes only tuple scrutinees to it.
Two copies drift (T499b was blocked by exactly this), and the old scalar/enum checker has a known soundness gap:
`match o { Opt.Some(1) => .., Opt.None => .. }` on a bare enum is accepted although `Opt.Some(2)` is unmatched
(`_workspaces/reports/T499b-report.md`, Design). Decision recorded in `_workspaces/reports/unblock-T499b.md`.

## Scope
- Generalise the usefulness entry point in `compiler/types/exhaust.ax` so it accepts any scrutinee type (bool, enum with
  payloads, integers/char incl. ranges, structs, tuples, opaque), and use it for every `match`.
- `compiler/types/typeck.ax`: `tc_match_check_exhaustiveness` becomes a thin call into `exhaust.ax`; delete
  `tc_match_check_exhaust_bool_or_enum` and the remaining duplicated helpers, and the `if false {}` reference.
- Delete the superseded old checker functions in `exhaust.ax` once nothing calls them (keep `get_pat_interval*` if other
  code uses them).
- Preserve diagnostics: `AX_PAT_NON_EXHAUSTIVE` (span of the match expression) and `AX_PAT_UNREACHABLE` (warning). Every
  existing `tests/ui` expectation must stay unchanged except cases that were wrongly accepted; list each changed
  expectation in the report with the reason.
- i128/u128 scrutinees: keep today's behaviour (the old checker has 128-bit interval support via `get_pat_interval_128`);
  either extend the usefulness checker to 128-bit intervals or keep that path delegated — no regression allowed.
- Tests: `tests/ui/exhaust_unified/*.ax` — enum with refutable payload (`Some(1)` + `None` → non-exhaustive), nested
  enum-in-enum, struct pattern with a refutable field, integer range gap on a bare `u8`, unreachable arm after full cover;
  `tests/run/exhaust_unified/*.ax` (three modes, exact `stdout:`) for complete matches of the same shapes.
- The stricter check may reject existing compiler/std/test sources that relied on the gap. Run it over the whole tree
  first; if files outside `paths:` need a new arm, report them under "Blocked" with the exact list (the architect
  extends `paths:`) instead of weakening the check.
- Keep the stage-2/stage-3 fixed point; selfhost bundles are regenerated by `taskctl snapshot`/`accept` (do not edit or
  list them).
