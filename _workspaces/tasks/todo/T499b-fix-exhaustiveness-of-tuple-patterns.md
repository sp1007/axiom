# T499b — Tuple patterns in the exhaustiveness checker

## Goal
Valid programs are rejected (`_workspaces/reports/T499a-report.md` follow-up 1, reproduced by the architect in triage-1122
with the current stage-2 compiler):

```
fn f(t: (bool, bool)) -> i32 { match t { (true, q) => 1, (false, q) => 2 } }   // AX_PAT_NON_EXHAUSTIVE (wrong)
fn g(t: (bool, bool)) -> i32 { match t { (p, q) => 3 } }                        // AX_PAT_NON_EXHAUSTIVE (wrong)
fn h(t: (bool, bool)) -> i32 { match t { (true, true) => 1, (false, _) => 2 } } // must stay AX_PAT_NON_EXHAUSTIVE
```

Also `match (1i64, 2i64) { (p, q) => p + q }` and `match t { (p, _) => p }`. Tests work around it with a trailing `_` arm
(`tests/run/tuple_expr_names/match_and_destructure.ax`).

## Scope
- `compiler/types/exhaust.ax`: treat a tuple pattern as a constructor with one field per element and specialise the matrix
  column-wise (standard usefulness algorithm), so binding/wildcard elements are irrefutable, `bool`/enum/integer-range
  elements combine across arms, nested tuples and tuples of enums (`(Some(x), _)`, `(None, _)`) work, and the reported
  "missing" case stays correct for genuinely incomplete matches. Guards keep counting as refutable.
- Also cover `let (a, b) = t` (irrefutable `let` must not need `else`) and `if let`/`while let` with tuple patterns if they
  use the same checker.
- Remove the workaround `_` arm from `tests/run/tuple_expr_names/match_and_destructure.ax` (keep its expected output).
- Tests: `tests/ui/exhaust_tuple/*.ax` (incomplete cases with exact code + line:col: `h` above, missing `(None, None)`,
  integer ranges in a tuple); `tests/run/exhaust_tuple/*.ax` (three modes, exact `stdout:`) for the accepted forms, including
  nested tuples, tuple of enum with payload binding, and a tuple scrutinee built from a call.
- Keep the stage-2/stage-3 fixed point; selfhost bundles are regenerated by `taskctl snapshot`/`accept` (do not edit or list them).

## Acceptance
- [ ] `f`, `g` compile and run in all three modes; `h` and the other incomplete cases report `AX_PAT_NON_EXHAUSTIVE`.
- [ ] `tests/ui`, `tests/run`, selfhost typeck/exhaust groups pass; gate per axiom-qa.md "Per-task gate scope".
