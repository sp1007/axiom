# T428l — std has exactly one owned-text `String`

## Why
`_workspaces/reports/unblock-T428a.md`: `std.io`, `std.env`, `std.process`, `std.text.utf16` and `std.text.string` each
declare their own `pub struct String { ptr, len, .. }` and `string_new`-style helpers (grep
`pub struct String` under `std/`). After T428g they are distinct nominal types, so a `String` returned by
`std.io.read_to_string` cannot be passed to `std.text.string` functions or to `std.thread`, and a program that uses
both sees two incompatible `String`s. REQ-STD-046/086/126: `String` is *the* owned UTF-8 text type of std. The
duplicates are bootstrap leftovers from before `std.text.string` existed.

## Scope
1. Make `std.text.string.String` the only `String`: in `std/io/io.ax`, `std/env/env.ax`, `std/process/process.ax`
   and `std/text/utf16/utf16.ax` delete the local struct and its duplicate helpers and `use std.text.string.String`
   (+ the helpers needed). Layering check: `std.text.string` must not import any of these modules (it imports only
   `std.core` and `std.text.utf8` today); if a helper exists only in a duplicate, move it into `std/text/string.ax`.
   Keep every public function signature of these modules otherwise unchanged (the type name stays `String`).
2. Update callers under `std/`, `compiler/` and `tests/` that relied on fields or helpers of a removed copy (grep for
   the removed helper names). Selfhost bundles are regenerated by the harness; do not edit them.
3. Test `tests/std/text/single_string_type/` (`modes: interp native`, exact `// stdout:`): a `String` from
   `std.io.read_to_string`, from `std.env`, from `std.process` output and from utf16 decoding is passed to
   `std.text.string` functions and to a function of another of these modules in one program.
