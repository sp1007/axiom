# T545 — Remove the UB-04 patterns T543 left in the other probe harnesses

## Why
`_workspaces/reports/T543-qa.md` follow-ups F1/F2. T543 fixed the uninitialised reads that T502's UB-04 detector
exposed in `compiler/opt` and in 7 opt harness templates. The same two patterns remain in probe templates outside
T543's scope. They pass today only because the executed paths never read before writing; under the T502 strict
oracle (or any change in the probe's control flow) they are UB-04:
- F1: `tests/run/static_items/qa_opt_static_atomic_probe.ax.in` (lines ~110–121) installs an interner map whose
  `smap_ids` come from `arena_alloc_raw` and are never zeroed.
- F2: typed loads of fresh arena memory (`*(arena_alloc_raw(..) as *const DiagBuffer / MemOptStats / DiagSink /
  MirStmt)`) in `tests/run/opt_alias/opt_alias_probe.ax.in` (~14 sites), `opt_escape`, `opt_loops` (line ~320),
  `opt_loop_vec`, `opt_scalar`, `opt_slp_vec` probe templates.

## Scope
1. F1: zero the map exactly as T543 did in its harness templates (the loop after `interner.map_cap = smap_cap`).
2. F2: replace each typed load of fresh arena memory by a struct literal / explicit initialisation written before any
   read (as T543 did in `compiler/opt`). Behaviour of the probes is unchanged.
3. Edit only the `.ax.in` templates in `paths:`; the generated bundles are regenerated by the harness (never list them).

## Acceptance
- [ ] Every test that uses these probes passes as before (`run/static_items/qa_opt_static_atomic.test`,
      `run/opt_alias`, `run/opt_escape`, `run/opt_loops`, `run/opt_loop_vec`, `run/opt_scalar`, `run/opt_slp_vec`),
      and the same probes run under the T502 strict oracle (`--interp` with the UB detector on) report no UB-04.
- [ ] A grep of the 7 templates finds no `*(arena_alloc_raw(` typed load left.
- [ ] Normal gate (task tests + smoke); failing ids ⊆ `_workspaces/baseline-failures.txt`.
- [ ] Report `_workspaces/reports/T545-report.md` with the sites changed per file and an exact `## Files changed`.
