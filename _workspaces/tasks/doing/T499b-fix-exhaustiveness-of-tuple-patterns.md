# T499b — Tuple patterns in the exhaustiveness checker

## Goal
Valid programs are rejected (`_workspaces/reports/T499a-report.md` follow-up 1, reproduced by the architect in triage-1122
with the current stage-2 compiler):

```
fn f(t: (bool, bool)) -> i32 { match t { (true, q) => 1, (false, q) => 2 } }   // AX_PAT_NON_EXHAUSTIVE (wrong)
fn g(t: (bool, bool)) -> i32 { match t { (p, q) => 3 } }                        // AX_PAT_NON_EXHAUSTIVE (wrong)
fn h(t: (bool, bool)) -> i32 { match t { (true, true) => 1, (false, _) => 2 } } // must stay AX_PAT_NON_EXHAUSTIVE
```

Also `match (1i64, 2i64) { (p, q) => p + q }` and `match t { (p, _) => p }`. Tests work around it with a trailing `_` arm
(`tests/run/tuple_expr_names/match_and_destructure.ax`).
