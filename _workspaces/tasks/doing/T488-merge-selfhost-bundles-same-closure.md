# T488 — Merge selfhost bundles with identical module closures

## Why (owner request 2026-11-17/18)
Selfhost is 9.2 h of the 10.6 h serial suite over 179 ids; 102 bundles share only 37 distinct module sets. Each
bundle recompiles the same closure (e.g. `qa_lir_from_ax_a.ax` is 2.9 MB of which its own test template is 39 KB,
1.4%). The earlier Axiom prototype kept its gate fast by compiling the compiler sources once (one concatenated
self-build) rather than once per test file. A 5-way merge compiles about 1.06× one bundle instead of 5×.

## Scope
1. **Measure first** with the snapshot's stage-2 compiler and `--time-passes`: e.g. lir a..e separately vs merged.
   If merged > 0.6 × the sum of the separate compiles, report the numbers and stop (`STATUS: BLOCKED` with the
   measurement; the architect decides).
2. A `bundle_common` "merge group": several templates' bodies under one prelude and one module closure, each
   original `main` renamed and called in order, each printing its own OK/FAIL line with the original bundle name,
   continuing after a failure. Generators (`tests/selfhost/<area>/gen_*.py`, `*.ax.in`, `*.test`) of the merged
   groups are edited as needed. After step 1, add each `tests/selfhost/<area>` directory you will edit to this
   task's `paths:` (never the whole `tests/selfhost` tree; generated bundles are regenerated by the harness, do not
   list them) and list every edited file in the report.
3. Remap ids in `_workspaces/baseline-failures.txt`, `tools/affected_map.txt`, `tests/smoke.list`.

## Acceptance (quality guards — mandatory, this is a compiler)
- Every original assertion is kept (report: count of test cases per original bundle before/after, equal).
- Mutation proof: break one case per merged group and see exactly that line FAIL natively (and at native-O1), the
  rest still running.
- Interp/native comparison unchanged (`WEAK-NATIVE` report shows no new entries).
- Selfhost wall time before/after on the same compiler.
