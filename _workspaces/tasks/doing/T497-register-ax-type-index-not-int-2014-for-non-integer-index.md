# T497 — `AX_TYPE_INDEX_NOT_INT` (2014)

## Goal
`a[i]` where `i` is not an integer (`bool`, `f32`, `f64`, a struct, a tuple, a `view`) is rejected with exactly
`AX_TYPE_INDEX_NOT_INT` (SPEC-40 AXS-INT-053 rule 1 last bullet, AXS-INT-060 row 2014). Observed (T455, FU-T455-IDXCODE): the code is
not defined in `compiler/diag/code.ax`; `a[true]` reports `AX_TYPE_MISMATCH` and `a[1.0f32]` reports `AX_TYPE_UNSUPPORTED_IN_BOOTSTRAP`.

## Scope
- Register `AX_TYPE_INDEX_NOT_INT` in `compiler/diag/code.ax` (next free compiler id; name table; `explain` entry in
  `compiler/diag/explain/mod.ax`) with the SPEC-40 display number 2014; follow how T483 registered `AX_CONST_SHIFT_RANGE`.
  `spec/diagnostics.md` is updated by the architect from the report.
- `compiler/types/typeck.ax`: the index operand check (array and slice, through `view`/`mut_view` bases) emits it, with a primary span on the
  index expression and the message `index must be an integer, found <type>`. Integer (`IntVar` included) indices are unchanged; range
  indices `a[lo..hi]` apply the same check to each bound.
- Tests: move `tests/run/numeric/mixed_int_matrix/repro_index_not_int_code.ax` to `tests/ui/index_not_int/bool.ax` as a `// test: ui`
  with the exact code and span; add `f32`, `f64`, struct, tuple and range-bound cases. Delete the old helper.
- Keep the stage-2/stage-3 fixed point; selfhost bundles are regenerated by `taskctl snapshot`/`accept` (do not edit or list them).

## Acceptance
