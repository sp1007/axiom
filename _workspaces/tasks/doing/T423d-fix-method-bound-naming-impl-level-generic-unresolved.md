# T423d — Impl-level generics in method bounds

## Goal
`tests/std/fiber/impl_generic_in_method_bound_xfail.ax` (T423 report F3): in `impl<R> W<R> { pub fn mk<F: FnOnce<R>>(f: F) -> i64 }`
the `R` inside the method's bound is not found (`AX_NAME_UNRESOLVED`), also with a `where` clause, although `R` resolves in
the method's parameter and return types. Because of this `std.fiber` declares `Fiber.new<F>` / `Fiber.spawn<F>` without the
`F: FnOnce<R>` bound (SPEC-34 AXS-EXEC-053.3).

## Scope
- Make the impl's generic parameters visible while resolving and checking the bounds (inline and `where`) of a method's own
  generic parameters, in every pass that walks them (resolver ribs, HIR lowering of bounds, typeck/trait solving of the bound,
  mono substitution of the impl arguments into the method bound). Fix in the owning modules.
- Remove the `xfail` line of `tests/std/fiber/impl_generic_in_method_bound_xfail.ax` (it must pass in interp, native and
  native-O1).
- Restore the bound in `std/fiber/mod.ax`: `Fiber.new<F: FnOnce<R>>` and `Fiber.spawn<F: FnOnce<R>>`; run
  `python tests/std/fiber/gen_tests.py` to regenerate the fiber bundles (`--check` passes) and keep `tests/std/fiber` green.
- Tests `tests/run/impl_generic_in_method_bound/*.ax` (exact stdout): inline bound, `where` bound, two impl generics in one bound,
  impl generic inside a nested generic bound (`F: FnOnce<Option<R>>`), trait impl method (`impl<T> Tr for S<T> { fn m<U: Into<T>>(..) }`
  if traits allow), call sites with inferred and explicit type arguments. `tests/ui/impl_generic_in_method_bound/*.ax`: an unknown
  name in a method bound still reports `AX_NAME_UNRESOLVED` with the exact span; a closure whose result type does not match `R`
  reports a bound error, not a crash.
- Keep the stage-2/stage-3 fixed point; selfhost bundles are regenerated by `taskctl snapshot`/`accept` (do not edit or list them).
