# T498a — odd-size aggregates must be copied with exact-width accesses

## Goal
Natively, an aggregate (array, struct, tuple) whose size is not 1, 2, 4 or 8 bytes but at most 8 (3, 5, 6, 7 bytes) is
loaded and stored with a widened scalar access (4 or 8 bytes) and the extra bytes overwrite the next field. The interpreter is
correct, so this is a silent miscompile (FU-T498-AGG-WIDEN, `_workspaces/reports/T498-report.md` follow-up 3).

Repro (prints `4` in interp, `0` natively):
```axiom
struct Rec { tag: u8, vals: [3]u16 }
fn main() -> i32 {
    let r = Rec { tag: 4u8, vals: [5u16, 10u16, 15u16] };
    print_int(r.tag as i64);
    print("\n");
    0
}
```
Layout is `vals@0` (6 bytes) and `tag@6`; the LIR stores `vals` with an 8-byte `load`/`store` after `tag` was stored.
`[3]u8` next to a `u8` fails the same way.

## Scope
- Find every place where the LIR builder or x86-64 instruction selection picks a single scalar access for an aggregate by
  size (aggregate `load`/`store`/copy, argument and return passing, struct/array literal construction, field and element
  writes, spills/reloads of an aggregate vreg). An aggregate whose size is not exactly 1, 2, 4 or 8 must be moved in exact
  chunks (`isel_chunk_size`-style 4+2+1 decomposition) or through memory, never with a wider access. Win64 ABI passing of a
  3/5/6/7-byte aggregate is by reference (`abi_classify`); check it agrees.
- Fix it in the owning module (`compiler/target/x64/isel.ax`; the LIR builder if the width is chosen there — it is a lock,
  shared with T423, so the task waits for T423 to release it).
- Tests `tests/run/agg_odd_size/*.ax`, interp/native/native-O1 with exact `// stdout:`: the repro; `[3]u8`, `[5]u8`, `[7]u8`,
  `[3]u16` followed by `u8`/`u16` fields and preceded by them; such fields in a tuple, in an array of structs, passed by value,
  returned, assigned, copied twice, mutated through `mut_view`; a struct of size 12 whose tail is 4 bytes (no regression).
  Canaries print every byte of the neighbouring field.
- Switch `tests/run/array_copy/nested_and_field.ax` back to the `[3]u16` field its author wanted (it uses `[4]u16` to avoid
  this bug).
- Keep the stage-2/stage-3 fixed point; selfhost bundles are regenerated by `taskctl snapshot`/`accept` (do not edit or list them).
