# T496a — `s[a..=b]` includes `b`

## Goal
`let s: view<[i32]> = view(a); let t = s[0..=2]; len(t)` prints 2 (expected 3) in interp and native; `s[..=hi]` likewise
(`_workspaces/reports/T496-qa.md` follow-up 1; reproduces before T496). ADR-0045 fixes the meaning: elements `a` to `b` inclusive,
valid iff `b < len` (checked in the bound's own width, ADR-0044 §1) and `a <= b + 1`; the exclusive end `b + 1` is computed in `usize`
only after `b < len`, so it cannot overflow.

## Scope
- Find where the range's `inclusive` flag is lost (HIR lowering, typeck of the index range, or the MIR builder) and lower
  `s[a..=b]`/`s[..=b]` per ADR-0045 through the existing `mb_emit_range_bounds_check` path (T496), for arrays, slices,
  `view`/`mut_view` bases (AXS-SEM-047) and every integer bound type.
- Tests `tests/run/slice_inclusive/*.ax` (interp/native/native-O1, exact `// stdout:`): `s[0..=2]`, `s[..=2]`, `s[k..=k]`,
  `s[k..=k-1]` (empty), on `[N]T`, `view<[T]>`, `mut_view<[T]>` (write through the sub-slice), with `u8`/`i32`/`usize`/`u64`/`u128`/`i128`
  bounds. Trap tests (expected panic `index out of bounds`): `b == len`, `b == usize.MAX`, `b == u64.MAX`, `b == u128.MAX`,
  negative `i128` bound, `a > b + 1`.
- Keep the stage-2/stage-3 fixed point; selfhost bundles are regenerated by `taskctl snapshot`/`accept` (do not edit or list them).
