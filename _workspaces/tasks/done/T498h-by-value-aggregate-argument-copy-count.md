# T498h — Copies of by-value aggregate arguments

## Goal
`_workspaces/reports/T498c-qa.md` FU-QA-T498c-1, analysed in triage-1122: `fn huge(a: [262144]u8, t: u32)` called once from
`main` makes the native exe die with `STATUS_STACK_OVERFLOW` (0xC00000FD) at `-O0` and `-O1`; `[200000]u8` passes; with
`--stack-reserve 4194304` the 256 KiB case passes. So the fault itself is by-spec (ADR-0003: 1 MB default reserve, stack probes
turn the overflow into a deterministic fault; SPEC-03: no test may depend on stack depth) — **not a soundness bug**. The defect
is the copy count: about four stack copies of the argument (literal temporary, the binding, the caller's argument copy, a
callee-side copy) where the Win64 ABI needs at most the binding plus one caller-owned copy passed by hidden pointer (and none
when the source is a dead temporary or a moved value).

## Scope
- Measure the frame sizes of caller and callee for the repro at `-O0` and `-O1` (`inspect --emit=mi` / frame dump) and
  report which copies exist and why.
- Remove the copies that the ABI and SPEC-10 (move of a non-Copy value; `MIR_OP_COPY` "the backend may elide the physical
  copy", AXS-OWN-003) do not require: at minimum the callee must use the incoming hidden pointer of a by-value aggregate
  parameter directly instead of copying it into its own frame, and at `-O1` a moved or last-use argument is passed without a
  caller copy. Keep the semantics: a Copy array that is still used after the call must not be modified by the callee.
- Tests `tests/run/agg_arg_copies/` (three modes, exact `stdout:`): `[262144]u8` by value with the default stack (passes after
  the fix), the callee mutates its parameter while the caller's still-used Copy array stays intact, a moved non-Copy aggregate,
  a struct with an array field, recursion depth with a 64 KiB by-value parameter.
- Update the stale comment in `tests/run/array_copy/large_and_edge.ax` (the 256-byte interp limit was removed by T498c).
- Keep the stage-2/stage-3 fixed point; selfhost bundles are regenerated by `taskctl snapshot`/`accept` (do not edit or list them).
