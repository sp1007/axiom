# T423c — Generic call inference inside closure bodies

## Goal
`tests/std/fiber/closure_generic_infer_xfail.ax` (T423 report F2): `fn g<T>(v: T) {}` called as `g(1i64)` inside
`run_it(|| -> i64 { g(1i64); 5i64 })` is rejected with `AX_TYPE_UNKNOWN`; `g<i64>(1i64)` is accepted, and the same call in a
plain fn is accepted. std.fiber users must write `yield_val<i64>(x)` inside closures today (SPEC-34 AXS-EXEC-053.3).
Inference of a generic call must not depend on whether the call sits in a closure body.

## Scope
- Find why the generic-argument inference of a call (typeck, and the instantiation recorded for mono/MIR) is not done or not
  recorded for calls inside closure bodies (closure bodies typed in a separate pass, inference variables not resolved/flushed for
  the closure body, or the instantiation lookup keyed by the enclosing fn), and fix it in the owning module.
- Remove the `xfail` line of `tests/std/fiber/closure_generic_infer_xfail.ax` (it must pass in interp, native and native-O1).
- Tests `tests/run/closure_generic_infer/*.ax` (exact `// stdout:`): generic call with inferred `T` from an argument, from the
  expected return type, two generic calls with different `T` in one closure, nested closures, a closure inside a generic fn
  calling another generic fn with the outer `T`, a `move` closure, a closure passed to a generic higher-order fn, method-style
  generic call inside a closure, and a ui test that a really ambiguous call inside a closure still reports `AX_TYPE_UNKNOWN`
  with the right span.
- Keep the stage-2/stage-3 fixed point; selfhost bundles are regenerated by `taskctl snapshot`/`accept` (do not edit or list them).

## Acceptance
- [ ] The repro and all new tests pass in interp, native and native-O1 with WEAK-NATIVE 0.
