# T453a — `print_int` of large unsigned values

## Goal
Natively, `print_int(18446744073709551615u64)` prints `-1`; any `u64`/`usize` value `>= 2^63` prints negative. The interpreter
prints `18446744073709551615` (`_workspaces/reports/T453-report.md` follow-ups; also noted by T454). The native leg of every
test that prints such a value is wrong, so differential tests avoid them today.

Cause (architect): the `TY_BUILTIN_PRINT_INT` lowering in `compiler/lir/builder.ax` sends 128-bit operands to
`lower_print_int128_call` (which honours the signedness) and every other width to the signed 64-bit host routine
`__ax_host_print_int`.

## Scope
- Route unsigned 64-bit operands (`u64`, `usize`, and narrower unsigned types if they are not already zero-extended) through an
  unsigned formatting path: reuse `lower_print_int128_call` with a zero-extended value, or add an unsigned host routine; keep signed
  types unchanged. Check `-O1` (constant-folded arguments) too.
- Tests `tests/run/print_int_unsigned/*.ax` (interp/native/native-O1, exact `// stdout:`): `u64` 2^63-1, 2^63, 2^64-1; `usize.MAX`;
  `u32.MAX`, `u16.MAX`, `u8.MAX`; computed values (`0u64 - 1` wrapping, shifts), `i64.MIN`, `-1i64` (signed unchanged).
- Keep the stage-2/stage-3 fixed point; selfhost bundles are regenerated by `taskctl snapshot`/`accept` (do not edit or list them).
