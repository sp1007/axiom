# T539 — Restrict implicit capability-forgery diagnostic to raw pointers and address types so non-address integers emit `AX_TYPE_MISMATCH` (`fullrun-4` R4)

## Goal
Resolve `fullrun-4` regression R4 (`ui/method/inherent_methods_err.ax`: `Point.sum(10)` emits `AX_SEC_CAPABILITY_FORGERY` instead of `AX_TYPE_MISMATCH`) introduced by `T517` (`4579f0ec`).

Per `SPEC-53 §1.4 AXS-SEC-004 (2)` (`REQ-CAP-123`), raw pointers (`*const T`, `*mut T`), pointer-sized integer addresses (`usize`, `isize`), and address wrapper structs (`PhysAddr`, `VirtAddr`, `WasmAddr`) carry no safe capability provenance and must emit `AX_SEC_CAPABILITY_FORGERY` on both explicit casts and implicit coercions to `view<T>`, `mut_view<T>`, `Str`, or authority tokens (`FsCap`, `NetCap`, `EnvCap`, `ProcessCap`, `ClockCap`, `SandboxCaps`, `RootCaps`). However, `tc_try_report_capability_forgery` in `compiler/types/typeck.ax` currently checks `is_intlike` even when `is_explicit_cast == false`, causing ordinary non-address integer expressions and untyped integer literals (`TY_INT_VAR`, `i32`, `u32`, etc., such as `Point.sum(10)`) to hijack `AX_TYPE_MISMATCH` on regular call/binding/return type mismatches.

Repro before fix (in an isolated snapshot):
```
python tools/axtest.py --compiler build/axiomc2.exe --build-dir build --no-cache -v ui/method/inherent_methods_err.ax
```

## Scope
- Update `tc_try_report_capability_forgery` in `compiler/types/typeck.ax`:
  - Keep `src_kind_code = 1u8` (`raw_ptr`) for `sk == TY_PTR` (`*const T`, `*mut T`) on both explicit casts and implicit coercions.
  - Keep `src_kind_code = 2u8` (`integer_addr`) on **both** explicit casts (`is_explicit_cast == true`) and implicit coercions (`is_explicit_cast == false`) for pointer-sized integer address types (`sk == TY_USIZE || sk == TY_ISIZE`) and address wrapper structs (`PhysAddr`, `VirtAddr`, `WasmAddr` via `sec_is_raw_addr_struct_name`).
  - For non-address integer primitives (`i8..i128`, `u8..u128` other than `usize`/`isize`) and untyped integer literals (`TY_INT_VAR`):
    - When `is_explicit_cast == true` (e.g. `10 as view<Point>`, `0u64 as mut_view<u8>`, `1i32 as FsCap`), still set `src_kind_code = 2u8` and emit `AX_SEC_CAPABILITY_FORGERY`.
    - When `is_explicit_cast == false` (implicit coercion in calls, method receivers like `Point.sum(10)`, `let` bindings, block tail expressions, and `return`), return `false` so standard type checking reports `AX_TYPE_MISMATCH`.
- Leave `tests/ui/method/inherent_methods_err.ax` untouched (it must pass as written).
- Add regression UI test(s) under `tests/ui/security_profiles/` covering both sides of the boundary:
  - Implicit coercions of untyped integer literals (`10`) and non-address integers (`10i32`, `0u64`, `1u8`) to `view<T>`, `mut_view<T>`, and `FsCap` (in method calls, function calls, `let` bindings, block tails, and `return`) emit `AX_TYPE_MISMATCH`.
  - Explicit casts (`10 as view<T>`, `10i32 as mut_view<T>`, `0u64 as FsCap`) and implicit coercions of `usize`, `isize`, `*const T`, `*mut T`, `PhysAddr`, `VirtAddr`, `WasmAddr` to `view<T>`, `mut_view<T>`, and `*Cap` continue to emit `AX_SEC_CAPABILITY_FORGERY`.
- Keep the stage-2/stage-3 fixed point; selfhost bundles are regenerated by `taskctl snapshot`/`accept` (never edit or list generated bundles).
