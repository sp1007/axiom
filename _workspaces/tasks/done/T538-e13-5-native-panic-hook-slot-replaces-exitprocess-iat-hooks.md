# T538 — Explicit panic path for native containment

## Goal
Today a panic on a fiber or a spawned thread is contained natively by patching the `ExitProcess` IAT entry of the EXE and
treating `ExitProcess(101)` on that thread as a panic (`_workspaces/reports/T423b-report.md`, `T423b-qa.md`):
1. A user `ExitProcess(101)` / `exit(101)` inside a fiber or thread is contained as if it were a panic (verified by QA:
   the program continued and exited 0).
2. The hook state lives in the EXE's import lookup table (bit 63 trick) and in descriptor 0 — fragile against any linker change
   (merged ILT/IAT, bound or delay-load imports).

Decision (architect, triage-1122): give panics their own path. The linker provides a writable pointer-sized data symbol
`__ax_panic_hook` (initially 0) next to the `axiom_panic` stub. `axiom_panic` writes the message, then, if the slot is non-zero,
calls the hook on the panicking thread (Win64 ABI, no arguments or the message slice — engineer's choice, documented); if the
hook returns (or no hook is registered) it calls `ExitProcess(101)` exactly as today. `std/sys/windows/fiber.ax` and
`thread.ax` register one shared containment routine through a process-wide `static mut` (T537) and decide per thread
(fiber running → switch to the resumer with `Panicked`; spawned thread → end the thread with the join error; otherwise
return). `ExitProcess` is no longer hooked, so every other exit code — including a user 101 — passes through untouched.

## Scope
- `compiler/link/import.ax`: `__ax_panic_hook` in the EXE and DLL runtime stubs and in the `--kind obj` runtime object
  (SPEC-26 INV-WLIB-003: gcc/ld cross-link still works); `axiom_panic` calls it when set. Keep the stub sizes/offsets tables
  and their comments consistent.
- Accessing `__ax_panic_hook` from Axiom: an `extern` data declaration if supported, else a tiny host-provided setter;
  document the choice in the report.
- std: replace the IAT/ILT patching in `fiber.ax` and `thread.ax` by the registered hook; delete `ILT_HOOKED_FLAG`,
  descriptor-0 stash and their helpers.
- Tests: the existing `tests/std/fiber/native_panic/*` and thread panic tests keep passing unchanged; new
  `tests/std/fiber/native_panic/exit101_passthrough.ax` and `tests/std/thread/native_panic_hook/` (user `ExitProcess(101)`
  inside a fiber / spawned thread ends the process with 101; panic still contained); `tests/run/panic_hook_slot/` (no
  fiber/thread: panic exits 101 with the message, exact `stderr-contains`).
- Keep the stage-2/stage-3 fixed point; selfhost bundles are regenerated by `taskctl snapshot`/`accept` (do not edit or list them).
