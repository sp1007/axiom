# T543 — Remove the two latent uninitialised reads that T502's UB-04 detector exposed

## Why
`_workspaces/reports/triage-2026-11-26-T502-regression.md`. Since T502 (HEAD e085e8e6) the oracle reports
`AX_UNSAFE_INTERP_UB: read of uninitialized memory` (UB-04, SPEC-50 AXS-UNS-014) in two tests that passed at
fb368ce. The detector is right in both cases (verified by patching a copy and rerunning: both pass). T502's acceptance
forbids weakening the detector; the reads are fixed at their source.

1. `run/opt_lto/opt_lto_engine.test` (oracle part A, `--interp` of the assembled LTO probe) stops in
   `compiler/opt/inline/mod.ax:2607`:
   `let mut ast = unsafe { *(arena_alloc_raw(mut_view(*arena), size_of<MirStmt>(), align_of<MirStmt>()) as *mut MirStmt) };`
   This is a typed load of a whole `MirStmt` from arena bytes that were never written; the following
   `mir_stmt_reset` only overwrites the copy. Natively it "works" because `HeapAlloc(HEAP_ZERO_MEMORY)` backs the arena
   with zero bytes; the language gives no such guarantee (`heap_alloc` returns uninitialised memory).
   The same pattern occurs at 26 sites (`grep -rn "unsafe { \*(arena_alloc_raw(" compiler/`):
   `compiler/opt/escape/mod.ax` 9 (8 `MirStmt`, 1 `MemOptStats` at ~7453), `compiler/opt/inline/mod.ax` 5,
   `compiler/opt/ipa/mod.ax` 3, `compiler/opt/sroa/mod.ax` 9. With all 26 replaced by a zero-initialised value the
   probe prints all nine `PROBE_LTO_*=OK` lines (triage experiment).
2. `selfhost/opt/qa_opt_pipeline.ax [interp]` stops in `interner_intern_bytes` at `*(mids0 + slot)`. The interner is
   correct; the harness `tests/selfhost/opt/harness_opt_pipeline.ax.in` (~line 383) replaces the session interner's
   hash map with `arena_alloc_raw(perm_arena, smap_cap * 4, 4) as *mut u32` and never zeroes it, while the interner's
   probe loop treats slot id `0u32` as "empty". With the 1024 slots zeroed the bundle prints `OK opt pipeline`
   (triage experiment). Six other probe templates copy the same block (`smap_ids` without zeroing, listed in `paths:`);
   they do not fail today only because they are not reached under `--interp` the same way, so fix them too.

## Scope
1. In `compiler/opt/{inline,escape,ipa,sroa}/mod.ax` replace every typed load of fresh arena/heap memory by a value that
   is initialised before it is read. Preferred: a struct literal or one shared constructor (e.g. `mir_stmt_new(kind,
   span) -> MirStmt` in `compiler/mir/mir.ax`, built from `mir_stmt_zero`'s field list) and, for `MemOptStats`, its
   zero literal. Each site must keep its exact behaviour (the arena allocation there is dead: the statement is copied
   into the block by `mir_bb_push_stmt`; drop it). Also check multi-line forms (`*(arena_alloc_raw(` / `*(heap_alloc(`
   split over lines) in all of `compiler/` and fix any further site of the same kind; list each in the report.
   A site outside `paths:`/`locks:` is not patched: report it and `STATUS: BLOCKED` (the architect extends the locks).
2. In the seven harness templates zero the installed interner map before it is used (`map_ids[i] = 0u32` for all
   `smap_cap` slots; zeroing `map_hashes` is optional). Do not change `compiler/kernel/interner.ax`.
   The generated bundle (`tests/selfhost/opt/qa_opt_pipeline.ax`) is regenerated by the harness (`taskctl snapshot` /
   `accept`); do not edit or list it.
3. Guard test `tests/run/unsafe/oracle_ub_compiler_sites/` (a `.test` with a small python `cmd:` or equivalent): fails
   when `compiler/**/*.ax` contains a dereference of a direct `arena_alloc_raw(` / `heap_alloc(` call result
   (`\*\(\s*(arena_alloc_raw|heap_alloc)\(`), so the pattern cannot come back. Print the offending `file:line` on failure.
4. Remove the two lines admitted on 2026-11-26 for this task from `_workspaces/baseline-failures.txt` in the same change.
