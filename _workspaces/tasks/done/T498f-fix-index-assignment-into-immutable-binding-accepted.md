# T498f — Index assignment respects binding mutability; operand spans

## Goal
1. Mutability hole (found by the architect in triage-1122 while reproducing T498b-qa follow-up 1): bindings are immutable unless
   the pattern says `mut` (SPEC-02 AXS-GRM-041), and `s.n = 5` on an immutable `let s` is rejected with `AX_TYPE_ASSIGN_IMMUTABLE`,
   but a write through an index is accepted and executed:
   ```
   struct H { n: u32 }
   fn mk() -> H { H { n: 1u32 } }
   fn main() -> i32 {
       let hs: [2]H = [mk(), mk()]
       hs[0].n = 5u32          // accepted today, prints 5
       let a: [2]u32 = [1u32, 2u32]
       a[0] = 9u32             // accepted today, prints 9
       print_int(hs[0].n as i64)
       print_int(a[0] as i64)
       0
   }
   ```
   Root cause: the place walk in the assignment check of `compiler/types/typeck.ax` (the `HIR_EXPR_FIELD` / `UNOP_DEREF` /
   `HIR_EXPR_TUPLE_INDEX` loop before `AX_TYPE_ASSIGN_IMMUTABLE`) stops at `HIR_EXPR_INDEX`, so the base binding is never checked.
2. Diagnostic span (T498b-report follow-up 1, reproduced): `let u = 1u32 + hs[i].n;` after `hs` was moved reports
   `AX_MOVE_USE_AFTER_MOVE` at column of `1u32` (the start of the binary expression) instead of at `hs[i].n`: the MIR operands of a
   binary rvalue carry the expression span, not the operand span (`compiler/mir/builder.ax`).

## Scope
- typeck: walk through `HIR_EXPR_INDEX` (and range sub-slices used as a place) the same way as fields: an index on a local array
  continues to the base binding (immutable → `AX_TYPE_ASSIGN_IMMUTABLE`); an index whose base auto-derefs a view follows
  AXS-SEM-047 (any `view` level → `AX_TYPE_ASSIGN_IMMUTABLE`, all `mut_view` → OK); a raw-pointer deref keeps today's rule.
  Applies to `=`, every compound assignment `op=`, and taking `mut_view(a[i])` of an immutable binding (check what is reported
  today; keep `AX_CAP_CONFLICT_MUT` where SPEC-03 already says so). The deferred form `let a: [2]u32` followed by `a[0] = 1` is
  rejected too (a deferred binding is initialised only by a whole assignment).
- Before changing typeck, grep `compiler/`, `std/` and `tests/` for index writes into immutable bindings; fix any source that
  relied on the hole (the architect's heuristic scan found none) and list them in the report.
- builder: give each operand of a binary/unary/compare rvalue (and call arguments if they share the problem) its own expression
  span so the own checker points at the moved operand.
- Tests: `tests/ui/assign_immutable_index/*.ax` (exact code + line:col: element, field of element, nested `a[i][j]`, compound,
  through `view<[N]T>` (SEM-T23) and `mut_view<view<[N]T>>`, deferred `let`), plus positive run cases inside the same directory
  only if they are compile-pass ui tests; `tests/ui/own_operand_span/*.ax` (moved operand on the right and on the left of `+`,
  in a comparison, as a call argument).
- Keep the stage-2/stage-3 fixed point; selfhost bundles are regenerated by `taskctl snapshot`/`accept` (do not edit or list them).
