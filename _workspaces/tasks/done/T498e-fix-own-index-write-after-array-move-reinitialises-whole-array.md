# T498e — An indexed write never re-initialises a moved array

## Goal
Ownership soundness hole (pre-existing; `_workspaces/reports/T498b-qa.md` follow-up 1, reproduced by the architect in triage-1122
with the current compiler): after the whole array is moved, a write through an index is accepted and marks the whole array
`OWNED` again, so the remaining elements (moved away) can be read:

```
struct H { n: u32 }
fn mk() -> H { H { n: 1u32 } }
fn main() -> i32 {
    let mut hs: [2]H = [mk(), mk()]
    let t = hs
    hs[0].n = 5u32      // accepted today; must be AX_MOVE_USE_AFTER_MOVE
    let u = hs[1].n     // reads a moved element
    print_int(u as i64)
    0
}
```

`hs[0] = mk()` after the move behaves the same. The rule is SPEC-10 AXS-OWN-006 (clarified in triage-1122): a write through an
index never re-initialises anything and requires the array place to be definitely `OWNED`; only a whole assignment
`hs = [...]` re-initialises.

## Scope
- `compiler/own/init.ax`: for an assignment destination whose place goes through `MIR_PROJ_INDEX` (before any deref), check the
  array node like a read (`own_check_use`: moved/maybe-moved/partial → `AX_MOVE_USE_AFTER_MOVE` with the "moved here" note;
  uninit → `AX_INIT_USE_UNINIT`) and do not mark any node initialised. Covers `a[i] = v`, `a[i].f = v`, `a[i][j] = v`,
  `a[i] op= v`, arrays held in a struct field (`w.hs[0].n = 5` after `w.hs` or `w` was moved) and the branch/loop join cases
  (maybe-moved). Writes through a `mut_view`/raw-pointer deref keep their current handling.
- Whole assignment `hs = [...]` after a move, field re-initialisation of a non-indexed struct (`s.n = 5` then read `s.n` OK, read
  `s.m` still rejected — AOWN-37) and the T498b positive cases (re-init after `take(hs[0])`, Copy-field reads through an index)
  keep working.
- Remove the dead `resolve_place` from `compiler/own/move.ax` and its re-export in `compiler/own/mod.ax` (no caller since T498b;
  verify with a repo-wide grep that only regenerated selfhost bundles mention it).
- Tests: `tests/ui/own_index_moved/*.ax` (exact `//~ ERROR` code and line:col for every form above, incl. maybe-moved after a
  branch and in a loop); `tests/run/own_index_moved/*.ax` (interp/native/native-O1, exact `stdout:`) for the still-valid forms.
  Use `let mut` bindings (index assignment into an immutable binding is a separate bug, T498f).
- Keep the stage-2/stage-3 fixed point; selfhost bundles are regenerated by `taskctl snapshot`/`accept` (do not edit or list them).
  If the compiler sources themselves write through an index of a moved array, fix the source and report it.
