# T498c — the oracle must pass aggregates of any size by value

## Goal
The oracle carries by-value call arguments in an `InterpValue` whose payload is `vals: [32]u64` (256 bytes,
`compiler/interp/value.ax`), so a larger argument is cut off: `fn f(a: [300]u8)` sees only the first 256 bytes, and a
`[1024]u8` passed by value sums to 256 instead of 1024 (FU-T498-INTERP-ARG256, `_workspaces/reports/T498-report.md` follow-up 2).
Native code is correct. The oracle is the semantic reference (differential tests), so it must not be the one that is wrong.

## Scope
- Find every path where an aggregate crosses a value boundary through `InterpValue` (call arguments, return values, by-value `self`,
  closure captures, `Option`/`Result`/enum payloads, tuple/struct construction) and make sizes above the inline capacity work —
  for example spill to an allocation in the interpreter heap and copy byte-exact, keeping the inline fast path for small values.
  Do not just enlarge the array (memory and speed of the selfhost interp runs). Values above a hard cap, if any, report an
  interpreter limit diagnostic instead of truncating.
- Tests `tests/run/interp_big_args/*.ax` (interp/native/native-O1, exact `// stdout:`): by-value `[257]u8`, `[300]u8`, `[1024]u8`,
  `[4096]u8` argument (sum and last element), a large struct returned by value, a large by-value `self` method, a large tuple in an
  enum payload, a large closure capture; the 256-byte boundary (`[256]u8`, `[255]u8`).
- Keep the stage-2/stage-3 fixed point and the interp speed of `tests/selfhost` (report before/after timing of one selfhost group);
  selfhost bundles are regenerated by `taskctl snapshot`/`accept` (do not edit or list them).

## Acceptance
