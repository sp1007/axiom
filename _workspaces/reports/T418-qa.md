## Implementation Audit
- **Deterministic Lifecycle Events (`REQ-ASY-059, REQ-ASY-060`)**:
  - `compiler/interp/oracle.ax`, `compiler/interp/interp.ax`, `compiler/interp/value.ax`, and `std/future/mod.ax` correctly track and emit `POLL`, `SUSPEND`, `RESUME`, `WAKE`, `COMPLETE`, and `CANCEL_DROP`.
  - Event sequences follow deterministic execution order across both single-step and multi-step async tasks.
- **Panic on Poll After Completion or Cancellation (`REQ-ASY-034, REQ-ASY-052`)**:
  - Polling a completed (`0xFFFFFFFFu32`) or cancelled/panicked (`0xFFFFFFFEu32`) state machine deterministically aborts with exit code 101 and stderr message `polling a completed Future state machine`.
  - Lowering in `compiler/mir/async_lower.ax` generates a dedicated `bb_invalid` assertion block (`MIR_TERM_ASSERT`) catching invalid dispatch targets.
- **Active-State Cancellation Drop Order (`REQ-ASY-034, REQ-ASY-052`)**:
  - Coroutine drop elaboration in `compiler/mir/drop.ax` correctly emits destructor chaining in reverse declaration order for the active state variant only.
  - Inactive branch state variables are never touched or double-dropped.
- **Zero-Heap Stack Futures (`REQ-ASY-016, REQ-ASY-021, REQ-ASY-046`)**:
  - Future state machines are unboxed value types with statically known size and alignment, requiring zero dynamic heap allocation when allocated on the stack.
- **Async Layout Inspection (`REQ-ASY-045, AXS-ASY-051`)**:
  - `inspect --emit=async-layout` implemented via `compiler/driver/opts.ax`, `compiler/driver/pipeline.ax`, and `compiler/mir/async_lower.ax` accurately outputs state counts, byte sizes, alignments, and live field offsets with `needs_drop` attributes for each suspension point.
