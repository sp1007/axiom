### 5. Soundness probes (adversarial; scratch generator, not committed: 639 programs x interp/native/native-O1 = 1917 runs on the new compiler)
Values u128: 0, 7, 8, 2^63, 2^32+1, 2^64, 2^64+1, 2^64+7, 2^64+8, 2^127, 2^127+2, u128::MAX; i128: 0, 7, 8, -1, MIN, MAX, -(2^64)+1, -2^64,
-(2^63), 2^63, 2^64, 2^64+1, 2^64+7. Forms: array view read `(*a)[i]`, slice `s[i]`, local array write `v[k] = x`, compound `v[k] += x`,
`mut_view<[i32]>` write, nested `m[k][2]`, `m[2][k]`, `m[j][k]`, struct-field array write, literal index (const-fold path), `type Idx = u128`
alias, generic struct field, fn-returned array, ascending/descending loops, empty slice. Expected: in-bounds -> exact value / exact aliased-element
state; out-of-bounds -> exit 101 + `index out of bounds`.
Ranges: `s[lo..hi]` over 9x9 u128 and 8x8 i128 boundary values, `s[lo..]`, `s[..hi]`, `s[..=hi]`, `s[lo..=hi]`, mixed bound widths
(u128/i128 with i32, u8, usize, i64, u64, i128, negative i64) in both operand orders.
Result: every case passes in all three modes EXCEPT the `..=` forms (24 runs), see Follow-up 1 — that is pre-existing and identical with the HEAD
compiler (I built a HEAD compiler from `git archive HEAD` for A/B comparison). Mutation/A-B proof that the probes are live: the HEAD compiler fails
the same probes in interp, native and native-O1 (e.g. `s[0..2^64+2]` yields `2:10,20` instead of trapping).
BCE adversary (`if (i as usize) < 8 { (*a)[i] }` with i = 2^64+3, native-O1) traps correctly: the 128-bit assert is not eliminated by the truncated guard.
Vec-like std paths: std `Vec`/`ByteBuf`/arena have no index operator (`impl Index` does not exist; std indexes through pointer arithmetic / usize
methods), so no std path indexes with a 128-bit type; nothing further to check there.

### Follow-ups (for the architect)
1. PRE-EXISTING bug, independent of T496 (reproduces with the HEAD compiler and with `usize` bounds): inclusive range slicing ignores the `=`.
   `let s: view<[i32]> = view(a); let t = s[0..=2]; len(t)` prints 2 (expected 3), in interp and native; `s[..=hi]` likewise. When it is fixed,
   the `hi + 1` for a 128-bit bound must be done without overflow (`s[0..=u128::MAX]` must trap `index out of bounds`, not wrap), so the
   fix task should reuse the T496 `mb_emit_range_bounds_check` path. Also worth a spec/req check whether `..=` slicing is meant to be supported.
2. Harness: `build_axiomc.py` after a manual gcc configure yields a Debug stage-0 that overflows the stack building stage 1 (Section 2).
3. Spec text cleanup in N2.
