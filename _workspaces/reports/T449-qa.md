### Findings (3)

1. **FINDING-1 — `@lang("spawn_blocking")` is not recognized in `typeck.ax`, silently allowing escaping stack views and missing spawn-capture diagnostics (soundness bug)**
   - **Location**: `compiler/types/typeck.ax:10094-10141` (`tc_item_spawn_attr_kind`).
   - **Expected**: Functions and methods marked `@lang("spawn_blocking")` (claimed in `T449-report.md` line 5 and implemented in `compiler/own/unsafe.ax:2345` via `conc_sv_is_spawn_blocking`) must be classified as unscoped spawn boundaries (`1u8`) in `typeck.ax` as well, rejecting escaping stack `view<T>` with `AX_CONC_ESCAPING_VIEW` and `!Send` captures with `AX_CONC_CAPTURE_NOT_SEND`.
   - **Actual**: `tc_item_spawn_attr_kind` only checks `sv_is_spawn_name(...)` (`spawn` / `spawn_local` / `spawn_scoped`) and omits `sv_is_spawn_blocking_name(...)` (even though `sv_is_spawn_blocking_name` is defined immediately above at line 10084). As a result, `classify_spawn_call` returns `0u8`, `scan_spawn_boundaries_expr` skips `verify_closure_at_boundary`, and escaping stack views in `@lang("spawn_blocking")` closures compile with **0 errors** (while `!Send` captures only trigger a generic `AX_CONC_NOT_SEND` from `check_all_bounds` when the fn happens to spell `+ Send`, or nothing otherwise).
   - **Repro**: `tests/ui/concurrency/spawn_contract/qa_spawn_contract_adversarial.ax` lines 64, 68, 75, 79:
     `missing diagnostics: ERROR AX_CONC_CAPTURE_NOT_SEND at line 64; ERROR AX_CONC_ESCAPING_VIEW at line 68; ERROR AX_CONC_CAPTURE_NOT_SEND at line 75; ERROR AX_CONC_ESCAPING_VIEW at line 79 | unexpected diagnostics: ERROR AX_CONC_NOT_SEND at line 64; ERROR AX_CONC_NOT_SEND at line 75`.
   - **Fix**: Check `sv_is_spawn_blocking_name(...)` returning `1u8` in `tc_item_spawn_attr_kind` (matching `conc_item_spawn_attr_kind` in `compiler/own/unsafe.ax:2345`).

2. **FINDING-2 — User-defined `struct Executor` / `Builder` / `LocalExecutor` in a non-`std` module falsely triggers spawn checks**
   - **Location**: `compiler/types/typeck.ax:10143-10218` (`tc_receiver_spawn_method_kind`) and `compiler/own/unsafe.ax:2470-2494` (`conc_classify_spawn_call`).
   - **Expected**: A user-defined struct in `module main` (e.g., `struct Executor { pub tag: i32 }`) whose method is merely named `spawn` (without `@lang("spawn")` and outside `std.*`) must NOT be treated as a std spawn boundary.
   - **Actual**: Both `tc_receiver_spawn_method_kind` and `conc_classify_spawn_call` match purely on the unqualified struct name (`"Executor"`, `"Builder"`, `"LocalExecutor"`) without checking `(*sdef).module_path` — even though `HirItem.module_path` is populated for every item and `tc_item_is_prelude_or_std` already exists at `compiler/types/typeck.ax:12325`, and zero existing tests define `Executor`, `Builder`, or `LocalExecutor` outside `module std.*` (only `Scope` appears in 3 legacy `tests/ui/concurrency/data_race/*` files).
   - **Repro**: `tests/ui/concurrency/spawn_contract/qa_spawn_contract_adversarial.ax` line 85:
     `ex.spawn(view(x), id_ptr(raw))` on user `module main` `struct Executor` fails with `unexpected diagnostics: ERROR AX_CONC_NOT_SEND at line 85`.
   - **Fix**: Gate the `Executor` / `Builder` / `LocalExecutor` receiver fallback in both `compiler/types/typeck.ax` and `compiler/own/unsafe.ax` on `(*sdef).module_path` starting with `"std"` (matching `tc_item_is_prelude_or_std`), leaving `Scope` compatible with the 3 unchanged `tests/ui/concurrency/data_race/*` stubs.

3. **FINDING-3 — User-defined 1-arg generic free function `fn spawn<T: MyTag>(x: T)` in a non-`std` module falsely triggers spawn checks**
   - **Location**: `compiler/types/typeck.ax:10243-10280` (`tc_def_is_free_spawn_fn`) and `compiler/own/unsafe.ax:2399-2451` (`conc_def_is_free_spawn_fn`).
   - **Expected**: A user free function in `module main` merely named `spawn` with an unrelated generic bound (`fn spawn<T: MyTag>(x: T) -> i32`, no `@lang("spawn")`, not in `std.thread`) must NOT be classified as an unscoped thread spawn boundary. (`T449-report.md` line 5 also inaccurately states free `spawn` is recognized through `std.thread`'s module path, whereas the implementation never checks `module_path`.)
   - **Actual**: Both `tc_def_is_free_spawn_fn` and `conc_def_is_free_spawn_fn` match any 1-arg generic function named `spawn` whose generic param has *any* bound (or `where` clause), regardless of module path or whether the bound is `FnOnce`.
   - **Repro**: `tests/ui/concurrency/spawn_contract/qa_spawn_contract_adversarial.ax` line 89:
     `spawn(ns3)` calling `module main`'s `fn spawn<T: MyTag>(x: T)` fails with `unexpected diagnostics: ERROR AX_CONC_CAPTURE_NOT_SEND at line 89`.
   - **Fix**: Check `(*def).module_path` (`std.thread` / `std.*`) first; if retaining a non-`std` fallback solely for the unchanged legacy stubs in `tests/ui/concurrency/{spawn_capture,data_race,tls}/*`, require a `FnOnce` bound on the generic parameter (every legacy stub in `tests/ui/concurrency/` uses `F: FnOnce` / `F: FnOnce + Send` / `F: FnOnce<()>`), so ordinary user `fn spawn<T: MyTag>(x: T)` is never misclassified. Also update `T449-report.md` so its description matches the exact predicate implemented.
