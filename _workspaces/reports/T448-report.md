# T448 Report — Fix: explicit type arguments honoured (FU-H); inference from bounds and inside poll methods (FU-D, FU-5)

## Summary
The three repros from the T422/T421 reports now compile without annotations and print the expected values in
interp, native and native-O1. Most of FU-H (explicit `free_one<A>()` / `g.one<A>()` / return-only `collect<A>()`)
had already been fixed by T446 (`expr_substs` resolved through the mono substitution in `mir/builder.ax`); this
task confirmed it with tests and fixed the remaining cases.

### Root causes & fixes
1. **FU-D — bound output resolved in the callee's scope (`compiler/types/typeck.ax`,
   `check_future_bound_outputs_for_call`).** For `h<F2: Future<Output = T>, T>(fut: mut_view<F2>, ..)` called
   inside `fn outer<F: Future<Output = i64>>` (or inside `impl<F: Future<Output = i64>> Future for W<F>`), the
   type argument of `F2` is the caller's parameter `F`. The function switched `current_fn` to the callee *before*
   asking `resolve_future_output_ty(F)`, so `F`'s bound was looked up in the callee's generic list (finding the
   callee's own `Output = T`, a different `TY_PARAM`) → `AX_TYPE_MISMATCH`. Now every argument's `Future` output
   is resolved in the caller's context first, then the callee's bounds are read.
   Second half (generic impl caller): while the callee's bounds were read, `current_impl` was still the caller's
   generic impl, so the callee's parameters were numbered `impl_n + i` (T446 numbering) and did not match the
   callee-only `substs`. `current_impl` is cleared (and restored) while the bounds of a callee whose impl has no
   generics are read.
2. **FU-5 — method calls never checked `Future` bound outputs (`typeck.ax`, `check_expr_method_call`).** Free
   function calls ran `check_future_bound_outputs_for_call`, method calls did not. `self.exec.spawn(Child{..}, f)`
   only inferred `T` in `main` because later uses of the handle (`match h.join() { .. => v }`) constrained it;
   inside `poll` the handle is only `detach()`ed → `AX_TYPE_UNKNOWN`. The method path now runs the same check
   (for methods whose impl has no generic parameters, where `method_substs` indexes the callee's bounds directly —
   e.g. `Executor.spawn`, `LocalExecutor.spawn_local`).
3. **FU-H remainder — `T.tag()` (type parameter only in a bound) (`compiler/mir/builder.ax`).** A trait member
   without `self` called through a type name had no receiver operand, so `mb_scan_or_rewrite_calls` matched the
   first impl in scope (`tag_of<S24>()` returned `S1`'s value, interp and native). New
   `mb_static_trait_call_target`: when building the call, if the receiver is a type path, the member has no
   `self`, and the receiver type (after the mono substitution) is concrete, the call is bound to that type's impl
   member (`mb_impl_member_for`, the same lookup `mb_instantiate_default` uses for `Self.k()`).

### Ambiguity is still an error
A parameter that occurs in no argument, no bound binding and no annotation is not guessed: `free_one()` and
`g.collect()` (return-only `T`) report `AX_TYPE_UNKNOWN`; a bound-fixed `T = i64` used as `bool` reports
`AX_TYPE_MISMATCH` (tests below).

## Decisions
- The method-call bound check is limited to methods of impls without generic parameters. For a method of a generic
  impl, `method_substs` holds only the method's own arguments while a bound may mention impl parameters; doing it
  right needs the combined impl+method slice and a matching parameter numbering in
  `build_item_generic_param_args` (which numbers from 0). No repro needs it (all executor/group `spawn*` methods
  are on non-generic impls); recorded here as a known limit rather than guessed.
- `tests/std` files that still carry the old workaround annotations (`let h: TaskHandle<i64> = ...`) are outside
  this task's paths and were left unchanged (they stay valid); T422c (std convergence) can drop them.
