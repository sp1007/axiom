# Unblock T444 — layout through forward-referenced pointees / lang-item fields in std modules

## Tóm tắt
- **B1 (mono.ax):** sửa của T444 làm đồ thị kiểu có chu trình thật (đúng ngữ nghĩa), nên `subst_ty_self` /
  `subst_ty_adt` / `subst_ty_enum_or_closure` trong `compiler/traits/mono.ax` đệ quy vô hạn. Quyết định: chu trình là
  hợp lệ; mọi phép thay thế kiểu quyết định theo đối số kiểu và intern "vỏ" trước (ADR-0043 §1, INV-SEM-008). T444 được
  thêm `compiler/traits/mono.ax` vào `locks` (không task nào đang chạy giữ file này) và được gỡ chặn.
- **B2 (id ký hiệu):** cả axiom0 lẫn axiomc đánh số user/std/extern từ 1/10000/30000; bundle axiomc có > 30000 ký hiệu
  user nên id đã trùng nhau, chỉ còn ~12 ký hiệu trước khi stage 1 hỏng. Đây là bom hẹn giờ cho mọi task → tạo T164
  (AX0-FIX-10, priority 0, P10): một bộ đếm duy nhất, thuộc tính std/extern lưu theo ký hiệu, sửa đồng bộ axiom0 và bản
  port (kể cả `sym_is_std_item` trong `solver.ax` đang suy luận từ khoảng số). T444 phụ thuộc T164.
- Phát hiện phụ thành task: T444a (offset payload kích thước trộn — sai mã), T444b (hai binding báo move nhầm),
  T444c (build_axiomc dùng lại binary cũ theo mtime → gate có thể test compiler cũ; priority 11), T165 (điều tra
  axiomc1 segfault khi `run --interp`). T311 phụ thuộc T444a/b/c và T164.
- Rủi ro cần orchestrator lưu ý: T485 đang chạy và khoá `compiler/types/typeck.ax`, file đang chứa phần việc dở của
  T444 (chưa commit) trong cây chính.

## Blocker (from `_workspaces/reports/T444-report.md`)
- B1: the fix (on-demand, shell-first struct/enum registration in `typeck.ax`, cycle-safe `subst_type_with_vars` in
  `types.ax`) produces real cyclic type graphs; `mono.ax` substitution recurses forever (stack overflow on `check` of
  any program, stage 2 fails). File outside T444's `paths`/`locks`.
- B2: axiom0 `resolve.c` symbol-id ranges collide in the axiomc bundle; generic parameters landing on extern ids give
  `AX_TYPE_NOT_CALLABLE` at kernel32 externs in stage 1. T444 at shift 22 leaves 12 symbols of headroom.

## Decision
B1 — options: (a) reject cyclic types (contradicts SPEC-03, REQ-LAY-136); (b) visited-set guards in every walker
(fragile, does not give the instance its identity); (c) **chosen**: identity = def + args, substitution decided by
args, shell-first interning (ADR-0043 §1). Applied by widening T444: `locks` + `compiler/traits/mono.ax`; scope gains
the complete mono fix (the early return alone leaves `async_channel_pipeline.ax` overflowing); acceptance gains that
test and a stage 1-3 bootstrap. `mono.ax` is in T446's `paths` (todo, not running): T444 holds it as a lock, so the
scheduler serialises them. The whole-tree `tests/selfhost` lock is dropped (bundles are regenerated by the harness
since 2026-11-17).

B2 — options: (a) move std/extern bases far away (dense `symbol_nodes`/naming arrays would allocate gigabytes);
(b) separate extern table (user/std overlap and the range-based `sym_is_std_item` stay wrong); (c) **chosen**: one
counter for all symbols in both compilers, properties stored per symbol (ADR-0043 §2, INV-BOOT-005). Must precede
further growth of the compiler, so T164 has priority 0 (runs alone); T444 depends on it because its mono fix adds
more symbols ahead of `compiler.obj.writer`. Additional collision found while checking: axiom0 `driver/mono.c` and
the port's mono (`resolve_next_sym_v + 1`) allocate instance ids after the **user** counter only, i.e. inside the std
range once there are > 10000 user symbols — also fixed by the single counter. T164 is an `AX0-FIX` task per the
freeze rule (title `AX0-FIX-10`, phase P10-selfhost, paths limited to the resolver in both compilers).
