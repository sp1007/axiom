### Findings

No FAIL findings. Notes (pre-existing limits, not caused by T448; each reproduced on constructs T448 did not touch):

- N1 (follow-up for the architect): `T.tag()` where `T` is an **array type** impl target (`impl Tag for [4]u8`, `[8]u8`) still
  resolves to the first impl in scope (`mb_impl_member_for` -> `impl_matches_receiver` has no array match, so
  `mb_static_trait_call_target` returns null and the old fallback applies). Repro: `tag_of<[4]u8>()` prints 1, expected 7 (interp and native agree). Same as
  HEAD behaviour; scalar, pointer, tuple, struct and generic-struct impls all work.
- N2 (follow-up): inside a **closure body** in a generic function, `T` is not substituted by the monomorphisation: `fn c<T: Tag>() -> u64 { let f = || T.tag() + 1u64; f() }`
  gives 2 for `c<S4>()` (expected 5); the same for `|| size_of<T>() as u64` (8 instead of 24 for a 24-byte `T`), so it is independent of T448
  (pre-existing generic-closure issue). A closure that only captures a value computed outside works. The matrix test documents it
  and computes the value outside the closure.
- N3: the 2 SKIPs in the gate are in affected ids and pre-existing.
