# T423 report - E11.5 stackful Fiber runtime and cooperative context switching

## Summary
`std.fiber` (`Fiber<Y, R>`, `FiberState<Y, R>`, `FiberBuilder`, `FiberScheduler`, `yield_val`, `yield_now`) is
implemented on four new host intrinsics, `host.fiber_create / fiber_resume / fiber_yield / fiber_destroy`
(SPEC-34 AXS-EXEC-050..056). All eight run tests pass in the interpreter, native O0 and native O1 (WEAK-NATIVE 0);
a mutated expectation makes all three modes FAIL (evidence that the native stdout is really compared).

## Design
- **Host layer, native (`std/sys/windows/fiber.ax`)**: Win32 fibers (`ConvertThreadToFiberEx`, `CreateFiberEx`,
  `SwitchToFiber`, `DeleteFiber`). Win32 has no exported "current fiber" call (`GetCurrentFiber` / `GetFiberData` are
  TEB macros), so a per-thread table (`@thread_local`) holds the slots; a handle is `(generation << 32) | index`,
  which gives the required `-4` for a dead, foreign-thread or bogus handle and for resuming a running/finished fiber.
  The slot of the running fiber and the converted root fiber are also thread-local, so nested resume (fiber resumes
  fiber) and `yield` need no `GetCurrentFiber`.
- **Host layer, oracle (`compiler/interp/interp.ax`, `oracle.ax`)**: a fiber is one more record of the existing
  cooperative thread scheduler (`SchedThread`, `is_fiber`), parked in `SCHED_STATE_FIBER_IDLE`; the resumer is parked in
  `SCHED_STATE_BLOCKED_FIBER`. `resume` hands the CPU to exactly that record, `yield`/return hands it back and writes
  `*out_val` and the result code (0 yielded, 1 completed, 2 panicked). A fiber reports the owner thread's id
  (`thread_current_id`) and shares the owner's vector-clock id, so the race detector sees one thread and TLS is shared
  (AFIBER-39). `thread_join`/`thread_detach` reject fiber handles. A panic inside a fiber is contained (`Panicked`).
  Destroying a suspended fiber releases its frames without running Drop of its locals, which is what `DeleteFiber`
  does natively. Outside the scheduler (comptime) the four calls return -4 / -9.
- **Compiler plumbing**: `fiber_*` are `@lang("host_intrinsic")` like the thread intrinsics; typeck knows their names
  and signatures (kinds 9..12 in `tc_host_thread_intrinsic_kind` / `_sig_ok`), the LIR builder maps them to
  `__ax_host_fiber_*` (`is_host_thread_intrinsic_name`).
- **Library (`std/fiber/mod.ax`)**: the user closure is boxed; a generic trampoline `fiber_trampoline<F, R>` creates the
  host fiber, runs the closure on the fiber stack and stores the result. `yield_val<Y>` moves the value into a heap
  cell and yields the cell address (`i64`) through `host.fiber_yield`; `resume` takes the value over and frees the cell,
  so any `Y`/`R` crosses the `i64` host interface by move. `Fiber` is `!Send` and `!Share` and records
  `owner_thread`; resuming from another thread is rejected by the host (-4), and `resume` panics deterministically on -4.
  `Drop` destroys the host fiber (suspended fibers leak their live locals like Win32 `DeleteFiber`, a running fiber or
  a foreign thread panics) and frees the closure of a never-started fiber exactly once.
- **Self entry alias**: a generic trampoline cannot be used as a function value (T422a FU-J), so it passes itself as
  the fiber entry through a placeholder fn whose *name* the compiler rewrites to "the enclosing function"
  (`__ax_thread_self_entry` for std.thread). Two same-named placeholders in two modules break the rewrite (the wrong
  entry runs: `Completed` without a result, native access violation), so std.fiber uses `__ax_fiber_self_entry`
  and `interp.ax` (`is_self_entry_fn_item`) and `lir/builder.ax` (`is_fiber_self_entry_name`) accept both names.

## Deviations from SPEC-34 (the architect should fold them into the spec)
1. `FiberScheduler` keeps its ready queue in a raw heap array (`queue/len/cap`), not `Vec<Fiber<(), ()>>`: std.alloc.vec
   would add a module to every fiber bundle and its API is still free-function based. `run` resumes the fibers in FIFO
   rounds without moving them.
2. `FiberId` is `@derive(Copy)` plus `eq/clone/as_u64` methods (the derive list of the spec does not resolve in a
   bundle: only `Copy` is known). Ids are `(thread id << 32) | per-thread counter`.
3. `Fiber.new` / `Fiber.spawn` have no `F: FnOnce<R>` bound (compiler gap F3 below); `FiberBuilder.spawn<F: FnOnce<R>, Y, R>`
   has it. `Y` is inferred from the expected type (`let f: Fiber<i64, i64> = Fiber.new(...)`).
4. `host.fiber_resume`'s second parameter is named `resume_arg` (a parameter named `arg` shadows `host.arg`).
5. Extra pub fields `Fiber.owner_thread` and `Fiber.completed`, `FiberScheduler.pending()`.
6. Native panic containment is not implemented: a panic inside a native fiber ends the process (exit 101); only the
   oracle yields `FiberState.Panicked` (test `fiber_panic_contained`, interp only, see F1).

## Tests (`tests/std/fiber`, bundles generated by `gen_tests.py` from the live std sources, same scheme as tests/std/async)
All `// modes: interp native` unless noted; exact `stdout:`; failures print `FAIL line N`, not `assert`.
- `fiber_ping_pong`: three yields and a result; two fibers interleaved by the resumer; unique ids.
- `fiber_deep_stack`: suspension from depth 20 / depth 5 helper chains at the same time (sum of the depths proves every frame survives).
- `fiber_stack_sizes`: `FiberBuilder.stack_size(32768, 1048576)` and `stack_size(0, 0)` (default), recursion 150 and 100 deep with a yield per level.
- `fiber_scheduler_rr`: three fibers, FIFO round robin order `10 20 30 11 21 12`, scheduler reuse.
- `fiber_drop_cleanup`: locals dropped in reverse order at completion (`2 1`), a never-started fiber runs nothing, a fiber destroyed while suspended runs no Drop.
- `fiber_nested`: a fiber resumes a fiber and forwards its yields.
- `fiber_host_contract`: every -4/-9 rule of the four host calls, resume argument and yield value round trip, double destroy, running fiber cannot destroy/resume itself.
- `fiber_affinity`: thread id inside a fiber is the creator's; another OS thread gets -4 for resume and destroy; the fiber is unaffected.
- `fiber_panic_contained` (interp only, F1): `Panicked` for the panicking fiber, the other fiber unaffected.
- `check_fiber_bundles.test` (bundles match the live std), `compile_live_fiber.test` (live modules compile with the std root).
- `closure_generic_infer_xfail.ax`, `impl_generic_in_method_bound_xfail.ax`: minimal repros of F2 and F3 (`xfail: T423`).

## Follow-ups
- **F1** native panic containment for fibers (Win32): a panic on a fiber stack should return 2 from `fiber_resume`
  like the oracle; today the process exits with 101. Needs the exit hook of std/sys/windows/thread.ax to learn about fibers.
- **F2** compiler: a generic fn called without type arguments inside a closure body fails with `AX_TYPE_UNKNOWN`
  (`g(1i64)` inside `|| -> i64 {..}`; `g<i64>(1i64)` is accepted, and so is the same call in a plain fn). std.fiber users
  must write `yield_val<i64>(x)` in closures. Test `tests/std/fiber/closure_generic_infer_xfail.ax`.
- **F3** compiler: a method-level bound naming an impl-level generic (`impl<R> W<R> { fn mk<F: FnOnce<R>>(f: F) }`)
  reports `AX_NAME_UNRESOLVED` (also with a `where` clause). Test `tests/std/fiber/impl_generic_in_method_bound_xfail.ax`.
- **F4** compiler: two functions with the same name `__ax_thread_self_entry` in different modules make the fiber
  entry resolve to the wrong function (observed when std.thread is bundled before std.fiber). Root cause not
  isolated; worked around with the `__ax_fiber_self_entry` alias. A name-keyed lookup in resolve/mono is the suspect.
- **F5** `tools/build_axiomc.py`: a seeded bootstrap whose seed cannot type-check the new source (here the
  `host.fiber_*` declarations, unknown to the old typeck) fails hard (`bootstrap: FAIL seeded A`, no fallback to
  the full chain). This change needs one `python tools/build_axiomc.py --out <dir> --full-chain` (about 8 minutes) before
  seeded builds work again; the compiler cache then holds a seed that knows the intrinsics.
- **F6** spec: SPEC-34 §5 and the INDEX should record the deviations above.

## Round 1 (QA round 0 findings)
- **F1 fixed** (`std/fiber/mod.ax`): at both places that used `drop_in_place<F>` on the boxed closure (phase 2 of
  `fiber_trampoline` and the failure path of `spawn_raw_slot`) the closure is now moved into a local
  (`let _dead: F = *ptr;`) inside a block, so its captures are dropped, then the box is freed. This covers a dropped
  never-started `Fiber` and the fibers of a dropped `FiberScheduler`. `drop_in_place` on a closure type being a no-op
  is a compiler bug (architect task).
- **F2 fixed** (`std/sys/windows/fiber.ax`): native handles are `(owner thread id << 31) | (generation << 16) | (slot + 1)`
  (63 bits, positive). `lookup_slot` rejects a handle whose thread id is not the caller's, so a foreign-thread
  resume/destroy gets -4 even when the calling thread owns a slot with the same index; the slot `owner_tid` check stays.
  A thread can hold at most 65534 live fibers (create returns -9 beyond that), generation is 15 bits.
- **F3**: `fiber_panic_contained` now has `// modes: interp native` and `// native-after: T423b` (gen_tests.py `NATIVE_AFTER`
  replaces `INTERP_ONLY`); native mode is SKIP until T423b lands.
- **F4**: the two repro tests carry `// xfail: T423c` (`closure_generic_infer_xfail.ax`) and `// xfail: T423d`
  (`impl_generic_in_method_bound_xfail.ax`).
- **Edit of a QA test** (accepted by the coordinator): `tests/std/fiber/src/qa_fiber_drop.axsrc` lost three checks
  (original lines 57, 63, 84: `check(count == 2i64)` / `== 2i64` / `== 3i64` placed right after a `match f.resume()` whose
  arm binds a Guard payload). They assume the payload binding is dropped at the end of the match arm; the compiler
  drops it at the end of the enclosing block (also for a plain enum without any fiber), a compiler question tracked as
  T445a (ADR-0047). The checks after the enclosing blocks and the final log `1234576` remain, so every Guard is still
  proven to be dropped exactly once, in the right order. The bundle was regenerated.
- All QA-added tests and QA's `gen_tests.py` edits (`qa_*` entries, `EXPECT_EXIT`) are kept.
- Round 1 results (snapshot refreshed at HEAD 906440c, compiler sources unchanged since the round 0 build):
