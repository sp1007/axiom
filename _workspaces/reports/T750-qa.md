### Findings (Must Fix for PASS)

1. **`compiler/link/linker.ax:1838-1860` — Missing `<dir>/lib<name>.lib` candidate (and missing `else` guard on `has_arch_ext`) in `-l<name>` / `@link("<name>")` search order (`SPEC-26 AXS-WLIB-003` item 2)**
   - **Spec requirement:** `spec/SPEC-26-windows-artifact-kinds.md:52-57` (`AXS-WLIB-003` item 2) and `_workspaces/tasks/doing/T750-e18-7-static-libraries-coff-archive.md:29` mandate:
     - If `<name>` ends with `.lib` or `.a` (case-insensitive), probe `<dir>/<name>` for each `-L<dir>` in exact CLI order (and direct path `<name>` if relative/absolute).
     - Otherwise, for each `-L<dir>` in exact CLI order, probe:
       1. `<dir>/<name>.lib`
       2. `<dir>/lib<name>.lib`
       3. `<dir>/lib<name>.a`
   - **Defect:** `linker_resolve_library_in_dirs` (`compiler/link/linker.ax:1838-1860`) probes `<dir>/<name>.lib`, `<dir>/lib<name>.a`, and `<dir>/<name>.a`, completely omitting `<dir>/lib<name>.lib` (`p_pfx_lib, 3, lib_name, nlen, p_ext_lib, 4`). In addition, `if has_arch_ext` at `compiler/link/linker.ax:1843` has no `else`, so when `<name>` already carries `.lib` or `.a` (e.g. `-lfoo.lib`) and is not in `dir[0]`, `dir[0]` still spuriously probes `foo.lib.lib`, `libfoo.lib.a`, and `foo.lib.a` before advancing to `dir[1]`.
   - **Empirical reproducer:** Placing a valid COFF `.lib` archive at `<dir>/libqapfx.lib` and running `axiomc2.exe build -o pfx.exe -L <dir> -lqapfx consumer.ax` fails with exit code `1` (`error[AX_LINK_LIBRARY_NOT_FOUND]: library not found: qapfx`).
   - **Required fix:** When `has_arch_ext` is `true`, probe only `<dir>/<name>` in each `-L<dir>` (then direct `<name>` after the loop); in the `else` branch, probe `<dir>/<name>.lib`, `<dir>/lib<name>.lib`, `<dir>/lib<name>.a` (keeping `<dir>/<name>.a` last is compatible with `SPEC-89 AXS-ARTM-007`). Add regression coverage in `tests/link/lib/coff_lib_oracle.py` verifying `<dir>/lib<name>.lib` lookup and `<name>.lib` -> `lib<name>.lib` -> `lib<name>.a` precedence, and regenerate `tests/selfhost/link` + `tests/selfhost/obj_link_driver` bundles.

2. **`compiler/driver/pipeline.ax:2874-2876` — Source `@link("<archive>")` attributes are bypassed when no CLI `-L`, `-l`, or extra positional object/archive is supplied (`SPEC-26 AXS-WLIB-003` items 1–2)**
   - **Spec requirement:** `spec/SPEC-26-windows-artifact-kinds.md:51-58` (`AXS-WLIB-003` items 1–2) specifies `@link("<name>")` as a first-class library input channel and requires direct relative/absolute `.lib`/`.a` paths (e.g. `@link("qa1.lib")` or `@link("sub/qa1.lib")`) to resolve as COFF archives even when zero `-L` directories are passed (`linker_resolve_library_in_dirs` at `compiler/link/linker.ax:1861` already implements the `num_lib_dirs == 0` check for `has_arch_ext`).
   - **Defect:** `driver_execute_build_into_ctx` at `compiler/driver/pipeline.ax:2874` takes the `pe_link_objmodel_to_buf` fast path whenever `has_ax_sources && extra_input_count == 0 && dopts.lib_dir_count == 0 && dopts.lib_name_count == 0`, bypassing `pipe_collect_attr_libs` and `pe_link_obj_and_libs_to_buf` entirely.
   - **Empirical reproducer:** Compiling `@link("qa1.lib") extern "C" { fn mid_calc(x: i32) -> i32; }` via `axiomc2.exe build -o direct_attr.exe direct_attr.ax` (with `qa1.lib` in `cwd` and no `-L`/`-l` flags) emits a synthetic PE DLL import against `"qa1.lib"` instead of opening the static archive `qa1.lib`; running `direct_attr.exe` crashes immediately with `0xC0000135` (`STATUS_DLL_NOT_FOUND`).
   - **Required fix:** Collect `attr_lib_count` via `pipe_collect_attr_libs` before the fast-path branch at `compiler/driver/pipeline.ax:2874` and gate `pe_link_objmodel_to_buf` on `attr_lib_count == 0` as well. Add a regression test in `tests/link/lib/coff_lib_oracle.py` and regenerate `tests/selfhost/driver` + `tests/selfhost/obj_link_driver` bundles.

3. **`compiler/driver/opts.ax:1654-1661, 1866-1869` — `axiomc run --emit=obj` is not rejected with `AX_DRIVER_USAGE` (`SPEC-26 AXS-WLIB-002` items 1 & 4)**
   - **Spec requirement:** `spec/SPEC-26-windows-artifact-kinds.md:39, 46` (`AXS-WLIB-002` items 1 & 4) defines `--emit=obj` / `--emit obj` as exact aliases for `--kind obj` and requires rejecting non-`Executable` artifact kinds on `axiom run` with `AX_DRIVER_USAGE` (exit code `2`).
   - **Defect:** In `driver_parse_options` (`compiler/driver/opts.ax:1654-1660`), `--emit=obj` sets `dopts.emit_kind = EMIT_OBJ` and `dopts.artifact_kind = ARTIFACT_OBJ` without setting `dopts.has_explicit_kind = true`. In `driver_parse_cli` for `CMD_RUN` (`compiler/driver/opts.ax:1866`), the guard checks `if dopts.has_explicit_kind && dopts.artifact_kind != ARTIFACT_EXE`, which catches `run --kind obj|lib|dll` (exit code `2`) but allows `run --emit=obj` / `run --emit obj` through to semantic/interpreter execution (returning exit code `0` or `1` instead of `2` with `AX_DRIVER_USAGE`).
   - **Required fix:** Reject `dopts.emit_kind == EMIT_OBJ` (or `dopts.artifact_kind != ARTIFACT_EXE`) under `CMD_RUN` at `compiler/driver/opts.ax:1866` with `AX_DRIVER_USAGE` (exit code `2`), add regression coverage in `tests/link/lib/coff_lib_oracle.py`, and regenerate `tests/selfhost/driver` + `tests/selfhost/obj_link_driver` bundles.
