### Judgement of the two deviations

1. **Message names a type kind (`found bool`, `found tuple`, `found value`) instead of the exact type.** The Scope says `found <type>`, but
   the compiler has no type printer in this stage (grep for a type-name function in `compiler/`: none), and every acceptance
   criterion is about the code and the span, which are exact. Accepted as a documented minor deviation (note, not a FAIL). The word `value`
   (generic `T`, unresolved variable) is poor; follow-up: type printer for typeck diagnostics.
2. **No `f32`/`f64` variable test.** Float types and float literals report `AX_TYPE_UNSUPPORTED_IN_BOOTSTRAP` in this stage
   (E12.2), so a float-typed operand cannot be written. The float-literal forms `1.0f32`, `2.5f64`, `1.5` are covered and give exactly code 169.
   Accepted. Note (non-blocking): the check is on a *bare* float literal; `a[-1.5]` (unary minus on a float literal) still reports
   `AX_TYPE_UNSUPPORTED_IN_BOOTSTRAP` (observed: `a[-1.5]` -> UNSUPPORTED at 18:17), so "float-ish operand -> 2014" is only complete for
   bare literals. E12.2 must reuse `check_index_operand` for float-typed expressions of any shape (follow-up).
