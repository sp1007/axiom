## Audit findings
- **Unsafe context** (`own/unsafe.ax`): raw deref, raw ptr arithmetic, `address_of`/`address_of_mut`, `unsafe fn` calls, `extern` calls, `static mut` (via `AX_CONC_UNSYNC_STATIC`) all rejected outside `unsafe` and accepted inside `unsafe {}` / `unsafe fn`. Address introspection (`fn_addr`, `static_addr`, `addr_of`, `f as usize`) is safe as SPEC-50 AXS-UNS-002 says; the unsafe pass skips the direct path operand of those intrinsics only (so `static_addr(STATIC_MUT)` does not read the static).
- **`unsafe trait` / `unsafe impl`**: `AX_UNSAFE_UNNECESSARY_IMPL` is checked and tested. For a plain `impl` of an `unsafe trait`, the traits pass rejects it first with `AX_CONC_SAFE_SEND_SHARE_IMPL`, so `AX_UNSAFE_TRAIT_IMPL` is not what the user sees. The engineer's test documents this. The impl is still rejected (no soundness hole), but the code name differs from SPEC-50 AXS-UNS-005. Non-blocking; worth a follow-up.
- **REQ-OWNER-008 intrinsics** (`typeck.ax` / `builder.ax`): `fn_addr` accepts only `TY_FN` (closures rejected). `static_addr` accepts static items or block-scope placed bindings. `addr_of` needs a place (`AX_TYPE_NOT_A_PLACE` for temporaries). `fn as usize` is valid, `fn as u32` is `AX_TYPE_INVALID_CAST`. MIR lowering is a PtrToInt cast of the fn constant, or a shared `Ref` into a `*const T` temporary then PtrToInt.
- **`@addr` / `@at`**:
  - The parser hoists the address expression into a hidden `const __ax_addr_<n>: usize` (item scope) or `let __ax_addr_<n>: usize` (block scope). Typeck therefore checks `usize` and const-ness with the normal machinery.
  - Overlays lower to `*(addr as *mut T)` places.
  - Item-scope placed `static` with an initializer is rejected explicitly with `AX_TYPE_UNSUPPORTED_IN_BOOTSTRAP` and deferred to T526/T528. That is a visible deferral, not a silent workaround.
  - Missing `unsafe` on a placed item, or a block binding outside an unsafe context, gives `AX_UNSAFE_REQUIRED`.
- **Minor (non-blocking)**: a non-const item-scope `@at(runtime_value())` reports `AX_CONST_OVERFLOW`, which is the evaluator's generic code, not a dedicated "not const" code.
- **Diag codes**: the 5 new codes (211, 253–256) have unique name and message entries and no collision in `code.ax`.
- **Raw-pointer → view/mut_view**: views built in `unsafe` keep capability checking after the block ends. `AX_CAP_CONFLICT_MUT` and `AX_CAP_CONFLICT_READ` were confirmed for owner-derived and raw-pointer-derived capabilities, including conflicts between two separate `unsafe` blocks (QA test below).
- **Snapshot-only artifacts**: in the snapshot, taskgate's change set also lists 48 regenerated `tests/selfhost/**` bundles. These are copies of the changed compiler sources (for example the new diag consts) produced by the snapshot build. They are not modified in the main repo and are not part of T501's file list.

## QA adversarial tests (added)
1. `tests/mir/unsafe/qa_t501_parity_edge_cases.ax` (run, `interp native`, exact `// stdout:`). Checks interp == native -O0 == native -O1 for:
   - `address_of(v) as usize == addr_of(v) == address_of_mut(v) as usize`;
   - `address_of(STATIC) as usize == static_addr(STATIC)` and `addr_of(STATIC.b) == base + 4`;
   - write through a raw-pointer-derived `mut_view`, then read through a raw-pointer-derived `view` after leaving `unsafe` (99);
   - dynamic block-scope `@at(base)` `@repr(C)` struct overlay on a real static: field write/read gives 142, `static_addr`/`addr_of` round-trip, field offset +4;
   - `fn_addr(inc) == inc as usize == fn_addr(fp) == fp as usize != 0` for both a fn item and a fn pointer.
2. `tests/ui/unsafe/qa_t501_negative_edge_cases.ax`: `mut_view(*p)` and `address_of_mut(x)` outside `unsafe` give `AX_UNSAFE_REQUIRED`.
3. `tests/ui/unsafe/qa_t501_block_addr_negative.ax`: block-scope `@addr(1u32)` gives `AX_TYPE_MISMATCH`; `@at()` and `@at(a, b)` give `AX_ADDR_BAD_ARGS`.
4. `tests/ui/unsafe/qa_t501_raw_cap_conflict.ax`: raw-derived `view` then `mut_view` of the same `*p`, in separate `unsafe` blocks, gives `AX_CAP_CONFLICT_MUT`; the reverse order gives `AX_CAP_CONFLICT_READ`.

Note: my first attempt combined everything into one UI file. In that version the capability-conflict diagnostic did not appear, because diagnostics from the earlier pass stop the later capability pass in the same file. That is the pipeline's normal per-phase stop, not a bug, so the cases were split into separate files.
