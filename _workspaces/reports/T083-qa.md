### Findings

#### Finding 1 — `selfhost/interp_opt/qa_interp_opt_diff_comptime_a.ax [interp]` times out (>1200s) during the required gate suite run

- **Expected**: Running `python tools/axtest.py --compiler build/axiom0.exe selfhost/interp_opt selfhost/interp selfhost/opt interp opt comptime` inside `build-snap-T083/` must pass all 95 test runs within the 1200s timeout (`FAIL 0`).
- **Actual**: `selfhost/interp_opt/qa_interp_opt_diff_comptime_a.ax [interp]` fails with:
  ```
  TIMEOUT selfhost/interp_opt/qa_interp_opt_diff_comptime_a.ax [interp]: axiom0 run --interp did not finish within 1200s
  TOTAL 95 PASS 94 FAIL 1 SKIP 0 XFAIL 0
  ```
  Even when `selfhost/interp_opt` is run in isolation, `qa_interp_opt_diff_comptime_a.ax [interp]` takes `1067.1s` (compared to `68.9s` for `qa_interp_opt_unit.ax [interp]`, `154.1s` for `qa_interp_opt_diff_run_a.ax [interp]`, and `224.7s` for `qa_interp_opt_diff_mir_a.ax [interp]`).
- **Repro & Root Causes**:
  1. `COMPTIME_A_PATHS` (`tests/selfhost/interp_opt/gen_interp_opt_tests.py:424-427`) bundles both `tests/run/comptime/scalar_const.ax` (5 `const` items + 5-branch `main`, compiled and executed twice under `-O0` and `-O1` with `verify_each = true`) and `tests/ui/comptime/overflow_err.ax` (which runs a second full frontend + `typeck` + `mir_build_expr_body` + nested `InterpCtx` execution) into one `[interp]` process.
  2. In `compiler/interp_opt/session.ax:484-524` (`const_int_fits_type`), `TY_CHAR` is omitted, so `const E: char = 'Z';` in `scalar_const.ax` unnecessarily invokes `interp_eval_const_expr_into` (building expression MIR and spinning up a nested `InterpCtx` inside the interpreted compiler).
  3. Keep `COMPTIME_A_PATHS` lightweight (e.g. a single compact comptime case or lightweight `[interp, native, native-O1]` representative while placing the remaining fixtures in `qa_interp_opt_diff_comptime_b.ax`), and handle `TY_CHAR` literals without spawning `interp_eval_const_expr_into` so `qa_interp_opt_diff_comptime_a.ax [interp]` finishes in ~150-250s.

#### Finding 2 — `session_comptime_check_and_eval` skips `interp_eval_const_expr_into` whenever `typeck`'s unsigned pre-evaluator produces an in-range `CONST_INT`, causing wrong signed results and missed `AX_CONST_OVERFLOW` diagnostics
- **Location**: `compiler/interp_opt/session.ax:484-524`, `compiler/interp_opt/session.ax:625-635`
- **Expected**: `session_comptime_check_and_eval` must evaluate `const` initializers with Axiom's two's-complement signedness and checked-arithmetic rules (`REQ-OPT-387`, `SPEC-20 §4.7`): signed comparisons (`<`, `<=`, `>`, `>=`), signed division/remainder (`/`, `%`), and arithmetic right-shift (`>>`) must use signed operands, and any 64-bit or intermediate arithmetic/shift overflow must emit `AX_CONST_OVERFLOW`.
- **Actual**: During `session_typeck_into`, `compiler/types/typeck.ax`'s `eval_const_expr_int` (`typeck.ax:1228-1360`) pre-evaluates integer/boolean expressions using **unchecked unsigned 64-bit arithmetic** (`lv < rv`, `lv / rv`, `lv >> (rv & 63)`, wrapping `lv + rv`) and inserts `CONST_INT` into `thir.symbol_consts`. Then `session_comptime_check_and_eval` (`compiler/interp_opt/session.ax:625-635`) does:
  ```axiom
  let existing = sym_constmap_get(view(thir.symbol_consts), SymbolId { v: sym_v });
  if (existing as usize) != 0 && (unsafe { (*existing).kind }) == CONST_INT {
      let iv = unsafe { (*existing).int_val };
      if const_int_fits_type(view(*thir), (TypeId { v: expected_ty.v }), iv) {
          need_mir_eval = false;
      }
  }
  ```
  Because `const_int_fits_type` only checks whether the final 64-bit `iv` fits `expected_ty` (and returns `true` unconditionally for `TY_I64`, `TY_ISIZE`, `TY_U64`, `TY_USIZE`, and `val <= 1` for `TY_BOOL`), `session_comptime_check_and_eval` sets `need_mir_eval = false` and skips `interp_eval_const_expr_into` in all of the following cases:
  1. **Signed comparisons in `const`**: `const CMP: bool = -1 < 1;` is evaluated by `eval_const_expr_int` as unsigned `0xFFFFFFFFFFFFFFFFu64 < 1u64 == 0` (`false`). Since `0 <= 1` fits `TY_BOOL`, `need_mir_eval` becomes `false` and `CMP` evaluates to `false` instead of `true`.
  2. **Signed 64-bit division / remainder / right-shift in `const`**: `const D: i64 = -10i64 / 2i64;` is evaluated by `eval_const_expr_int` as unsigned `0xFFFFFFFFFFFFFFF6u64 / 2u64 == 9223372036854775803`. Since `const_int_fits_type` returns `true` for `TY_I64`, `need_mir_eval` becomes `false` and `D` evaluates to `9223372036854775803` instead of `-5`.
  3. **64-bit overflow and intermediate 32-bit overflow in `const`**:
     - `const OVF64: i64 = 9223372036854775807i64 + 1i64;`, `const OVF_U64: u64 = 18446744073709551615u64 + 1u64;`, and `const SHIFT_OVF: i32 = 1 << 32;` wrap/mask in `eval_const_expr_int` to values that satisfy `const_int_fits_type`, so `need_mir_eval = false` and `AX_CONST_OVERFLOW` is silently missed.
     - `const OVF_MID: i32 = (2147483647 + 1) - 1;` overflows `i32` on the inner addition, wraps in 64-bit arithmetic back to `2147483647` (which fits `TY_I32`), sets `need_mir_eval = false`, and silently misses `AX_CONST_OVERFLOW`.
- **Repro**:
  Run `session_typeck_into` + `session_comptime_check_and_eval` on any of:
  - `const CMP: bool = -1 < 1; fn main() -> i32 { if CMP { 0 } else { 1 } }` -> returns `1` instead of `0`.
  - `const D: i64 = -10i64 / 2i64; fn main() -> i32 { if D == -5i64 { 0 } else { 1 } }` -> returns `1` instead of `0`.
  - `const OVF64: i64 = 9223372036854775807i64 + 1i64; fn main() {}` -> `0` errors instead of `AX_CONST_OVERFLOW`.
  Only bypass MIR const evaluation (`need_mir_eval = false`) when `expr_ptr` is a simple literal (`HIR_EXPR_LITERAL` of `TOK_INT`, `TOK_CHAR`, `TOK_KW_TRUE`, `TOK_KW_FALSE`) or a `HIR_EXPR_PATH` to an already-validated `CONST_INT` (or a safe expression tree that has no signedness/overflow hazard).

#### Finding 3 — `session_comptime_check_and_eval` and `session_bind_mir_const_locals` mishandle `CONST_AGGREGATE` constants in chained `const` expressions, return places, and mutable local copies
- **Location**: `compiler/interp_opt/session.ax:637-655`, `compiler/interp_opt/session.ax:680-708`
- **Expected**:
  1. A `const` item whose initializer reads a field or element of an earlier aggregate `const` item (e.g. `const P: (i32, i32) = (10, 20); const SUM: i32 = P.0 + P.1;` or `const ARR: [3]i32 = [10, 20, 30]; const SUM: i32 = ARR[0] + ARR[2];`) must bind the temporary `CONST_AGGREGATE` local and evaluate `SUM` to `30` / `40`.
  2. Returning an aggregate `const` directly from a function (`fn get_p() -> (i32, i32) { P }`) or copying an aggregate `const` into a local variable and mutating a field (`let mut p = P; p.0 = 99; p.0 + P.0`) must not overwrite `_0` (`MIR_LOCAL_RETURN`) or `p` (`MIR_LOCAL_VAR`) into `MIR_LOCAL_CONST`.
- **Actual**:
  1. In `session_comptime_check_and_eval` (`compiler/interp_opt/session.ax:646`), `interp_eval_const_expr_into` builds a `MirBody` via `mir_build_expr_body` and immediately calls `exec_mir_body` without running `session_bind_mir_const_locals` on that `MirBody`. In `const P: (i32, i32) = (10, 20); const SUM: i32 = P.0 + P.1;`, the temporary local for `P` stays `MIR_LOCAL_TEMP` (`const_sym.v == 0`), `exec_assign_use` writes the symbol ID `P` as a scalar integer into the temporary, and `SUM` evaluates to `sym.v + 0` instead of `30` (or `0` for `const ARR: [3]i32 = [10, 20, 30]; const SUM: i32 = ARR[0] + ARR[2];`).
  2. In `session_bind_mir_const_locals` (`compiler/interp_opt/session.ax:685-703`), any `MIR_STMT_ASSIGN` of the form `_loc = use(const <sym>)` where `sym` is a `CONST_AGGREGATE` unconditionally rewrites `(*ldecl).kind = MIR_LOCAL_CONST` — even when `loc_v == 0` (`MIR_LOCAL_RETURN`, as in `fn get_p() -> (i32, i32) { P }`) or `(*ldecl).kind == MIR_LOCAL_VAR` (as in `let mut p = P; p.0 = 99;`). Because `exec_mir_body` (`compiler/interp/interp.ax:2038-2042`) skips all assignments whose `place.local` has `kind == MIR_LOCAL_CONST` and `frame_cleanup` (`compiler/interp/frame.ax:326`) reads `frm.local_ptrs[0]` directly:
     - `fn get_p() -> (i32, i32) { P }` skips the assignment to `_0` and returns `(0, 0)` instead of `(10, 20)`.
     - `let mut p = P; p.0 = 99;` skips both `p = P` and `p.0 = 99`, evaluating `p.0` to `10` instead of `99`.
- **Repro**:
  - Run `session_comptime_check_and_eval` + `session_run_interp` on:
    ```axiom
    const P: (i32, i32) = (10, 20);
    const SUM: i32 = P.0 + P.1;
    fn main() -> i32 { SUM }
    ```
    Returns `1` (the symbol ID of `P`) instead of `30`.
  - Run `session_comptime_check_and_eval` + `session_run_interp` on:
    ```axiom
    const P: (i32, i32) = (10, 20);
    fn get_p() -> (i32, i32) { P }
    fn main() -> i32 {
        let q = get_p();
        let mut r = P;
        r.0 = 99;
        q.0 + q.1 + r.0 + P.0
    }
    ```
    Returns `0 + 0 + 10 + 10 = 20` instead of `10 + 20 + 99 + 10 = 139`.
  - In `session.ax`, evaluate comptime expressions by calling `mir_build_expr_body` + `session_bind_mir_const_locals` before `exec_mir_body`, and in `session_bind_mir_const_locals`, when `_loc` is `MIR_LOCAL_RETURN` (`loc_v == 0`), `MIR_LOCAL_VAR`, or a local that is mutated/assigned more than once, allocate a fresh `MIR_LOCAL_CONST` local `_c` bound to `csym_v` and rewrite `(*st).rvalue.use_op` from `MIR_OP_CONST` to `MIR_OP_COPY` of `mir_local_place(_c)` so `exec_assign_use` copies the aggregate bytes from `_c` (`cval.agg_data`) into `_loc`!
