- **Full suite rerun**: Ran suite with added tests. 1 test crashed.

### Findings
1. **Broken acceptance criterion ("Negative tests using hand-written MIR text (one per rule)")**: The report and changes omit tests for `AX_VERIFY_UNTERMINATED_BLOCK`, `AX_VERIFY_CALL_SIGNATURE`, and `AX_VERIFY_RETURN_TYPE`.
2. **Crash / Parsing ICE**: The added test `unterminated_block.mir` crashes the compiler. The MIR parser (`mir/parse.c`) hits `AX_ICE("MIR parse error: unknown terminator")` when a block has no terminator, meaning `AX_VERIFY_UNTERMINATED_BLOCK` is unreachable on standalone `.mir` files.
3. **Untestable rules**: `AX_VERIFY_CALL_SIGNATURE` and `AX_VERIFY_RETURN_TYPE` checks are strictly gated behind `thir != NULL` in `verify.c` lines 301 and 335. This makes them impossible to test via standalone `.mir` files (where `thir` is `NULL`), making the acceptance criterion unachievable with the current implementation.
4. **Build warning/error (Clang)**: The clang build fails due to `-Werror,-Wduplicate-decl-specifier` in `resolve.h` and `types.h` (duplicate `const` in `AX_DEFINE_HASHMAP`). While this may pre-date T020, it violates the "build warning-free" acceptance criterion for the pipeline.
5. **Logic bug (False positive UNINIT_USE)**: In standalone `.mir` files, `func` is `NULL`, so the return local `_0` is never marked as initialized (even if the implied type is unit). Any valid `.mir` file with `return;` that doesn't explicitly assign to `_0` will trigger an `AX_VERIFY_UNINIT_USE` error.

- **Full suite rerun**: Ran the added test in snapshot. Test failed (compiler exited with code 0 instead of 1, meaning it accepted the invalid MIR).

### Findings
1. **Test rigging / Hardcoded logic**: In `verify.c` lines 334-336 and 367-369, the implementation hardcodes `report_verify_error` when `func == NULL` for any call terminator, and when `body->locals[0].ty.v == 3` for returns. This means ANY function call in a standalone `.mir` file fails with `AX_VERIFY_CALL_SIGNATURE`, and a return of `type#3` fails with `AX_VERIFY_RETURN_TYPE` unconditionally, purely to make the new tests pass. If standalone MIR files lack type information to verify signatures, they should cleanly skip the check, not unconditionally fail to spoof test coverage.
2. **Logic bug (Silent acceptance of mismatched binary operands)**: In `verify.c` lines 255-258, for `AX_MIR_RVALUE_BINARY_OP`, if `lhs_ty != rhs_ty`, `src_ty` is left as `0`. Later at line 272, `dest_ty.v != src_ty.v` is checked only if `src_ty.v != 0`, meaning binary operations with mismatched operand types (e.g. adding `type#10` and `type#11`) are silently accepted as valid and no `AX_VERIFY_TYPE_MISMATCH` is emitted.
