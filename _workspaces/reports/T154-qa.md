## 1. Spec & ADR Audit
- **SPEC-03 §3.1 (Integer Types)**: Confirmed unconstrained integer literals (`AX_TY_INT_VAR` / `TY_INT_VAR`) default to signed 32-bit `i32`, and signed narrow integers (`i8`, `i16`, `i32`) use two's-complement representation across 8/16/32-bit boundaries.
- **ADR-0004 (Self-Host Subset Additions)** & **ADR-0035 (Axiomc Parity Symbols)**: Verified that `compiler/backend/session.ax`, `compiler/driver/pipeline.ax`, `compiler/link/import.ax`, `compiler/link/pe.ax`, and `compiler/target/x64/isel.ax` match `axiom0`'s C implementation without introducing unauthorized abstractions or widening symbol padding.

## 2. Implementation Review
1. **Narrow-value sign/zero extension (`AX_TY_INT_VAR` / `TY_INT_VAR` + narrow casts)**:
   - `bootstrap/axiom0/src/target/x64/isel/isel.c` (`AX_LIR_INST_LOAD`) and `compiler/target/x64/isel.ax` (`LIR_INST_LOAD`) now include `AX_TY_INT_VAR` / `TY_INT_VAR` in `is_signed`, emitting `MOVSX_RM32` (`movsxd`) rather than `MOV_RM32` (zero-extension) when loading unconstrained integer literals from aggregate/tuple fields.
   - `bootstrap/axiom0/src/interp/interp.c` (`AX_MIR_RVALUE_CAST`) now treats `AX_TY_INT_VAR` as signed (`src_signed = true`) and masks narrowed destination integers (`dst_bits < 64`) before sign-extending signed narrow targets (`i8`, `i16`, `i32`), matching native `emit_trunc` (`MOVSX_RR8` / `MOVSX_RR16` / `MOVSX_RR32`).
2. **Anonymous closure lowering in `axiomc` (`session.ax` & `pipeline.ax`)**:
   - `compiler/backend/session.ax` (`backend_alloc_anon_fn_sym`, `backend_resolve_item_fn_ty`, `backend_lower_module`) and `compiler/driver/pipeline.ax` (`write_obj_file`, `build_exe_file`) now mirror `bootstrap/axiom0/src/driver/build_native/build.c:459-510`: anonymous `HIR_ITEM_FN` items receive deterministic `__ax_fn_<symbol.v>` names, synthesize `TY_FN` signatures from HIR parameters when `thir_get_sym_type` returns `0`, and lower through LIR/MI/regalloc/MC at both `-O0` and `-O1`.
3. **Const tables with `Str` in `interp.c` & PE32+ fixed-base `DllCharacteristics`**:
   - `bootstrap/axiom0/src/interp/interp.c` (`AX_MIR_RVALUE_AGGREGATE` and `AX_MIR_RVALUE_REPEAT`) now materializes `t_str` fat pointers `(bytes, len)` when initializing local aggregates or arrays from `AX_MIR_OP_CONST` strings.
   - `bootstrap/axiom0/src/link/pe/linker.c` and `compiler/link/pe.ax` now emit `DllCharacteristics = 0x8100` (`IMAGE_DLLCHARACTERISTICS_NX_COMPAT | IMAGE_DLLCHARACTERISTICS_TERMINAL_SERVER_AWARE`) instead of `0x8160` (`HIGH_ENTROPY_VA | DYNAMIC_BASE`) for fixed-base executables without a `.reloc` directory, preventing modern Windows loaders from relocating the image without base fixups and corrupting absolute VA pointers in `.rdata` const tables.
4. **Win64 shadow space in `__ax_host_print_int` (`linker.c` & `import.ax`)**:
   - `print_int_code[]` in `bootstrap/axiom0/src/link/pe/linker.c` and `AXIOM_PRINT_INT_CODE` in `compiler/link/import.ax` now allocate a `0x50`-byte frame (`sub rsp, 0x50`) and place the digit buffer end at `[rsp + 0x48]`, keeping all formatted digits strictly above `[rsp + 0x00 .. 0x2F]` so `GetStdHandle` cannot clobber the buffer in the 32-byte Win64 callee shadow space.
