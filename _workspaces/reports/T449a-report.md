# T449a Report — std/async stale bundles, timer_wheel_100_timers flake, missing waker import

## Summary
- **Missing waker import.** `std/async/timer.ax` and `std/async/timeout.ax` call the inherent method
  `Context.waker()` defined in `std/async/waker.ax` without importing that module. Both now import
  `std.asyn.waker.waker_leak`. That import only makes the method visible, so behaviour is unchanged.
  Regression test: `tests/std/async/reactor/timer_import_without_executor.ax` imports only `std.net`
  and has no executor. On HEAD it failed in interp, native and native-O1 with
  `AX_TYPE_UNKNOWN_FIELD` at `<std>/async/timer.ax:459:21` (`let w = cx.waker();`) and at
  `<std>/async/timeout.ax:128:25`. It passes in all 3 modes after the fix.
- **Deterministic `timer_wheel_100_timers`.** Root cause: the test assumed all 120 tasks register on the wheel
  within a 2 s wall-clock lead. Under `-j 2` load in MIR interp the ranks 0..k could fire before later tasks
  registered, so the order check read 0 (`stdout differs at byte 30`, observed `... 120 0 1 0`).
  The scenario is now `run_scenario(lead_ns)`. After spawning, it drives the executor by hand
  (`while exec.try_tick() {}`) until the ready queue is empty, so every task is polled once and parked on
  the wheel. It then checks that `active_count() == 120` and that no task has completed (`setup_ok`).
  If setup was disturbed (a stalled machine), the scenario is repeated with the lead doubled
  (1 s, 2 s, 4 s, 8 s, 16 s) and a hard FAIL line is printed if it never succeeds.
  The checked properties are unchanged and still compared exactly against stdout
  `OK timer_wheel_100_timers 120 1 1 0`: 120 timers, strictly ascending deadline order, same thread,
  0 remaining timers. The wheel and the 60 s drop-cancel check are unchanged. No timeout was raised.
- **Stale bundles.** After `std/async/executor.ax` started importing `std.asyn.reactor`, `std.asyn.timer`
  and `std.io`, the hand-written source lists in the 4 generators were both stale and incomplete. A plain
  regeneration produced bundles that did not compile (`AX_TYPE_MISMATCH` on `Result.Ok(string_new())`:
  `std.text.string` and `std.io` each define `String`/`string_new`). Fix, in generators only:
  - New `tests/std/async/structured/bundle_closure.py` derives the bundle's std import closure from the
    `use std.*` lines (longest dotted prefix that names a std `module`, `std.core.*` skipped, imports
    before importers, deterministic order). The source lists are now seeds.
  - `COMMON_PREREQS` is emptied. Nothing in the closure needs `std.text.string`, `std.thread`, `std.sys.*`
    or `std.thread.local`. The new closure for `waker_qa/qa_wake_during_poll.ax` is
    atomic, waker, task, io, time, timeout, timer, reactor, executor.
  - The 4 `gen_tests.py` files import the helper and regenerate; bundles were regenerated by the
    generators, not edited by hand. `--check` passes in all 4 directories.
  - `waker/cancel_self_waking` and `waker/join_waker_race` are heavy MIR-interp workloads (about 145 s
    alone against a 180 s step budget). With the larger closure the former timed out once at `-j 2`.
    Their per-test timeout in `waker/gen_tests.py` is raised 180 to 420. They have no wall-clock
    assertion, so this does not weaken what they check.
- `_workspaces/baseline-failures.txt`: the 5 T449a lines are removed.

## Design decisions (for the architect)
- Bundle closure derived from imports (not a longer hand list). A hand list had just gone stale for exactly this
  reason, and T449b (harness regeneration of std bundles) benefits from generators that cannot drift. The
  helper lives under `structured/` because that is where the path-owned directories already share
  generators; a different home would need a new `paths:` entry.
- A single shared `waker_leak` import is used to make the module (and its inherent `Context.waker`) visible,
  because the compiler has no `use module` form without an item.

     on HEAD and became stale because of my `timer.ax`/`timeout.ax` import lines, as predicted. Planned fix
     task is T428d.
   These generators concatenate a fixed source list; they can adopt `bundle_closure.py`
   (`from bundle_closure import bundle_sources`) or be regenerated if the lists still fit. Candidates for T449b
   (harness-side regeneration) as well. Please add the e11_5 / perf directories to a fix task if not covered.
2. `timer_wheel_100_timers` relies on `LocalExecutor.try_tick` plus reactor polling to park all tasks; if
   the executor ever stops parking on first poll the `setup_ok` guard will fail loudly instead of flaking.
3. `cancel_self_waking` takes about 145 s in the MIR interpreter when run alone; worth a performance look
   in the interpreter, no action taken here.
