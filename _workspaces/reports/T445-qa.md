### Findings

**F1 (FAIL) — guarded match arm on a mut_view place: double `Drop`, diagnostic lost.**
`compiler/mir/builder.ax` `mb_build_match_scrutinee` (new; used by match/if-let/while-let) now
matches a view-reached place in place, so the move checker no longer sees the binding moves.
A guarded arm binds the payload by move before evaluating the guard; when the guard fails the next
arm binds the same payload again.
```
fn guard_arm(self: mut_view<Self>, gn: Guard) {
    match self.guard {
        Option.Some(g) if g.id == 9u8 => { emit_digit(0u8); },
        Option.Some(g) => { emit_digit(5u8); self.guard = Option.Some(gn); },
        Option.None => {},
    }
}
```
- HEAD: `error[AX_MOVE_USE_AFTER_MOVE]` at the second arm (same as for a local scrutinee, which
  still errors with T445).
- T445: compiles; with guard id 1, interp and native both print `5 1 1` — the payload's `Drop`
  runs twice (expected at most once: `5 1`). This is exactly the "mutex guard released twice" class
  FU-4 was opened for.
- Regression test: `tests/ui/own_mut_view_receiver/qa_guard_arm_view_place_move.ax`
  (expects `AX_MOVE_USE_AFTER_MOVE`, as HEAD and the local-scrutinee case do). If the fix instead
  makes guard binding sound (bind after the guard / by reference in the guard) for both local and
  view scrutinees, replace it by a run test with the exact drop sequence and say so in the report.
- Minimal fix suggestion: keep the HEAD temporary path in `mb_build_match_scrutinee` when any arm
  of the match has a guard, or make the guard evaluate before the by-move bindings.

**F2 (FAIL) — FU-6 reborrow upgrades a shared `view<T>` receiver to `mut_view<T>` (unsound).**
`compiler/mir/builder.ax` (method-call receiver, new `else if` branch): `is_mut_ref` is taken from
the `self` parameter kind and the reborrow fires for a receiver of kind `TY_VIEW` too, so
`cx.bump()` with `cx: view<Ctx>` and `fn bump(self: mut_view<Self>)` builds `mut_view(*cx)` with no
diagnostic.
```
fn shared_only(cx: view<Ctx>) -> u8 { cx.bump() }
pub fn main() -> i32 {
    let c = Ctx { count: 40u8 };          // not even `let mut`
    let a = view(c); let b = view(c);
    shared_only(a); shared_only(b);
    c.count as i32
}
```
- HEAD: `error[AX_VERIFY_CALL_SIGNATURE]` (rejected, albeit late in the verifier).
- T445: `check` exits 0; interp exit 42, native exit 42 — an immutable owner mutated through two
  live shared views (SPEC-11 AXS-CAP-001/003).
- Regression test: `tests/ui/own_mut_view_receiver/qa_view_recv_mut_method.ax` expects
  `AX_TYPE_MISMATCH` (the code a free-function call `bumpf(cx)` with the same types gets). A
  different registered code is acceptable if justified in the report; "no error" is not.
- Fix: only reborrow when the receiver's view kind is at least as strong as `self`'s
  (`view` receiver -> `view` self only; `mut_view` receiver -> either).
