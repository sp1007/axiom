### 4. Boundary / adversarial test added by QA

`tests/std/async/structured/qa_nested_groups_races.ax` (source `src/qa_nested_groups_races.axsrc`, registered in `gen_tests.py`;
stdout `OK qa_nested_groups_races 0`): PASS 3/3 (interp, native, native-O1), WEAK-NATIVE 0, stable in the 4 repeats. Covers things the
engineer's tests do not:
- A. three-level group tree (root -> mid -> leaf via `with_cancellation`): `root.cancel_all()` (twice, idempotent) cancels the
  nested groups' tokens and the cooperative children at every level (leaf 3x5, mid 2x5), destructors balanced.
- B. failure propagates downward only: a panicking child of the inner group fails the inner group (`join_all` = `Panicked`),
  cancels its descendant group, and leaves the outer group/token un-cancelled and un-failed.
- C. deadline-vs-completion race: children already completed when an expired deadline (`at_ns(0)`) is set are still delivered
  (`Ok`, 2 results, sum 7: completion wins), while an unfinished child at an expired deadline yields `Cancelled` (no hang).
- D. quota exhaustion: `Tasks` hard limit 0 refuses the first child (usage stays 0, nothing live, refused task dropped);
  raising the limit to 1 admits one, the next is refused, collecting releases the unit.
- E. small generic outputs through `join_all<T>`: 1-byte `bool` and an 8-byte `Pair` struct (ordering and values preserved).
- F. `adopt` into a cancelled group is refused (`GroupError.Cancelled`) and the refused task is dropped by the executor.

### 5. Spec / deviation review (axiom-qa step 6)

Deviations declared by the implementer (report "Design decisions", FU-A..K), checked against the acceptance list and the task text:
- Non-generic `TaskGroup` / `Timeout`, `adopt(handle)` instead of `spawn(exec, fut)`: caused by documented compiler gaps (FU-B/C/E/F/G/H
  were reproduced by the implementer with `axiomc2`); every acceptance behaviour is still implemented and tested (join, cancel +
  destructors, token tree, deadline, governor). Not an acceptance-criterion drop. Recorded as follow-up for the architect: the
  public API should converge on the SPEC-34 shape (`TaskGroup<T>.spawn`, `Timeout<F>`) once FU-F/G/H are fixed.
- Panic containment is cooperative (`task_panic(cx)` + `group_poll_fn`): SPEC-34 AXS-EXEC-007 item 2 describes containment of a
  real task panic; `grep` for `catch_unwind|panic_hook|setjmp|unwind` over `std/` finds nothing, so the runtime has no mechanism
  to intercept a real `panic` and the task's paths (`std/async`) cannot provide one. The acceptance bullet "captures child task
  panics into `TaskResult::Panicked`" is met for panics reported through the task API and verified (`task_panic_contained`,
  `group_sibling_cancel`); a real-`panic` capture needs an architect decision / a compiler-runtime task (open item for the
  architect, see Follow-ups). Judged: not a FAIL of T422, the limitation is documented in the module header and the report.
- No `BOOTSTRAP-SHORTCUT`, no new diagnostics, no shared-file edit outside the lock (`std/async/mod.ax` is the declared lock).
- Mode check: all run tests are `modes: interp native` (native-O1 variants are added by the runner); no mode restriction, no
  `native-after`.
