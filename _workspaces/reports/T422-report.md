# T422 report

E11.5 -- structured concurrency (`TaskGroup`), cooperative cancellation (`CancellationSource` /
`CancellationToken`), deadlines, task panic containment and `ResourceGovernor` accounting in module
`std.asyn` (`std/async/`, module name `asyn` because `async` is a keyword).

## Summary

The change set is purely additive: four new library files (`std/async/{cancel,timeout,governor,group}.ax`),
re-exports appended to the lock file `std/async/mod.ax`, and a new test directory
`tests/std/async/structured/`. Nothing outside `paths`/`locks` was touched, so no `tests/selfhost` run is
needed by this change itself.

The language/compiler could not express the spec's generic API (`TaskGroup<T>`, `Timeout<F: Future>`) with
correct behaviour: **impl-level generics are not monomorphised** (details and minimal repros in
"Follow-ups"). Everything that depends on the real layout, drop glue or trait dispatch of a type parameter
is therefore written as free generic functions / method-level generics whose parameters are inferred from
value arguments, and the API deviates from the spec where a generic struct would have been wrong. Every
deviation is listed below.

### Semantics implemented (acceptance checklist)

- **TaskGroup joins before scope exit**: `join_all` waits for all children; `Drop` cancels what is still
  running and waits until every child future has been dropped (`group_drop_cancels`, `group_join_all`).
- **Sibling cancellation + Future destructors**: a child that reports a panic cancels the group
  `CancellationSource` (cooperative siblings finish via their token) and every other child task; all are
  awaited; destructor counters prove each future is dropped exactly once (`group_sibling_cancel`).
- **Token propagation across nested levels**: root -> child -> grandchild + sibling tree
  (`cancel_token_tree`), group with a parent token (`group_drop_cancels` section 5).
- **Deadline budgets**: `Deadline` arithmetic, `min` narrowing, real-clock expiry, nested deadlines, group
  deadline that only narrows (`deadline_timeout`, `group_deadline`).
- **Panic containment into `TaskResult.Panicked`**: `task_panic(cx)` + `group_poll_fn`
  (`task_panic_contained`, `group_sibling_cancel`, `group_generic_output`).
- **ResourceGovernor task limits**: hard/soft limits, pressure levels, hierarchy with rollback, leases, and
  a governed `TaskGroup` (`resource_governor_limits`, `group_governor_quota`).
- **Drop-vs-detach** (REQ-ASY-109): dropping an un-awaited handle cancels the task and drops the future;
  `detach()` lets it run; join/cancel semantics (`handle_drop_vs_detach`).

## Design decisions and spec deviations (for the architect)

1. **`TaskGroup` is not generic** (spec: `TaskGroup<T>`). Typed operations are method-level generics
   whose `T` is fixed by the caller (`join_all<T>`, `try_next<T>`, `next_blocking<T>`; `T` comes from the
   annotated result type). Using two different `T` on one group is undefined. Reason: FU-F/FU-G below.
2. **`adopt(handle)` instead of `spawn(exec, fut)`**: children are spawned with `exec.spawn(fut,
   group_poll_fn-based poll_fn)` and handed over with `group.adopt(handle)`. A wrapping `spawn` cannot be
   written: the concurrency checker rejects calls named `spawn` that take a `view` or a generic by-value
   argument (FU-E) and `T` cannot be inferred (FU-H). `adopt` refuses a handle when the group is
   cancelled/failed/timed out or the governor quota is full: the handle is dropped, which cancels the
   spawned task (spawn-then-refuse, quota is never charged for a refused task).
3. **`Timeout<F: Future>` is not generic.** `Timeout` / `LocalTimeout` wrap a spawned
   `TaskHandle<i64>` / `LocalTaskHandle<i64>` (the output type the handles are `Future` for) and cancel the
   task when the deadline passes; `poll_deadline<F, T>` is the generic building block for adapters over any
   future (used from concrete `Future` impls). There is no timer driver yet, so a pending deadline wait
   re-wakes itself on every poll (correct, not idle-free; E11.6/T426 should add a timer queue).
4. **Panic containment is cooperative.** The runtime has no unwinding or `catch_unwind`; a real `panic`
   inside a worker ends that worker thread (`win_exit_process_hook`) and in the oracle ends the process.
   `task_panic(cx)` marks the current task, `group_poll_fn` publishes it as `TASK_PANICKED`. Architect
   decision needed once real task-level unwinding exists (then `group_poll_fn` should install the catch).
5. **`group_poll_fn` replaces `tcb_poll_fn` for group children** (also usable for any task). It keeps
   the flag bits (cancel, detach) across the IDLE/NOTIFIED -> POLLING -> IDLE transitions (`tcb_poll_fn`'s
   `store(TASK_POLLING)` overwrites them, so a cancel requested while a task is queued or running can be
   lost) and re-queues a task that was cancelled while polling.
6. **`group_request_cancel` instead of `task_wake` for cancellation**: `task_wake` (T421, `waker.ax`)
   spins on a CAS and livelocks against a task that keeps waking itself under the MIR interpreter's
   deterministic round-robin scheduler (found with a `Looper` child; interp only, step-limit timeout).
   The new function is wait-free for non-idle tasks and relies on the poller to observe the flag.
7. **Resource accounting**: one `Tasks` unit is charged when a child is adopted and released when it is
   collected (`try_next`/`join_all`/`Drop`), not when it finishes. Pressure: `Exhausted` at the hard
   limit, `Critical` in the last tenth, `Warning` from the soft limit, else `Normal`.
8. **Uncollected outputs are not dropped**: a completed child whose result was never collected (group
   dropped) leaks its output's destructor, because the output type is unknown to `Drop for TaskGroup`
   (`TaskHandle` has the same limitation). `join_all` on failure does drop the collected outputs.
9. **`GroupResults<T>`**: the container is generic only in its pointer field; element access/drop are free
   generic functions (`results_get_ptr`, `results_drop_all`); `Drop` frees the storage only.
10. No `Arc`: cancel states and governors are own heap objects with atomic reference counts (`std.sync.arc`
    is not usable from `std.asyn` bundles yet, and its generic drop would hit FU-F). A child source is not
    unlinked from its parent when dropped (bounded by the parent's lifetime/cancel).
11. `FLAG_PANIC_REQUESTED = 0x400` is defined in `std.asyn.group` (the shared `waker.ax` is not mine).
12. `Executor` is not `Send`, so `group.spawn(exec, ...)` could not take it by value either; tests pass
    `view(exec)`/use the `Executor` directly.

## Follow-ups (compiler bugs found; each repro was verified with `axiomc2`)

- **FU-A parser**: `if other.deadline_ns < self.deadline_ns {` reports `AX_PARSE_EXPECTED_TOKEN: Expected
  '>'` (`field <` is read as generic arguments); bind both sides to locals as a workaround. Owner: frontend.
- **FU-B associated type with impl generics**: `impl<F: Future<Output = T>, T> Future for W<F, T> {
  type Output = Result<T, E>; ... }` gives `AX_NAME_UNRESOLVED` on `T` in `type Output`. Same for
  `impl<T> Future for GroupNext<T> { type Output = Option<TaskResult<T>>; }`. Owner: semantics (resolver).
- **FU-C `AX_TRAIT_OVERLAP`**: `impl<F> Future for W<F, i64>` and `impl<F> Future for W<F, ()>` are reported
  as overlapping (the check ignores the concrete type arguments). Owner: semantics (trait solver).
- **FU-D**: inside a generic function/impl with `F: Future<Output = i64>`, calling a generic helper
  `h<F, T>(fut: mut_view<F>, ..) -> Poll<Result<T, E>>` does not infer `T` from the bound
  (`AX_TYPE_MISMATCH`/`AX_TYPE_UNKNOWN`); works when `F` is concrete.
- **FU-E concurrency checker keyed on the callee name `spawn`**: any call spelled `spawn` is checked, and
  by-value arguments of generic type are reported as shared views (`AX_CONC_VIEW_NOT_SHARE`) unless the
  type is `Share`; `view` arguments give `AX_CONC_ESCAPING_VIEW`; a local of raw-pointer type passed
  through a call nested in the arguments gives `AX_CONC_VIEW_NOT_SHARE` (bind it first). Renaming the
  method (`spawn_child`) makes the diagnostics disappear for identical code, so the check is textual.
  Owner: semantics (own/unsafe checker, T402).
- **FU-F impl-level generics are erased**: in `impl<F> Wrap<F> { fn m(self: mut_view<Wrap<F>>) }`,
  field offsets behind a generic-typed field are computed with a placeholder size (8 bytes), fields are
  reordered, `size_of<F>()` is the placeholder and `needs_drop<F>()` is `false`.
  Repro: `struct Wrap<F> { a: u64, flag: u32, fut: F }`, construct with a 16-byte `F`, call a method that
  prints `self.a` and `self.flag` -> prints the wrong words (`a=5 flag=9` for `a=9, flag=7`).
  `@repr(C)` + the generic field LAST repairs field offsets, not `size_of`/`needs_drop`. Owner: semantics.
- **FU-G trait dispatch on an impl-level parameter**: in `impl<F: Future<Output = i64>> Future for W<F>`,
  `self.fut.poll(..)` is bound to the FIRST `Future` impl in scope, not to `F`'s (observed:
  `TaskHandle<i64>::poll` or an unrelated `Other::poll` executed); and a generic free function called from
  such a method is not instantiated natively (`AX_LINK_UNDEFINED_SYMBOL: show`). This is why T421 only has
  concrete-type futures. Owner: semantics (monomorphisation of impl methods).
- **FU-H explicit type arguments are ignored**: `free_one<A>()` evaluates `size_of<T>()` as 8 for a 24-byte
  `A` (interp) and a method called with explicit type arguments (`g.one<A>()`) is an undefined symbol
  natively. Type arguments are only honoured when inferred from value-argument types; a parameter that
  occurs only in the return type or in a bound (`join_all<T>() -> Result<GroupResults<T>, E>`) needs an
  annotated result (`let r: Result<GroupResults<i64>, _> = g.join_all();`). Owner: semantics.
- **FU-I (T421 files, not modified)** `std/async/waker.ax:task_wake` livelocks against a self-waking task
  under the oracle scheduler (see decision 6); `TaskHandle.cancel`/`Drop` use it. `tcb_poll_fn`'s
  `store(TASK_POLLING)` clobbers the cancel/detach flag bits (decision 5). The join-waker slot in
  `task.ax` (`task_set_join_waker` vs `task_wake_join_waker`) is a racy plain-field protocol; nothing in
  T422 depends on it: `Timeout`/`GroupNext` re-wake themselves instead of waiting for it.
- **FU-J** a generic function cannot be used as a function-pointer value (`let f: fn(..) = g<F>;` gives
  `AX_PARSE_CHAINED_COMPARISON`), so no generic poll function can be formed inside a generic method;
  callers must declare `fn poll_x(raw, cx) -> u32 { group_poll_fn<X, T>(raw as *mut TaskControlBlock<X, T>, cx) }`.
- **FU-K** the oracle drops buffered stdout when a run ends with the step-limit error (diagnosing a hang
  needed `--step-limit` plus extra instrumentation); minor.
