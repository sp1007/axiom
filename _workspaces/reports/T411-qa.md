### Findings

#### Finding 1: Struct Layout Defect in `std/sync/mutex.ax` & Test Divergence
- **Location**: `std/sync/mutex.ax:13-16` vs `tests/std/sync/arc_mutex_threads.ax:24-27`
- **Expected**:
  ```axiom
  @repr(C)
  pub struct Mutex<T> {
      pub state: Atomic<u32>,
      pub data: T,
  }
  ```
- **Actual**:
  In `std/sync/mutex.ax`:
  ```axiom
  @repr(C)
  pub struct Mutex<T> {
      pub data: T,
      pub state: Atomic<u32>,
  }
  ```
  However, in `tests/std/sync/arc_mutex_threads.ax`:
  ```axiom
  @repr(C)
  pub struct Mutex<T> {
      pub state: Atomic<u32>,
      pub data: T,
  }
  ```
- **Impact**: In `std/sync/mutex.ax`, `data: T` is placed before `state: Atomic<u32>`. When `Mutex<T>` is generic, `address_of(self.state)` calculates an invalid offset if `size_of<T>() != 8`. In the MIR interpreter oracle, evaluating `view(m).lock()` on a struct `T` crashes with:
  `error[AX_UNSAFE_INTERP_UB]: out-of-bounds pointer access` during CAS.
  In native execution, it corrupts the futex word or causes deadlocks on `futex_wait`. The developer's test inlined a modified copy of `Mutex<T>` with `state` first, masking this bug in the library file.

#### Finding 2: Generic Heap Under-Allocation in `std/sync/rc.ax`
- **Location**: `std/sync/rc.ax:45, 122, 165, 214`
- **Expected**:
  `let alloc_sz = if sz < 128 { 128 } else { sz };` (as correctly implemented in `std/sync/arc.ax:47` and `std/sync/once.ax:202`).
- **Actual**:
  `let alloc_sz = if sz == 0 { 1 } else { sz };`
- **Impact**: In generic `Rc<T>::new(val: T)`, `size_of<RcInner<T>>()` evaluates generic `T` as pointer-sized (8 bytes), yielding `sz = 24` bytes. For any `T` where `size_of<T>() > 8` (e.g. any 16-byte struct), `heap_alloc` allocates only 24 bytes instead of the needed 32+ bytes. Accessing fields of `T` past byte 24 in the interpreter immediately aborts with:
  `error[AX_UNSAFE_INTERP_UB]: out-of-bounds pointer access`.
  `rc_basic.ax` only tested with `i64` (8 bytes), failing to cover struct types.

#### Finding 3: Struct Layout Defect in `std/sync/rwlock.ax`
- **Location**: `std/sync/rwlock.ax:17-20`
- **Expected**:
  `pub state: Atomic<u32>` placed at offset 0 before `pub data: T`.
- **Actual**:
  `pub data: T` placed before `pub state: Atomic<u32>`.
- **Impact**: Same as Finding 1. Any `RwLock<T>` with non-8-byte `T` calculates the wrong offset for `self.state` in `read()` and `write()`.

#### Finding 4: In-Tree Tests Bypassed Library Source Files
- **Location**: `tests/std/sync/*.ax`
- **Impact**: Every test file under `tests/std/sync/` inlined full copies of the types and methods instead of importing them or compiling against `std/sync/*.ax`. This allowed divergences (such as the field reordering in `arc_mutex_threads.ax`) to go undetected by test suites.
