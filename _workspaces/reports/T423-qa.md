### Findings

**F1 (FAIL) - captured values of a never-started fiber are leaked (never dropped), also when the `FiberScheduler` is dropped before `run`.**
`std/fiber/mod.ax` phase 2 of `fiber_trampoline` and `Drop for Fiber` free the closure box after `drop_in_place<F>(c_ptr as *mut F)`; but `drop_in_place` on a closure type is a no-op in both the oracle and native code (probe: a closure capturing `Guard`, `needs_drop<F>()` is true, `drop_in_place<F>` prints no `drop guard`, while `let _moved: F = *p;` does drop it). Repro: `tests/std/fiber/qa_fiber_drop.ax` (line 43 of `src/qa_fiber_drop.axsrc`: `{ let g = Guard{..}; let _f: Fiber<(), i64> = Fiber.new(|| -> i64 { consume(g) }); }` -> expected Guard dropped once, actual 0; same for two closures in a dropped `FiberScheduler`, ids 4/5). Interp and native agree (final log `2 3 7 6`, expected `1 2 3 4 5 7 6`). The report claims "frees the closure of a never-started fiber exactly once" and the task goal asks for deterministic Drop; resources owned by the closure (lock guards, files, Box) silently leak. Not covered by the engineer's `fiber_drop_cleanup` (it only checks that the unstarted closure does not run). Fix: in phase 2 (and wherever `drop_in_place<F>` is used for the closure) move the value out into a local and let the scope drop it (`let _dead: F = *(c_ptr as *mut F);`), then free the box; open a compiler follow-up for `drop_in_place<closure>` being a no-op (see Follow-ups). Cases 2, 3, 5 of the same test (yielded Guard, returned Guard, reverse-order locals) pass the checks that precede the leak and agree in all modes once the leak offset is accounted for (`2 3 .. 7 6` logged).

**F2 (FAIL) - native `host.fiber_resume` / `fiber_destroy` accept a handle of another thread when the calling thread owns a fiber with the same slot index (violates SPEC-34 AXS-EXEC-054 "h belongs to a different OS thread -> -4"; interp/native disagree).**
`std/sys/windows/fiber.ax` handles are `(generation << 32) | slot_index` into a per-thread table, so thread A's first fiber and thread B's first fiber have the identical handle `4294967297`; `lookup_slot` then finds B's own slot (the `owner_tid` check is trivially true). Repro: `tests/std/fiber/qa_fiber_foreign_collision.ax` (`f.raw_handle` is a public field, the engineer's own affinity test passes it to another thread): the foreign thread, which owns a suspended fiber, calls `fiber_resume(h)`; native returns `1` (it resumed and finished the thread's own fiber, `RC=1 h=4294967297 own=4294967297`), the oracle returns `-4`. Consequences natively: resume(h) from the wrong thread runs the wrong fiber (the thread then panics on its next `own.resume()` -> `join` Err, `-1 -1` printed instead of `6005 6006`), and `fiber_destroy(h)` from the wrong thread `DeleteFiber`s the foreign thread's own suspended fiber. The engineer's `fiber_affinity` only passes because the foreign thread has no fibers. Fix: make native handles unique across threads (e.g. fold the owner thread id or a process-wide counter into the handle bits) and keep the owner check.

**F3 (FAIL, mode check) - `fiber_panic_contained.ax` is `// modes: interp` without an accepted reason.**
axiom-testing allows `modes: interp` only for "oracle-only check" (out-of-bounds/dangling pointer); the correct device for a missing native feature is `// native-after: <catch-up task>`. Here the host contract (AXS-EXEC-054: `fiber_resume` returns 2 for a panicked fiber, `FiberState.Panicked`) holds only in the oracle; natively a panic in a fiber exits the process with 101 (deviation 6 / F1 of the report), i.e. a documented but real interp/native divergence on a spec'd behaviour, and no open task exists for it. Required: the architect files the catch-up task (native panic containment, F1 of the report), the test then uses `// native-after: <that id>` instead of `modes: interp`, and the spec/INDEX records the divergence meanwhile.

**F4 (FAIL, xfail rule) - `closure_generic_infer_xfail.ax` and `impl_generic_in_method_bound_xfail.ax` use `// xfail: T423`.**
xfail is only for a spec gap that has an ADR and an *open* task, never for an implementation bug; these are compiler bugs (report F2, F3) and the named task is the task under gate, which is closed on accept (the XFAIL would then reference no open task). Required: the architect files fix tasks for the two compiler gaps and the tests name those ids (or are replaced by tracked follow-up tasks and removed).

Notes (not findings):
- Deviation 1 (raw heap queue instead of `Vec<Fiber>` in `FiberScheduler`): functionally verified (queue regrowth with 60 fibers, drop of a never-run scheduler releases every fiber's slot); acceptable, must be folded into the spec as the report asks. Deviations 2-5: harmless, spec text must be updated.
- "Magic self-entry name accepted under two names" (`__ax_fiber_self_entry` in `compiler/lir/builder.ax` and interp): works for a bundle with both std.thread and std.fiber (`fiber_affinity`, `qa_fiber_foreign_collision`), but the real cause (F4 of the report) is not isolated; file a compiler task so the rewrite is keyed by the enclosing module/function and not a name.
- Destroying a suspended fiber (Drop of an unfinished `Fiber`) leaks its live locals without running Drop (interp and native agree; SPEC-34 AXS-EXEC-051.2 allows the destroy, but `0204 s18` says a fiber is destroyed only when COMPLETED or after cancellation). The behaviour is documented in the report design section and covered by `fiber_drop_cleanup`; the architect should state it in SPEC-34 (or add cooperative cancellation) rather than leave it implicit.
- Native stack-overflow on a tiny fiber stack was not turned into a test (needs a trap check); not part of the acceptance list.
