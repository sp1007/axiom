### Adequacy of the suite against the acceptance criteria and the workarounds
The suite covers the task scope with live-std run tests: multi-task `AsyncFile` pipeline (concurrent positional writers/transformers, `read_exact`, EOF read, `close().await`), multi-connection TCP echo with per-connection tasks and half-close/EOF, length-prefixed framing over `split()` halves, UDP burst with boundaries and per-datagram acks, CancellationToken cancellation of in-flight TCP/UDP reads (zombie drain, late data intact), I/O timeout cancellation with sentinel-heap/stack buffer safety and a dropped in-flight file read, TaskGroup + async I/O with `cancel_all` (bundle), and timer-wheel/IOCP ordering. Each leg asserts exact output, so the native IOCP path is genuinely compared with the oracle.

Workarounds F1-F8 are not silent: they are described at the point of use inside the tests (comments cite the follow-up id), in the README section "Implementation limits the tests are written around", and in the report with minimal repros (F1 and F3 verified above). No test is xfail-tracked because no architect-filed fix task exists yet (ADR-0046 D1 requires an open task naming the file); the gaps are therefore recorded as follow-ups below, which is the permitted alternative. I judge this acceptable: the suite does not assert any behaviour that contradicts the spec, it only avoids constructs that currently violate it, and the avoided constructs are enumerated. It is NOT acceptable for the gaps to stay unfiled; the architect must create the fix tasks (see Follow-ups) and attach the direct-form regression tests (and xfail where appropriate).

Minor notes (not FAIL):
- N1. The task scope names "`Timeout` + `CancellationToken` cancellation of in-flight file/socket reads". Token cancellation is only exercised on TCP/UDP reads; a file read is covered only by "dropped right after submission" (the op is submitted eagerly by `read_buf_at`, so that is a real in-flight drop), not by a token/timeout race. `std.asyn.timeout.Timeout` itself is not used (F8); `with_io_timeout_ms` is. Acceptable given F8, but the architect should add a file-read token/timeout case when F5/F8 are fixed.
- N2. `timeout_reads_buffer_safety.ax` `late` check accepts both "data delivered intact" and "fresh read timed out" (comment explains: the aborted op may consume the datagram/bytes). This is weaker than `cancel_token_reads.ax`, which requires the late data to arrive intact; it still catches corruption but not data loss. Note only.
- N3. The `tcp_multi_client_echo` accept `gate` handshake serialises connect after each accept is posted (F2), so connection establishment is not truly simultaneous; the data phase is.
- N4. 3 WEAK-NATIVE entries appear in the smoke draw (not this task's tests), pre-existing.

### Follow-ups for the architect (QA does not create tasks)
1. F1 (high): address of an `async fn` local must be stable (or the oracle/native must keep frames pinned, or slice I/O must not capture raw local pointers) across `.await` — AXS-AIO-012 item 2. Regression: slice `read`/`recv_from`/`read_exact`/`write_all` into async-fn locals; both oracle UB and native wrong value reproduce (repro in the report).
2. F2 (high): oracle TCP listener needs a backlog (`aio_submit_connect`/`aio_submit_accept` single `pending_accept_op` slot); native queues, oracle drops -> hang/divergence. Regression: truly concurrent connects without the `gate`.
3. F3 (high): `TaskGroup.spawn` fails `AX_CONC_CAPTURE_NOT_SEND` against live `std.asyn.group` (group.ax:285); every existing TaskGroup test is a bundle, which hides it. Regression: live-std `taskgroup_async_io`.
4. F5 (high): an `.await`ed operand inside an `async fn` is not dropped on completion, so adapter-wrapped I/O futures are never cancelled in tasks. Regression: cancel/timeout races inside tasks, file-read token cancel (N1).
5. F4 (medium): reactor counters read unsynchronised (`in_flight_count`/`has_pending_work`) -> race detector with 2 workers. F6 (medium): multi-worker `Executor` turns the reactor only when idle. F8 (medium): `std.asyn.timeout.Timeout` around pending I/O blocks forever natively under `LocalExecutor.block_on`. F7 (low): native `AX_ASYNC_FUTURE_NOT_SEND` rejects `SocketAddr`/`SleepFuture` across `.await` while the oracle accepts (check divergence).
6. Each of the above, once filed, should name `tests/conformance/p11/e11_6_async_io/` (or a sibling dir) for the direct-form regression, optionally as `xfail: <task>` tests until fixed.
7. Pre-existing (not caused by T428): stale `check_*_bundles` freshness tests under `tests/std/async/*` and `tests/conformance/p11/e11_5_executors` (already on the baseline / T449a-T449b).
