### Findings

- **F1: wrong cross-reference in a normative rule.** `spec/diagnostics.md:121` (AXD-030) says:
  "A code `AX_<AREA>_*` is defined only in `codes/<AREA>.def` (archcheck rule, T006;
  INV-LAYER-008)."
  - Expected: `INV-LAYER-007`. invariants.md:144-149 is "Diagnostic codes registered in their area
    file".
  - Actual: `INV-LAYER-008`. invariants.md:151-156 is "Standard library is Axiom source", an
    unrelated rule that T006 must also implement.
  - Impact: T006 and T009 read AXD-030 to find the invariant and fixture they must deliver, so the
    reference points them at the wrong rule.
  - Repro: `grep -n "INV-LAYER-00[78]" spec/diagnostics.md spec/invariants.md`
- **F2: report states facts that are not true.**
  - `_workspaces/reports/T002-report.md` says "49 invariants". The file has 48 blocks: KERN 7,
    LAYER 8, DIAG 8, DET 4, PIPE 5, ORACLE 3, SEM 6, BOOT 4, LEX 2, GRM 1. Repro:
    `grep -c "^### INV-" spec/invariants.md` → 48.
  - The report also says "Every `verify` path was taken from the `paths:` of the named task". This is
    false for the 6 paths in check 7.
  - Fix: correct the count, and either change the claim to "the named task or one of its
    dependencies", or name the delivering task per path. The invariant file itself is valid under
    IG-3.
