### 8. Findings

No FAIL finding. Notes (not blocking, for the architect via the orchestrator):

- N1 (environment dependency). `tests/std/math/check_vectors.test` and `check_tables.test` run `make_vectors.py --check` /
  `gen_tables.py --check`, which `import mpmath` (a third-party package, present on this machine through sympy, not part of
  Python 3 standard library; the axiom-qa tooling principle is stdlib only). On a machine without mpmath both tests FAIL
  with an `ImportError`, and `skip-unless:` only knows PATH tools and compiler features, not Python modules. They are
  uncached (`cmd:` without `cache-inputs:`), so no cache-hygiene problem. Suggested: a `skip-unless: pymodule mpmath` form in
  the runner, or a stdlib-only freshness check (committed SHA-256 of the generated files).
- N2 (heavy twins). The 8 `stress_*` tests are `modes: native` with a `reason:` (heavy twin of the interp+native `vec_*`). The
  axiom-testing rule says the accepted reason is a heavy test of at least 100k elements; these have about 4 000 - 10 000 vector entries. They are
  heavy in time (the interpreter needs about 15 ms per call, native about 5 us) and each has a small interp+native twin, so the
  purpose of the rule (no lost interp coverage) is met, but the written threshold is not. Suggest amending the rule to a time-based
  criterion (estimated interpreter time above the test timeout).
- N3 (semantics outside the spec text, recorded by the engineer as D5 but not in "Spec deviations"):
  `rem_euclid(-1e-20, 3.0)` returns `3.0` (= |b|), whereas AXS-FLT-062 says `r in [0, |b|)`; this is Rust's behaviour and is
  documented in D5. `log(x, 1.0)` returns NaN (ln(x)/0 would be +-inf in IEEE division); not in the spec text. The architect
  should fix the spec text for both (a spec decision, not an implementation bug).
- N4 (pre-existing compiler problem, unrelated to std.math, found while generating probes). A native program with 330 chunk
  functions of 100 calls each (33 000 statements `pr(plain_f32(from_bits_f32(N)));`, `plain_f32(x) = x * 1.5 + 1.0`, no std.math
  call involved) builds but dies with `0xC0000005` at run time and loses its buffered stdout; programs of 6 600 statements
  (66 chunks) work. Repro generator: QA scratchpad `qa461/combo2.py 22 1500`. Not caused by T461; the architect may want a
  task for it.
- N5. Method calls on a float literal receiver (`1.0.exp()`) are rejected with `AX_TYPE_UNKNOWN_FIELD` (the lexer reads `1.0.exp`
  as a field access); variables work. Language issue, not in T461's scope.
- N6. Performance (reported by the engineer): about 5 us per call native, 15 ms interp. Confirmed by my probes (interp
  1700 checks of `qa_adversarial.ax` take 39 s). Acceptable for this task; a fast path is a follow-up.
