#### Root Cause Analysis (`bootstrap/axiom0/src/interp/host.h:56-58` and `bootstrap/axiom0/src/interp/interp.c:570, 601, 1422, 1426-1432`)
- In `bootstrap/axiom0/src/interp/host.h:56-58`, `AxInterpValue` is a fixed 64-byte buffer:
  ```c
  typedef struct {
      uint64_t vals[8];
  } AxInterpValue;
  ```
- In `bootstrap/axiom0/src/interp/interp.c:570`, `eval_call` passes `sizeof(AxInterpValue)` (64 bytes) as `out_ret_size` to `exec_mir_body`:
  ```c
  exec_mir_body(ctx, body, args_raw, arg_count, (uint8_t*)out_ret, sizeof(AxInterpValue));
  ```
  And at `interp.c:1426-1432` (`AX_MIR_TERM_CALL`), `exec_mir_body` allocates `AxInterpValue ret_val = {0};` (64 bytes on the C stack), calls `eval_call(..., &ret_val)`, and then copies `ax_type_size(dest_ty, &ctx->thir->interner)` bytes from `&ret_val` into `dest`:
  ```c
  TypeId dest_ty;
  uint8_t* dest = get_place_ptr(ctx, &frame, &term->call.destination, &dest_ty, NULL);
  memcpy(dest, &ret_val, ax_type_size(dest_ty, &ctx->thir->interner));
  ```
  (Similarly, at lines 601 and 1422, by-value call arguments larger than `sizeof(AxInterpValue)` overflow `call_args[cap_count + i]` and are truncated to `sizeof(AxInterpValue)` on callee entry.)
- In `qa_hash_set.ax`, `U32Set` (`AxRawSet`) has 10 × 8-byte fields = **80 bytes** (`index_cap` at offset 64, `index_used` at offset 72). In `qa_hash_map_growth.ax` and `qa_hash_map_order.ax`, `U32Map` (`AxRawMap`) has 11 × 8-byte fields = **88 bytes** (`index` at offset 64, `index_cap` at offset 72, `index_used` at offset 80).
- When `u32set_new()` / `u32map_new()` / `u32map_with_capacity()` returns an 80-byte or 88-byte struct by value, `exec_mir_body` copies only the first 64 bytes into `ret_val`, and `memcpy(dest, &ret_val, 80 /* or 88 */)` **reads 16 to 24 bytes past the end of `ret_val` on `exec_mir_body`'s C stack**.
- Because T134 modified `exec_mir_body` in `bootstrap/axiom0/src/interp/interp.c` (lines 813-856, 1047-1048, 1111-1112), the C stack frame layout of `exec_mir_body` under `gcc` places non-zero stack temporaries immediately after `ret_val`, corrupting `s.raw.index_cap` (offset 64) and `m.raw.index` / `m.raw.index_cap` (offsets 64–79) with C stack garbage upon return from `u32set_new()` / `u32map_new()`.
- **Required Fix:** In `bootstrap/axiom0/src/interp/host.h` and `bootstrap/axiom0/src/interp/interp.c` (both within T134's allowed `paths:`), either widen `AxInterpValue` (e.g. `uint64_t vals[32]` = 256 bytes, with a bounds check/assertion against `sizeof(AxInterpValue)` at `interp.c:601, 1422, 1432`) or pass an explicit byte buffer sized to `ax_type_size(dest_ty, ...)` for call returns and arguments.
