### Oracle strength assessment

Representative (good):
- Scalars: 64 signatures, arity 1..8 x 8 variants (all-int, all-float, alternating int/float from both sides, 4 pseudo-random mixes of `i8 u16 i32 u64 f32 f64 *const u8`), edge bit patterns (INT_MIN, -0.0, denormals, FLT_MAX, kernel-range pointers). That covers positional slots RCX/RDX/R8/R9 vs XMM0-3 at positions 1-4 (the "slot is positional" rule) and stack arguments 5-8, in both directions (Axiom -> gcc DLL and gcc DLL -> Axiom `extern "C"` callback), plus returns of all 7 types (including callbacks returning narrow `i8/u16` with garbage upper bits).
- Structs: 20 by-value `@repr(C)` structs, sizes 1,2,3,4,5,6,7,8x4,12x3,16x3,24x3: all power-of-two classes passed in a register (1/2/4/8, incl. `{f64}` and `{f32,f32}` which Windows passes in an integer register, not XMM), non-power-of-two sizes 3/5/6/7/12/24 and the 16-byte classes passed by reference, padded structs (`{u8,u32}`, `{u8,u32,u8}`, `{u8,f64,u16}`), as parameter, as return (hidden pointer shifting later args), as callback parameter, callback return, and in positions 2 and 5 between scalars (sm_/sm_cb_), which exercises the by-reference temp + stack-arg interplay.
- Layout: 32 structs (12 hand-built + all 20 ABI structs): padding, bool, usize, pointers, `[N]T` arrays, nested structs (incl. a nested struct with a u64), field offsets via address differences, size/align via `size_of`/`align_of`; gcc table cross-checked by an independent Python C-layout algorithm before use.
- The engineer compiles the DLL at gcc -O0 and -O2 and Axiom at -O0 and -O1, so register-assignment differences are exercised.

### Tests I added (main tree, under the task's paths)

`qa_abi_nonvolatile.py` builds, with `gcc -shared` (hard fail if gcc is missing), a DLL containing three `naked` asm functions: `nv_probe(cb, expected)` loads sentinels into RBX/RSI/RDI/R12-R15 and both halves of XMM6-XMM15, calls an Axiom `extern "C"` callback with 6 args (two on the stack, RSP aligned), and returns a bit mask of every non-volatile register that changed (+ bit 30 if the callback result is wrong); `nv_clobber`/`nv_clobber5` destroy all volatile registers and return the RSP misalignment seen at entry (and check args 1-5 incl. the stack slot at [rsp+40]). The Axiom callback keeps 10 `f64` and 7 `u64` values live across a call to `nv_clobber`; `main` also calls `nv_clobber5` and a recursive function that calls `nv_clobber` at every level. A positive control (`nv_probe_evil`: a callee that zeroes RBX and XMM7) must produce exactly mask `0x40101`. Result: `WIN64-NV-ORACLE PASS` at gcc -O0/-O2 x axiom -O0/-O1. Mutation: wrong expected callback result (`expected+1`) -> `FAIL nv_probe mask=1073741824` (bit 30), exit 1. This found no compiler defect.
