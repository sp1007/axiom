### 1. Code & ABI audit (`compiler/link/{import,linker}.ax`, `std/sys/windows/{fiber,thread}.ax`)
- **Complete removal of IAT/ILT patching & descriptor-0 stash:**
  - `grep -n "ILT_HOOKED_FLAG\|ExitProcess" std/sys/windows/fiber.ax std/sys/windows/thread.ax` (plus checks for `import_desc`, `VirtualProtect`, `orig_exit`) returns zero matches.
  - `std/sys/windows/thread.ax` now stores `WIN_THREAD_RT` in a process-wide `static mut` (T537) and registers `win_thread_panic_hook` once via `extern "C" { fn __ax_panic_hook_set(hook: usize) -> usize; }` only if the previous slot value is 0 (restoring any pre-existing hook).
  - `std/sys/windows/fiber.ax` registers `win_fiber_panic_hook` once per process (`FIBER_PANIC_HOOK_SET`), initializing the thread runtime first via `__ax_host_thread_current_id()` so the fiber hook (which contains running user fibers via `SwitchToFiber(caller_fiber)` and delegates non-fiber panics to `win_thread_panic_contain()`) is never overwritten by a later first thread spawn.
- **Machine-code stub & Win64 ABI verification (`compiler/link/import.ax`):**
  - `AXIOM_PANIC_HOOK_CODE` (96 bytes): `push rsi; push rbx; sub rsp, 0x48` aligns `RSP` to 16 bytes (`entry RSP = 16k+8`, `-16 - 0x48 = 16k - 80`) with 32-byte writable shadow space `[rsp..rsp+0x1f]` and `WriteFile` scratch at `[rsp+0x20]` / `[rsp+0x38]`. Saves `(msg_ptr, msg_len)` in non-volatile `(rbx, rsi)` across `GetStdHandle(-12)` (`REL32 @19`) and `WriteFile` (`REL32 @48`), loads `mov rax, [rip + __ax_panic_hook]` (`REL32 @55`), and when non-zero invokes `hook(msg_ptr, msg_len)` (`mov rcx, rbx; mov rdx, rsi; call rax`). If the hook returns (or slot is 0), falls through to `mov ecx, 101; call [rip + ExitProcess]` (`REL32 @79`). Verified live from C with naked assembly in `qa_two_modules_oracle.py` (checks `(rsp & 15) == 8`, scribbles all 32 bytes of shadow space, clobbers all volatile registers `rax/rcx/rdx/r8/r9/r10/r11`, verifies clean return into `ExitProcess(101)`).
  - `AXIOM_PANIC_HOOK_SET_CODE` (11 bytes): `mov rax, rcx; xchg [rip + __ax_panic_hook], rax; ret` (`REL32 @6`). `xchg` with memory has implicit `LOCK` semantics on x86-64, providing atomic exchange without extra imports.
  - `linker_emit_panic_hook_slot`: wired into all 4 finalize pipelines in `compiler/link/linker.ax` (`EXE`, `DLL`, `EXE v2`, `DLL v2`) after archive member extraction and DLL stub synthesis, and before `$`-relocation rewriting. Images that never reference `__ax_panic_hook_set` keep the exact 64-byte hook-free `AXIOM_PANIC_CODE` and gain no `.data` section, preserving byte-for-byte parity with `axiom0` goldens (`selfhost/link/qa_pe_headers_and_linker_diff.ax` PASS). `linker_is_own_panic_stub` ensures user-supplied `axiom_panic` overrides in input objects are never clobbered. All stub/setter/hook-address references are RIP-relative (`REL32` / `lea`), so DLL rebasing under ASLR requires no `.data` pointer fixups and leaks zero `panic_hook` symbols into PE import/export tables (`qa_two_modules.test` PASS).
  - `pe_build_runtime_coff_obj` (`--rt-obj`, SPEC-26 INV-WLIB-003): emits `axiom_start` (`0..86`, pad to `96`), hooked `axiom_panic` (`96..192`), `__ax_host_print` (`192..251`, pad to `256`), `__ax_host_print_int` (`256..375`, pad to `384`), `__ax_panic_hook_set` (`384..395`), and 8-aligned `.data` (`_tls_index` at `0..4`, `__ax_panic_hook` at `8..16`) with `AX_RELOC_X86_64_PC32` (`-4`) relocations at `96+55` and `384+6`. Verified by `objdump -d -r` (zero `(bad)`), `panic_hook_link.test`, `qa_two_modules.test`, and `link/dll/gnu_ld_run.test` (all 1,099 native run tests in `tests/run/` cross-linked with GNU `ld` against `axiom_rt.obj` + `axiom_host_rt.lib` PASS).

### 2. Behavioral verification & QA adversarial tests
- **User exit 101 vs panic containment:**
  - Fiber `ExitProcess(101)` (`tests/std/fiber/native_panic/exit101_passthrough.ax`): contained fiber panic prints `panicked`, subsequent `ExitProcess(101)` inside a fiber exits process with 101 (not contained).
  - Spawned-thread `ExitProcess(101)` (`tests/std/thread/native_panic_hook/nph_exit101_thread.ax`): contained thread panic joins `Err`, subsequent `ExitProcess(101)` on a spawned thread exits process with 101 (not contained).
  - Dual-mode `host.exit(101)` inside a fiber (`tests/run/panic_hook_slot/qa_std_exit101_passthrough.ax`, `modes: interp native`): after containing a thread panic, a fiber panic, and a second thread panic, `std.core.host.exit(101)` inside a fiber terminates the process with exit 101 in `interp`, `native`, and `native-O1`.
  - Fiber-on-spawned-thread `ExitProcess(101)` (`qa_exit101_fiber_on_thread.ax`): neither the fiber layer nor the thread layer intercepts `ExitProcess(101)`.
- **Additional QA seam & adversarial tests (`tests/run/panic_hook_slot/`):**
  - `qa_user_hook_reentrant.ax`: custom hook without std thread/fiber runtime verifies `(msg_ptr, msg_len)` delivery and re-entrant panic inside the hook (`index out of bounds` -> `division by zero`), inner return, exit 101.
  - `qa_hook_cleared.ax`: clearing the slot (`__ax_panic_hook_set(0)`) after a contained thread panic disables containment on the next thread panic (proving containment comes solely from `__ax_panic_hook`).
  - `qa_fiber_thread_mix.ax` (`modes: interp native`): thread panic inside a fiber, fiber panic, thread panic after fiber hook replaced thread hook, 4 concurrent threads x 20 fiber panics + post-fiber thread panic, and final main-thread panic (exit 101).
  - `qa_two_modules.test` + `qa_two_modules_oracle.py`: per-module hook isolation across an Axiom EXE + Axiom DLL (`-O0` and `-O1`), PE import/export table non-leak check, plus C naked-asm Win64 ABI stress test of `axiom_rt.obj`.
