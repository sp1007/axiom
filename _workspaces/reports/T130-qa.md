## Round 1

### Checks Performed
- `taskctl.py changes T130`: Clean, no REFUSED lines.
- Snapshot build (`build-snap-T130/build`): Built cleanly.
- Full test suite: 1 failure due to the test I added (`004_field_wise.ax`).
- Architecture check (`python tools/archcheck.py`): 0 violations.
- Added test `tests/run/drop/004_field_wise.ax` to verify field-wise drop of an aggregate.

### Findings
- **FAIL**: Field-wise drops are not executed. While `type_needs_drop` in `builder.c` was made recursive, `AX_MIR_TERM_DROP` is emitted only for the outer aggregate (`Wrapper`). The interpreter in `interp.c` does not recursively expand drops for fields. Thus, the inner field is never dropped. My added test `tests/run/drop/004_field_wise.ax` fails because the drop logic for the field (`Droppable1`) is never executed.
- **FAIL**: Incomplete drop elaboration for fields. The drop elaboration pass in `drop.c` explicitly skips tracking initializations and moves of fields (`if (src.proj_count == 0 ...)`). Partial moves and partial assignments to fields are therefore completely ignored for conditional drops.
- **FAIL**: Spec check / Missing `BOOTSTRAP-SHORTCUT`. The engineer removed the string lookup for `Resource` but replaced it with a string lookup for `Droppable` in `interp.c` (`strncmp(target_sname.ptr, "Droppable", 9) == 0`), which lacks the required `// BOOTSTRAP-SHORTCUT` annotation and the task ID that retires it.
