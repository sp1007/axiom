## Architectural Decisions & Alignment Notes
1. **Collision-Free Rule & Invariant Namespaces (`AXS-UNIV-001`..`036`, `INV-UNIV-001`..`004`)**:
   - Uses dedicated rule IDs `AXS-UNIV-001`..`AXS-UNIV-036` (`0` gaps, `0` global duplicates across `spec/`) and normalizes task-card shorthand `INV-UNIV-01..04` to 3-digit `INV-UNIV-001`..`INV-UNIV-004` in `spec/invariants.md` §44 per rule `IG-1` (`^### (INV-[A-Z]+-[0-9]{3}) — `), with explicit `since: T690`/`T691`/`T692` implementation anchors (`AXS-UNIV-036`).
2. **Self-Hosted Compiler Scope & Frozen Bootstrap (`INV-BOOT-004`)**:
   - Explicitly scopes all `E16.11` production modules (`compiler/target/x64/macos`, `compiler/obj/macho_universal`, `compiler/link/macho`, `compiler/link/archive_resolve`, `compiler/driver/universal`, `compiler/driver/emit_universal`, `std/sys/macos`) to the self-hosted compiler (`T690`–`T691`), leaving `bootstrap/axiom0/` untouched (`AXS-UNIV-001`).
3. **`x86_64-apple-darwin` ABI, Darwin Kernel Slice Alignment & Code-Signing Precision (`AXS-UNIV-002`..`009`, `AXS-UNIV-013`)**:
   - Defines `TargetSpec`-driven `TargetId.X86_64Macos` (`REQ-TGT-105`) with `CallConv.SysV64`, Darwin `RBP` frame-pointer chain (`SPEC-84 AXS-MACHO-009`), Rosetta-2-compatible `x86-64-v2` baseline, `MIN_PAGE_SIZE_BYTES = 4096` (`0x1000`), `CPU_TYPE_X86_64 = 0x01000007`, `CPU_SUBTYPE_X86_64_ALL = 3`, all 10 `X86_64_RELOC_*` (`0..9`, `SPEC-84 AXS-MACHO-017`) relocation encodings, 6-byte `FF 25 disp32` stubs, 24-byte `tlv_descriptor` (`thunk: extern "C" fn(*mut TlvDesc) -> *mut u8`, `SPEC-84 AXS-MACHO-018`, `SPEC-02 AXS-GRM-086`), `UNWIND_X86_64_*` compact unwind encodings, 64-bit `ino_t` `_stat$INODE64`/`_fstat$INODE64`/`_lstat$INODE64`/`_readdir$INODE64` bindings, and `64`-byte (`x86_64`, `SPEC-80 AXS-ELFS-048`) vs. `160`-byte (`aarch64`, `SPEC-84 AXS-MACHO-030`) stackful `FiberContext` layouts in `std.sys.macos`.
   - Enforces outer Fat slice alignment (`AXS-UNIV-013`) `fat_arch.align = 12` (`4 KiB`) for `CPU_TYPE_X86_64` and `fat_arch.align = 14` (`16 KiB`) for `CPU_TYPE_ARM64` so XNU `mmap` segment mappings remain VM-page aligned, while `CS_CodeDirectory` (`AXS-UNIV-008`, `SPEC-84 AXS-MACHO-025`) uses `flags = CS_ADHOC (0x0000_0002) | CS_LINKER_SIGNED (0x0002_0000)` (`0x0002_0002`) and `pageSize = 12` (`4 KiB` SHA-256 hash pages) on **both** `x86_64-macos` and `aarch64-macos` (and accepts `align in 3..30` when consuming external `lipo`/`libtool` universal `BsdAr` archives).
4. **Byte-Exact Slice Preservation, `LC_UUID` Formula & `SPEC-24` Artifact Magic Alignment (`AXS-UNIV-010`, `AXS-UNIV-018`..`023`)**:
   - Embeds deterministic `LC_UUID` (`first 16 bytes of BLAKE3("axiom-macho-uuid-v1" || image_bytes_with_zeroed_uuid_and_codesig)`, `SPEC-84 AXS-MACHO-021`) and `LC_CODE_SIGNATURE` inside each thin 64-bit Mach-O slice *prior* to Fat composition so `--extract-slice` recovers the bit-identical signed thin image (`INV-UNIV-001`, `INV-UNIV-004`); restricts Universal 2 inner slice magics strictly to 64-bit `MH_MAGIC_64` or `"!<arch>\n"` (rejecting legacy 32-bit `MH_MAGIC = 0xFEED_FACE` with `AX_LINK_FAT_SLICE_KIND_MISMATCH` and JVM `.class` `0xCAFEBABE` / corrupt headers with `AX_LINK_BAD_UNIVERSAL`); and preserves `SPEC-24` 8-byte ASCII `ArtifactHeader.magic` values (`"AXMI0001"` for `lib.axrmeta` inside per-slice `BsdAr` `.axlib` containers and `"AXPKG001"` for cross-OS `.axpkg` bundles).
