### Scrutiny points
- **`qa_registry_format_check.py` empty-registry rule removed: justified, and no real check is weakened.** ADR-0035
  §3–§4 (zero tolerance) requires `known_divergent.txt` to be empty before T086, so the old rule rejected the required
  goal state. An empty registry can hide nothing. `axiomc_e2e_oracle.py` turns every non-equal program that is not
  listed into a `REGRESSION` failure, so empty is the strictest state. A missing file is still not accepted:
  `qa_registry_format_check.py` opens it unconditionally and crashes. All remaining format checks are unchanged:
  CR bytes, 3 fields, closed stage and behaviour vocabularies, corpus membership, uniqueness, sorting.
- **Bundles regenerated from the final sources.** Every `tests/selfhost/*/gen_*_tests.py --check` (34 generators)
  reports "up to date". The content agrees too: every bundle that contains `fn resolve_path_seg(` (73) also contains

### Follow-ups (to axiom-architect)
- **Pre-existing axiom0 interpreter defect, not caused by T153** (axiom0 is untouched). A generic function instantiated
  for two types whose impls differ binds the first impl's method in `run --interp` for both instances. Native is
  correct, and axiomc matches axiom0 native byte for byte. Minimal repro:
  - trait `Greet { fn hello(self: view<Self>) -> i32; }`, with `A.hello() = 42` and `B.hello() = 100`;
  - `fn via_bound<T: Greet>(x: view<T>) -> i32 { x.hello() }`;
  - `main` prints `via_bound(view(a))` and `via_bound(view(b))`.

  `axiom0 run --interp` prints `42 42`; native prints `42 100`. The same happens when `A` uses a default `hello`.
  Mono keys the call target by instance in the native path, but not in the interpreter. It may share a root cause with
  T161 (one body per trait member) but is wider: no default method is involved. It is a semantic-oracle bug that cross
  tests (T139) would expose. The QA test above avoids the second instance and says why.
- Unsupported `T.Item` (associated type through a type parameter) is rejected the same way by both compilers. This is
  a spec/feature gap to confirm against REQ-TRT-012, not a parity problem.
