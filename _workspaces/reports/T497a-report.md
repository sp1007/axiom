# T497a report — every registered diagnostic code renders with its name

## Summary
`diag_buf_push_code_name` (compiler/diag/format.ax) kept its own hand-written name tables (a byte table for ids 0..132, a second one
for the concurrency codes, one-off tables for 168 and 169) and had no branch for ids 156..165 (`AX_ASYNC_*`), so those diagnostics
printed `error[<unknown>]`. The function now renders `diag_code_name(c)` (compiler/diag/code.ax, the single name table); the five
duplicate tables and their helpers were deleted (about 120 lines removed). A code the table does not know still renders `<unknown>`,
exactly as before. The string is read byte by byte from the `str` fat pointer (same reinterpretation `ux2_sv` uses) so nothing is
allocated per diagnostic.

Layering: format.ax already imported `compiler.diag.code.diag_code_name`, so no new dependency; the added `address_of` intrinsic
declaration is module-local like in ux2/typeck.

## Tests
- `tests/run/diag_ux2/qa_t497_probe.ax.in`: the 156..165 skip is gone; the sweep over ids 0..=169 now covers every id.
- New `tests/run/diag_code_names/` (`diag_code_names.test`, `diag_code_names_oracle.py`, `diag_code_names_probe.ax.in`,
  `await_outside_async.ax.in`):
  - probe (interp, native -O0, native -O1): for every id 0..=255 the rendered name equals `diag_code_name`; "registered" is judged by the
    independent `diag_code_default_message` table (non-empty exactly for registered ids), so no registered id renders `<unknown>`, no
    unregistered id renders a name, and the highest registered id is >= 169; the ten `AX_ASYNC_*` ids must render an `AX_ASYNC_` name.
  - ui-style check: `axiomc check` on an `.await` outside an async fn must print `error[AX_ASYNC_AWAIT_OUTSIDE_ASYNC]` and never
    `error[<unknown>]` (the program is stored as `.ax.in` so the runner does not treat it as a ui test).
  - Mutation check: with HEAD's format.ax substituted, the probe fails (`mismatch=10 table_disagree=10 async_bad=10`); with the fix it passes.
