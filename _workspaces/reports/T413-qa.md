### Findings (FAIL)

#### Finding 1: Acceptance Criterion #1 Violated — Absence of Spawned Thread, `LocalKey<T>`, and Thread-Exit Cleanup Verification
- **File**: `tests/run/concurrency/tls/tls_threads.ax`, `tests/run/concurrency/tls/tls_static_basic.ax`, `tests/run/concurrency/tls/tls_multi_static.ax`
- **Spec / Contract**: Task Acceptance #1 specifies:
  > "`tests/run/concurrency/tls/*.ax` (`modes: interp native`) verifies that `@thread_local` statics and `LocalKey<T>` are isolated per thread across multiple spawned threads and cleaned up on thread exit."
- **Expected**: Tests under `tests/run/concurrency/tls/` must spawn multiple threads (verifying that each child thread sees its own fresh `@thread_local static` and `LocalKey<T>` initial values, that mutations on one thread do not pollute other threads or the parent thread, and that `LocalKey<T>` values are dropped upon thread termination).
- **Actual**:
  - `tests/run/concurrency/tls/tls_static_basic.ax`: Completely single-threaded. No threads are spawned.
  - `tests/run/concurrency/tls/tls_multi_static.ax`: Completely single-threaded. No threads are spawned.
  - `tests/run/concurrency/tls/tls_threads.ax`: Misleadingly titled `tls_threads.ax`, but does not spawn any threads at all. It merely calls a recursive factorial function `mult()` sequentially on the main thread.
  - `LocalKey<T>` is **not tested anywhere** in `tests/run/concurrency/tls/*.ax`.
  - Thread-exit cleanup is **not tested anywhere** in `tests/run/concurrency/tls/*.ax`.

#### Finding 2: `std.thread.LocalKey<T>` Reentrancy Violation
- **File**: `std/thread/local.ax:103-123`
- **Spec / Contract**: `SPEC-32` `AXS-SYNC-021.1`:
  > "`pub fn with_mut<F, R>(self: view<LocalKey<T>>, f: F) -> R`: Invokes `f(mut_view(tls_val))` on the calling thread's instance (panicking if reentrantly invoked on the same `LocalKey<T>` while an outer `with` or `with_mut` borrow on the same thread is active, preserving `mut_view` exclusivity)."
- **Expected**: A call to `with()` while an outer `with_mut()` is active, or a call to `with_mut()` while an outer `with()` or `with_mut()` is active, must panic dynamically on the current thread.
- **Actual**:
  ```axiom
  pub fn with<F: FnOnce<view<T>, R>, R>(self: view<LocalKey<T>>, f: F) -> R {
      let node = self.find_or_create_node();
      let ptr = unsafe { (*node).val_ptr };
      f(unsafe { view(*(ptr as *const T)) })
  }
  ```
  `with()` does not check or update any borrow state. `with_mut()` only checks `is_borrowed: bool`.
  - Calling `key.with(|v| key.with_mut(|m| ...))` does not panic; it grants a `mut_view<T>` aliasing the active outer `view<T>`.
  - Calling `key.with_mut(|m| key.with(|v| ...))` does not panic; it grants a shared `view<T>` while `mut_view<T>` is actively borrowed.
- **Fix Required**: Update `LocalSlotNode` to track borrow state (e.g. `borrow_state: i32` or RefCell-like state where `> 0` counts active `view<T>` borrows and `-1` represents an active `mut_view<T>`). `with()` must check `borrow_state >= 0`, increment on entry, and decrement on exit. `with_mut()` must check `borrow_state == 0`, set `-1` on entry, and restore `0` on exit.

#### Finding 3: `LocalKey<T>` Incompatible with Static Declaration and Thread Sharing
- **File**: `std/thread/local.ax:51-60`
- **Spec / Contract**: `SPEC-32` `AXS-SYNC-020` & `AXS-SYNC-021`
- **Actual**:
  - `LocalKey<T>` has `impl<T> !Share for LocalKey<T> {}`. Because normal global `static` items require `T: Share`, declaring `static KEY: LocalKey<T> = ...` is rejected with `AX_CONC_UNSYNC_STATIC`.
  - `LocalKey<T>` has `impl<T> !Send for LocalKey<T> {}`, so it cannot be captured by value in `std.thread.spawn` (`AX_CONC_CAPTURE_NOT_SEND`).
  - `local_key_new` invokes `NEXT_LOCAL_KEY_ID.fetch_add(...)` at runtime, preventing constant evaluation in static initializers.
  - As a result, no spawned thread can currently access a `LocalKey<T>`.
- **Fix Required**: Ensure `LocalKey<T>` can be declared as `@thread_local static KEY: LocalKey<T> = LocalKey.new(init_fn)` (with a `const`-evaluable initializer, e.g. using a unique slot ID or symbol ID assigned during compilation/initialization), or align its auto-traits with `SPEC-32`.

#### Finding 4: Acceptance Criterion #2 Incomplete — Missing Negative UI Diagnostics
- **File**: `tests/ui/concurrency/tls/tls_escape.ax`
- **Spec / Contract**: Task Acceptance #2 specifies:
  > "`tests/ui/concurrency/tls/*.ax` verifies compile-time rejection of cross-thread sharing or escaping references to thread-local storage."
- **Actual**:
  `tests/ui/concurrency/tls/tls_escape.ax` only tests reassigning a TLS view to an outer block-scoped variable.
  The following cases prescribed by `SPEC-32` `AXS-SYNC-020.3`, `AXS-SYNC-021.2`, and `AXS-SYNC-022.2` are untested in `tests/ui/concurrency/tls/`:
  1. Returning a `view<T>` or `mut_view<T>` of a `@thread_local static` from a function.
  2. Storing a `@thread_local static` view into a struct field, heap buffer, or global place.
  3. Capturing a `@thread_local static` or TLS view inside a `spawn(...)` closure.
  4. Escaping borrowed views from `LocalKey<T>.with` / `with_mut` closures.
