## 1. Implementation Audit against Specification

### 1.1 State Machine Layout & Lowering (`compiler/mir/async_lower.ax`)
- **Struct Representation**: For each `async fn`, an anonymous struct type is generated. Field 0 is `state_tag: u32`. Parameters are moved into following fields.
- **Liveness Analysis**: Forward maybe-initialized analysis combined with backward use liveness identifies variables that cross suspension points (`Suspend` MIR statement). Only live locals across suspension points are captured in the state-machine frame.
- **Sub-Future Slots**: Each await/suspension point allocates a dedicated field for the in-flight sub-future.
- **Constructor & Registration**: The original function signature is preserved and lowered into a constructor that initializes `state_tag = 0`, stores incoming parameters into their state-machine fields, and returns the coroutine instance.
- **`Future.poll` Synthesis**: Synthesizes `impl Future` with `poll(self: mut_view<Self>, cx: mut_view<Context>) -> Poll<Output>`.
  - Dispatches on `state_tag` via `SwitchInt`:
    - `0`: unpolled initial state.
    - `1..N`: suspension / resume points.
    - `u32::MAX`: completed future (returns panic / already completed).
    - `u32::MAX - 1`: cancelled / panicked future.
    - Otherwise: `unreachable`.

### 1.2 Cancellation Drop Glue (`compiler/mir/drop.ax`)
- In `drop_expand_coroutine`, per-state drop blocks are synthesized:
  - If dropped when `state_tag == u32::MAX` (completed) or `state_tag == u32::MAX - 1` (cancelled), branches directly to target (no-op drop).
  - If dropped at suspension point `k`, drops the in-flight sub-future first.
  - Subsequently drops live local variables of state `k` in reverse declaration order.
  - Updates `state_tag = u32::MAX - 1` before completing destruction.

### 1.3 `block_on` Poll Driver & Waker (`std/future/block_on.ax`, `std/future/mod.ax`)
- Implements single-threaded synchronous poll driver `block_on<F: Future>(mut future: F) -> F.Output`.
- Uses a stack-local no-op `RawWakerVTable` and `Waker`/`Context`.
- Loop repeatedly polls the future until `Poll.Ready(val)` is returned.
- Re-exports `Poll`, `Waker`, `Context`, `Future`, and `block_on` cleanly from `std.future`.

## 2. Adversarial QA Boundary Tests

Two new adversarial tests were constructed under `tests/run/async/` to probe edge conditions:

1. **`tests/run/async/qa_nested_cancel_reverse_drop_order.ax`**:
   - Probes deep suspension cancellation across a 3-tier coroutine hierarchy: `outer_task` awaiting `inner_task` awaiting a pending leaf future.
   - Evaluates early cancellation drop glue when the future is dropped before completion.
   - Asserts exact reverse recursive drop order via explicit stdout assertions:
     ```
     leaf_drop
     inner_local_drop
     inner_param_drop
     outer_local_drop
     outer_param_drop
     finished
     ```
   - Verified in `interp`, `native`, and `native-O1` (`WEAK-NATIVE 0`).

2. **`tests/run/async/qa_multi_pending_branch_loop_state.ax`**:
   - Probes a multi-step `Pending` future evaluated in a `while` loop with conditional branching (`if (i % 2) == 0`).
   - Verifies state-machine variable saving and restoration across multiple successive `Poll.Pending` yields within loops.
   - Exercises local variable drops on loop iteration boundaries and conditional branch scopes.
   - Verified in `interp`, `native`, and `native-O1` (`WEAK-NATIVE 0`).
