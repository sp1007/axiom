### Findings
- **FAIL**: `python tools/axtest.py` has multiple failing tests (e.g. `driver/build_ok.test`, `driver/run_ok.test`, `fuzz/qa_seed_test.ax`). The `stage_run` has been added into `ax_pipeline_stages` using the sentinel `AX_STAGE_LIMIT`, causing `ax_pipeline_run` to inappropriately execute the interpreter and `exit()` during `build` operations, violating pipeline boundaries and breaking standard tests.
- **FAIL**: `bootstrap/axiom0/src/driver/pipeline.c:164`: `stage_run` clears `st->sink.errors` explicitly to "workaround incomplete type inference". This hides actual verifier and type check errors and violates the strict rule: "no silent semantic choices; no BOOTSTRAP-SHORTCUT without the task that retires it".
- **FAIL**: `bootstrap/axiom0/src/driver/pipeline.c:127`: `stage_lex` introduces a hack to parse `.mir` files, bypassing typeck entirely, and relies on an unapproved syntax extension (`// expected_return_type: `). This violates canonical syntax and type checking rules.
- **FAIL**: `bootstrap/axiom0/src/interp/interp.c:78`: Library code directly calls `fprintf(stderr, ...)` and `exit(101)`/`exit(124)` rather than bubbling up errors to the driver. This prevents JSON rendering of diagnostics, producing zero output for limits/panics, and violates layer rule `INV-LAYER-006`.
- **FAIL**: Layer violation (`INV-LAYER-001`); `bootstrap/axiom0/src/interp/interp.c:1` includes `driver/driver.h`, violating dependency direction.
- **FAIL**: `tests/run/basic/008-step-limit.ax` added in this QA round hits the step limit but emits no diagnostic text to `stderr`, failing the acceptance criteria: "step limit: default per SPEC-03 with a clear diagnostic when exceeded".
