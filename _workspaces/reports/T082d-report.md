# T082d report — Port drop elaboration and cleanup edges to Axiom

## Summary
- `compiler/mir/drop.ax` is a complete port of `bootstrap/axiom0/src/mir/drop/drop.c`
  (`ax_type_needs_drop`, `place_type`, drop-flag synthesis, flag maintenance, `expand_drop`,
  `ax_mir_drop_elaborate`), written as readable Axiom (one statement per line, helper per concern).
  Public API:
  - `mir_drop_elaborate(body, thir, hir, db: *const SourceDatabase, str_in, arena)` — the C entry
    point; `db` may be null (destructor impls are then matched on interned names).
  - `mir_type_needs_drop_in(ty, thir, hir, db, str_in)` and `mir_type_needs_drop(ty, thir, hir,
    str_in)` (db = null; the signature `compiler/mir/builder.ax` already calls).
  - `mir_find_drop_impl_fn(hir, def, db, str_in)`, `mir_drop_place_type(body, thir, place)`.
- Covered: drop flags for every droppable local (initialised true for arguments), flag set after
  assignments and in the return block of calls that write the local, flag clear before every
  move/copy out (statements, switch discriminants, call callee/arguments, assert conditions),
  flag test + clear blocks in front of each `drop`, user `Drop.drop` calls, field-wise drops of
  structs and tuples (last field first), closure by-move captures (environment field k + 1), enum
  drops through `discriminant` + `switchInt` with one arm per variant whose fields need drop, and
  repeated passes until all new field drops are expanded. Drops on scope exit, `return`, `break`,
  `continue` and unwind edges are all elaborated (the builder emits them as `drop` terminators).
- Every block, local, statement and interned type is created in the C order, so the elaborated body
  prints byte-identically with `ax_mir_print`.

### Differential harness (`tests/selfhost/drop/`)
- `cdriver_drop_oracle.c` — C oracle (built as `ct_selfhost_drop_cdriver_drop_oracle` by the
  existing `cdriver_*.c` glob): pipeline up to TYPECK, `ax_mir_build` per top-level fn exactly like
  `axiom0 inspect --emit=mir`, then `ax_mir_drop_elaborate` with the driver's arguments, then
  `ax_mir_print`. `inspect --emit=mir` itself never runs drop elaboration, so this oracle is the
  only way to get the C elaborated MIR. With `--pre` it skips elaboration (and `gen_drop_tests.py
  goldens` checks that this equals `inspect --emit=mir`).
- `fixtures/dNN_*.ax` + goldens `*.pre.mir` (`inspect --emit=mir`) and `*.drop.mir` (C oracle).
- `qa_drop_dNN.ax` (one fixture per file; generated by `gen_drop_tests.py bundles` from
  `harness_main.ax.in`): the compiler modules as one program; per fixture it lowers with the Axiom
  front end + builder and compares the MIR byte for byte with `*.pre.mir` (pass 1), then with drop
  elaboration with `*.drop.mir` (pass 2).
- `drop_oracle.test` (exec, `requires: axiom0-internal`) runs `gen_drop_tests.py check`: the C
  oracle must still print exactly the committed goldens, so the goldens cannot drift from C.
- User destructors: the Axiom front end cannot lower any file that contains an `impl` (see
  Follow-ups), so `d10_destructor` runs a third, synthetic pass: the harness adds
  `impl Drop for Guard { fn drop }` to the HIR after type checking and elaborates without a source
  database; the result must equal `d10_destructor.synth.mir`, and `gen_drop_tests.py check` compares
  that golden with the C elaboration of `d10_destructor.impl.ax` (same program with the impl written
  out) after renumbering `type#N` and called fn constants by first appearance (the only
  differences: the C type checker interns `mut_view<Guard>` earlier and the destructor symbol is
  54 in C, 7001 in the synthetic HIR).
- Fixtures: d01 scope exit; d02 conditional move + moved argument; d03 nested structs, tuples,
  nested tuple; d04 enum variants (switch arms only for variants with droppable fields); d05 enums
  in structs and structs in enum variants (multi-pass expansion), droppable arguments; d06 early
  return, break, continue; d07 call destinations and re-assignment; d08 generic containers (C goldens
  only, see Follow-ups); d09 closure by-move capture; d10 user destructor (synthetic pass).

## Spec deviations
none — behaviour is the C implementation's, including these C quirks kept on purpose for byte
identity (recorded in the `drop.ax` header; the architect may want ADR/bug tasks for the C side):
- the destructor argument is built with a shared borrow (`_a = &place`) although its local has type
  `mut_view<T>` (C never sets the borrow kind);
- copies clear a drop flag exactly like moves;
- field drop blocks carry no flag, unwind to bb0 and are not cleanup blocks; the callee constant of
  a destructor call has a bare `fn` type;
- a struct declared without named fields (unit, `{}`, tuple struct) always needs drop; `impl Drop`
  is matched by name (source text with a database, interned names without), the first fn member
  is the destructor.
Design decisions (for the architect): `mir_type_needs_drop` keeps its 4-argument signature
(db = null, as `ax_type_needs_drop(..., NULL)` in the C interpreter) because builder.ax calls it;
the elaboration itself takes the source database like the C driver. `body.drop_flag_count` is set
to the number of flags created (the field had no writer).

## Follow-ups
1. Axiom front end drops function bodies when the file has any `impl` block (inherent or trait):
   every fn then lowers to an empty MIR body (`bb0: return;`), although HIR statements exist.
   Minimal repro (compare with `axiom0 inspect --emit=mir`):
   `struct Res {} struct Guard { id: i32, inner: Res } impl Guard { fn get(self: view<Guard>) -> i32 { 1 } } fn main() { let g = Guard { id: 1, inner: Res {} }; }`
   — typeck/builder area (T081 / T082a). Blocks the end-to-end differential of user destructors
   (covered by the synthetic pass instead).
2. Axiom type checker rejects generic struct literals and generic enum constructors
   (`struct Wrap<T> { v: T, tag: i32 } ... let w: Wrap<Res> = Wrap { v: Res {}, tag: 1 };` →
   AX_TYPE_MISMATCH; axiom0 accepts it) — T081. Fixture d08 keeps its C goldens and should be added
   to `GROUPS` in `gen_drop_tests.py` once fixed.
3. Without the std prelude the Axiom front end numbers tuple/closure types differently from axiom0;
   the harness therefore always appends the prelude (`session_append_std_prelude`) like axiom0.
   Untyped integer literals inside tuple literals still intern one extra type (`(Res {}, 5, Res {})`
   gives type#26 vs type#25) — fixtures use typed literals (`5u8`).
4. compiler/ front-end sources at HEAD do not build as one program: `compiler/kernel/interner.ax`
   contains mangled expressions (`old_(mcap << 3)`, `new_(((cap as isize) ...`, `cur_(cap << 2)`),
   `compiler/kernel_source_diag/session.ax` calls `compiler.diag.code.diag_code_severity` through a
   path the resolver rejects, and with those two modules taken from the T082a bundle the program
   fails at run time (interpreter: out-of-bounds pointer access; native: arithmetic overflow panic).
   The harness therefore takes the front end from the module sections of
   `tests/selfhost/mir/qa_mir_builder_and_drop_a.ax` (the copies QA accepted) and only the MIR layer
   (`mir.ax`, `drop.ax`, `builder.ax`, `mod.ax`) from compiler/. A canonical bundler from compiler/
   (T076 harness) is needed.
5. `compiler/mir/mod.ax` (not in this task's paths) does not re-export the drop API; add
   `pub use compiler.mir.drop.{mir_drop_elaborate, mir_type_needs_drop, mir_type_needs_drop_in,
   mir_find_drop_impl_fn, mir_drop_place_type}` (one `pub use` per name).
6. MIR interpreter: building a large struct by value in a helper (`let mut s = MirStmt { ... };
   mir_stmt_zero(mut_view(s), ..); s`) and pushing it with `mir_bb_push_stmt(.., view(s))` lost the
   statement contents under `axiom0 run --interp` (printed as an empty statement) while native was
   correct. drop.ax now allocates such statements in the arena (as C does), so it is not exercised;
   needs a minimal repro by the interpreter owner.
7. The `*(address_of(sv) as *const str)` trick used by the selfhost harnesses to print a byte view
   is out of bounds under the interpreter; it is only reached when a comparison fails, but then the
   interp run reports AX_UNSAFE_INTERP_UB instead of the diff. A std way to print bytes (`host.write`
   to stdout from a test) would make failures readable in both modes.
