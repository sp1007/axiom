### Findings
1. **F1 - `Self.k()` (receiver-less trait member) inside a default body binds to the first impl, in
   both legs and both compilers.** In scope: the task says "method calls and `Self` paths inside the
   body (`self.m()`, `Self.CONST`, `Self.Item`, supertrait methods) resolve against that type's impl".
   Repro: `tests/run/parity/trait_default/qa_default_self_static_call.ax` (trait `Base { fn k() -> i32;
   fn twice_k() -> i32 { Self.k() * 2 } fn via_self(self: view<Self>) -> i32 { Self.k() + 1 } }`,
   A.k() = 4, B.k() = 40). Expected `8 80 5 41 40`, actual `8 8 5 5 40` (interp, native, native-O1).
   `Self.K` in the same position is correct (`assoc_const_in_default.ax`), so only the call is wrong.
   Likely cause: `bootstrap/axiom0/src/driver/mono.c` `ax_mono_instantiate_default` skips calls with
   `term->call.arg_count == 0` and takes the receiver type from `args[0]`; the port's
   `compiler/mir/builder.ax` `mb_instantiate_default` has the same `arg_count > 0` guard. A call of a
   trait member with no receiver needs the implementing type itself (the instance's self type).
