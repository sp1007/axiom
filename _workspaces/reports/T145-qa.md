## Findings

### Follow-up Fix Tasks Required After `taskctl.py accept T145` (Architect Diagnosis)

1. **Stage-0 (`axiom0`) comptime `Str`-in-`const`-table bug (`run/comptime/table_str.ax`, `run/comptime/qa_table_struct_str.ax`, `run/native_const/qa_table_str_empty_and_multitables.ax` — 9 failing legs)**:
   - **Root cause in `axiom0`**: `bootstrap/axiom0/src/interp/interp.c` handles `AX_MIR_OP_CONST` of type `t_str` (`f_size == 16`) in `AX_MIR_RVALUE_USE` (lines 626–629), but omits `t_str` (`f_size == 16`) in `AX_MIR_RVALUE_AGGREGATE` (lines 686–692) and `AX_MIR_RVALUE_REPEAT` (lines 720–726), which only handle `f_size` in `{1, 2, 4, 8}`. Because `ax_interp_eval_const_expr` executes the initializer MIR body via `exec_mir_body` to populate `cval->aggregate.data`, every `Str` slot inside a `const` array or struct is left zero-initialized (`ptr = 0, len = 0`) in both `--interp` and `build.c`'s `emit_const_tables`.
   - **Action for orchestrator / `T154`**: `T154` ("Backend parity - narrow-value sign/zero extension in x64 isel, -O1 LIR path, const-table .rdata layout") already owns item 3 (`tests/run/comptime/{table_str,qa_table_struct_str}.ax` and `native_const/qa_table_str_empty_and_multitables.ax`), **but `T154`'s `paths:` currently lacks `bootstrap/axiom0/src/interp`**. Add `bootstrap/axiom0/src/interp` (and `tests/run/comptime`, `tests/run/native_const` if needed) to `T154`'s `paths:` and note the `interp.c:686-692,720-726` root cause in `T154`.

2. **Stage-0 (`axiom0`) native `__ax_host_print_int` Win64 shadow-space clobber bug (`run/method/builtins.ax`, `run/method/inherent_methods.ax`, `run/method/qa_run.ax`, `run/native_str/qa_print_int.ax`, `run/str/qa_print_int.ax` — 10 failing native legs)**:
   - **Root cause in `axiom0`**: In `bootstrap/axiom0/src/link/pe/linker.c` line 468 (`print_int_code[]`), the machine-code stub allocates `sub rsp, 0x30`, sets `lea rdi, [rsp + 0x20]`, and formats the ASCII digits backwards into `[rsp + 0x00 .. rsp + 0x1F]` **before** calling `GetStdHandle(-11)`. On Windows x64, `[rsp + 0x00 .. rsp + 0x1F]` is the 32-byte home/shadow space owned by the callee (`GetStdHandle`), and `kernelbase!GetStdHandle` zeroes `[rsp + 0x18 .. rsp + 0x1F]`, overwriting the formatted ASCII digits with `0x00` bytes before `WriteFile` is called.
   - **Action for orchestrator**: File a new `AX0-FIX` task (or expand `T154` with `paths: [bootstrap/axiom0/src/link/pe, compiler/link]`) to fix `print_int_code` in `bootstrap/axiom0/src/link/pe/linker.c` (and verify `compiler/link/pe.ax` in lockstep per ADR-0034 §2) so the digit buffer is placed above the 32-byte Win64 shadow space (or `GetStdHandle` is called before formatting digits), and make `T086` depend on it.

3. **Selfhost bundle and registry refresh (`tests/selfhost/`)**:
   - **Action for orchestrator**: `T144` (currently running in `tests/selfhost`) and `T154` (which owns `tests/selfhost` and `known_divergent.txt`) will refresh `tests/selfhost/backend/qa_backend_diff_{lir,mi_mc}_b.ax`, `tests/selfhost/interp_opt/qa_interp_opt_bundle.ax`, and `tests/selfhost/obj_link_driver/known_divergent.txt` for the `tests/run/` files updated in `T145`.
