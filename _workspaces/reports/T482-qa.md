### 5. Adversarial test (step 5)
`tests/run/o1_neg_carry_repro/qa_neg_carry_i128_runtime.ax`: the engineer's test exercises the u64-pair helper shape;
it does not go through the real i128 path of the compiler. Mine negates genuine `i128` values built at run time in a
loop (not foldable at -O1): low word 0 (k * 2^64, carry into the high word, k = 0..3) and low word != 0 (1,
3 * 2^64 + 2), and prints hi/lo of `-x`, of `0 - x`, and the quotient/remainder of `(-x) / (-(2^64))`. The signed
division routes through `u128_neg_raw` in the interpreter and through the T453 native i128 path. Expected values come
from a Python big-int model. Snapshot compiler: 3/3 PASS (interp, native, native-O1); original-form compiler: PASS
(part of the 161 above).

Note (not a finding): in `neg_carry_forms.ax` the early-return branch of `neg_orig_stmt` (`hi == 0 && lo == 0`) is
never reached by the 10-case loop (lo = 0 always pairs with hi = 1 or max). Coverage nit only.
