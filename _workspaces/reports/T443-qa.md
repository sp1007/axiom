### 1. Duplicate detection (code read + executed)
Code: `bundle_common.py` `_canonical_module_name`, `find_duplicate_modules`, `assemble_compiler_modules(mod_list, root, caller)`.
- Exact duplicate, adjacent, tuple entries, several duplicates in one message, caller in the message: covered by the engineer's
  11 checks and by my 8 checks (all pass). Message form `duplicate module(s) ['x', 'y'] in module list of <caller>`.
  `caller` defaults to `os.path.basename(sys.argv[0])`. The caller's list is not mutated (my check 7). No silent de-duplication.
- Folding correctness. The file table `compiler_module_files` registers a file under: its declared name, the declared name minus
  `.mod`, and `compiler.own.move_ck` / `compiler.own.unsafe_ck` aliases of `compiler.own.move` / `compiler.own.unsafe`.
  `_canonical_module_name` folds exactly those and nothing else, so two spellings reach the same file iff they fold together
  (no under- or over-folding). Evidence for "no false rejection": I scanned all 175 module declarations under `compiler/`
  (4 `.mod` modules, `own.move`, `own.unsafe`): 175 declared names -> 175 canonical names, 0 collisions between distinct files, 0
  files declaring the same module twice; and the whole set of 175 modules in one list is accepted and assembled byte-identically
  to the HEAD implementation (output 11,462,993 bytes, `old == new` True; HEAD version taken from `git show HEAD:...`).
- All 36 generators plus every other caller. Beyond the 36 `gen_*.py`, `assemble_compiler_modules` has ~70 other callers
  (`tests/conformance/p15,p18,p19,p20/*_oracle.py`, `tests/run/*_oracle.py`, `tests/opt2/*`), which the report did not mention and
  the new raise could break. I checked them all for duplicates: (a) AST scan of every list/tuple literal of `compiler.*` names
  and every module-level constant in 82 files (133 lists), (b) dynamic hook (patched `assemble_compiler_modules` recording the
  names, then running each oracle with its `.test` arguments): the opt family / e18_5 / translation_val lists (86 modules,
  `list(got.CORE_MODULES) + [...]`) reach the hook with 0 duplicates, and e15_5 / e15_7 / perf_contract extras checked by hand
  against `got.CORE_MODULES` (25 modules): 0 duplicates. Only duplicate found anywhere: the intentional one inside the new
  selftest. No caller breaks. (Oracles that fail before reaching the call in the stripped environment were covered by (a).)

### 2. Adversarial inputs (my own, results and judgement)
- Case difference (`Compiler.Kernel.Id`), trailing / leading blank, `/` separator: not folded, and not accepted as a second
  module either: `files[raw_name]` raises `KeyError`, so no silent second copy and no bundle. Right behaviour (the identifier
  space is exact); note only that the error is a bare `KeyError: 'compiler.kernel.id '` (pre-existing, unchanged).
- Empty list: accepted, returns `''`. 1-element tuple entry: accepted.
- Same module in two tuple forms `("m","a"), ("m","b")` and plain `"m"`: one duplicate, reported once.
- `.mod` twice, `X` + `X.mod`: rejected as duplicate (same file would be emitted twice). `move`+`move_ck`+`unsafe`+`unsafe_ck`
  in one list: both aliases reported in one message. `compiler.own.move.mod` folds to `move_ck` (not a real module; harmless).
- Tuple container instead of list: checked. Generator/iterator input: works (consumed once into `names`).
- Judgement on `X` + `X.mod`: the engineer's fold treats them as one module although they are emitted as differently named
  modules (`module X` vs `module X.mod`). Rejecting is the safe reading (same source twice) and no real list does it.
