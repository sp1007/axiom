### Findings

#### Finding 1: `bootstrap/axiom0/src/own/own.c:184-186` — `move_loc` dropped during state merge, misreporting use-after-move as uninit
- **File & Line**: `bootstrap/axiom0/src/own/own.c:184-186`
- **Expected vs Actual**:
  - Expected: In a loop where a variable is moved across iterations (such as `tests/ui/own/loop_move.ax`), reading the moved variable on subsequent iterations reports `AX_MOVE_USE_AFTER_MOVE` with a label pointing to the move site.
  - Actual: In `merge_states()`, `m = merge_state_val(dest[i].state, src[i].state)` evaluates to `AX_OWN_PARTIAL` when joining `AX_OWN_OWNED` (from entry block) and `AX_OWN_MOVED` (from the loop back-edge). The guard `if (src[i].state == m)` evaluates to false because `src[i].state` is `AX_OWN_MOVED != AX_OWN_PARTIAL`. Consequently, `dest[i].move_loc` remains empty (`file.v == 0`). In `check_use()` (lines 209-210), `is_uninit` evaluates to true because `move_loc.file.v == 0`, emitting `AX_INIT_USE_UNINIT` without labels instead of `AX_MOVE_USE_AFTER_MOVE`.
- **Repro**:
  ```powershell
  python tools/axtest.py --compiler build/axiom0.exe ui/own/loop_move.ax
  ```
  Output: `FAIL ui/own/loop_move.ax: missing diagnostics: ERROR AX_MOVE_USE_AFTER_MOVE at line 10 | unexpected diagnostics: ERROR AX_INIT_USE_UNINIT at line 10`

#### Finding 2: `bootstrap/axiom0/src/verify/verify.c:210-214, 356` — MIR verifier definite assignment checks deleted
- **File & Line**: `bootstrap/axiom0/src/verify/verify.c:210-214` and line 356
- **Expected vs Actual**:
  - Expected: `ax_verify_mir()` validates MIR invariants for standalone `.mir` files (e.g. `axiom0 check tests/verify/uninit_cond.mir`) and reports `AX_VERIFY_UNINIT_USE` when a local is read before definite assignment.
  - Actual: `CHECK_PLACE(p)` was reduced to an empty macro `do { } while (0)` and the return-slot check was removed. When running `axiom0 check tests/verify/uninit_cond.mir` or `tests/verify/uninit_use.mir`, `axiom0` exits 0 with no error, failing the test expectations.
- **Repro**:
  ```powershell
  python tools/axtest.py --compiler build/axiom0.exe verify/uninit_cond.test verify/uninit_use.test
  ```
  Output:
  ```
  FAIL verify/uninit_cond.test: exit code 0, expected 1; stderr:
  FAIL verify/uninit_use.test: exit code 0, expected 1; stderr:
  ```

#### Finding 3: `bootstrap/axiom0/src/types/typeck.c:1588-1594` — Removal of `AX_TYPE_UNINIT_USE` broke existing tests
- **File & Line**: `bootstrap/axiom0/src/types/typeck.c:1588-1594`
- **Expected vs Actual**:
  - Expected: Full test suite passes.
  - Actual: `tests/ui/own/uninit.ax` and `tests/ui/vars/uninit_use.ax` expect `AX_TYPE_UNINIT_USE`. Removing the check from `typeck.c` allows these cases to proceed past typeck into `own.c`, where they emit `AX_INIT_USE_UNINIT`. Because these test files were neither locked nor updated (they are outside T047's paths), both tests fail.
  - Recommendation / architectural decision: Either `typeck.c` must retain its check, or if the intent (per ADR-0023) is to completely replace `AX_TYPE_UNINIT_USE` with `AX_INIT_USE_UNINIT`, the architect must grant locks on `tests/ui/own/uninit.ax` and `tests/ui/vars/uninit_use.ax` so their annotations can be updated to `AX_INIT_USE_UNINIT`.
- **Repro**:
  ```powershell
  python tools/axtest.py --compiler build/axiom0.exe ui/own/uninit.ax ui/vars/uninit_use.ax
  ```
  Output:
  ```
  FAIL ui/own/uninit.ax: missing diagnostics: ERROR AX_TYPE_UNINIT_USE at line 7 | unexpected diagnostics: ERROR AX_INIT_USE_UNINIT at line 7
  FAIL ui/vars/uninit_use.ax: missing diagnostics: ERROR AX_TYPE_UNINIT_USE at line 4 | unexpected diagnostics: ERROR AX_INIT_USE_UNINIT at line 4
  ```
