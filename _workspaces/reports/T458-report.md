# T458 Report - E12.2: Oracle IEEE-754 float evaluator and strict FP optimizer preservation

## Summary
- **Soft-float in the oracle (`compiler/interp/value.ax`)**: f32/f64 are evaluated on raw bit patterns with integer arithmetic only (axiom0 has no FPU use, and the result must not depend on the host). All rounding is roundTiesToEven, subnormals are exact (no FTZ/DAZ), a fresh NaN is the canonical positive quiet NaN.
  - `sf_binop`: `+ - * / %` (exact fmod) and the six comparisons (NaN is unordered: only `!=` is true, `-0.0 == +0.0`). No panic and no overflow check on floats.
  - `sf_neg` flips only the sign bit (payload kept).
  - `sf_int_to_float` (all 12 integer types, incl. i128/u128, round-to-nearest-even, `u128::MAX as f32` is `+inf`), `sf_float_to_int` (saturating, `NaN -> 0`, all 12 targets), `sf_float_convert` (widening exact, narrowing rounded; NaN keeps sign and top payload bits).
  - Intrinsic kernel `sf_intrinsic` / `sf_intrinsic_kind`: `sqrt abs copysign floor ceil trunc round round_ties_even fma min max next_up next_down to_bits from_bits` (`op` or `op_<suffix>` names). `fma` is a single rounding from the exact product.
- **Dispatch (`compiler/interp/interp.ax`)**: `exec_assign_binop`, `exec_assign_unop`, `exec_assign_cast` branch on f32/f64 and the three float cast kinds before any integer logic; `eval_core_intrinsic` evaluates float intrinsics when the first parameter (return type for `from_bits`) is a float type; TLS/const initialisation and `interp_eval_const_expr_into` accept `CONST_FLOAT` (the bit pattern is kept in `int_val`). `compiler/interp_opt/session.ax` does the same for the comptime result.
- **Strict optimizer (`compiler/opt/const_fold.ax`, `dce.ax`)**: `opt_is_scalar_const_op` rejects `MIR_CONST_FLOAT` and any f32/f64-typed constant, so `do_const_fold_binop/unop` never fold float bits as integers; `do_const_fold_cast` refuses casts to floats. Because only constant/constant folding exists and there are no algebraic rewrites (`x+0.0`, `x*0.0`, `x-x`, `x==x`, `!(a<b)`, reassociation, FMA contraction), none of the forbidden rewrites can happen. DCE documents that BINARY_OP/UNARY_OP are not pure and keeps source order. `cfg_simp` only touches INT/BOOL switch constants (unchanged).

## Decisions (for the architect)
1. **Fresh-NaN sign**: the oracle returns the canonical positive qNaN (SPEC-41 AXS-FLT-002). A native SSE2 result has the sign bit set (x86 default NaN), which the spec calls unobservable. Arithmetic tests therefore use a NaN-tolerant comparison (`chkf32/chkf64`: both NaN = equal); `nan_canonical.ax` pins the exact oracle bits and is `modes: interp` for that reason ("oracle-only check").
2. **Float constants are never folded** (not even const op const) at -O1: the folder only handles INT/BOOL, and an IEEE-exact folder would duplicate the oracle's soft-float inside `compiler.opt`. Folding is allowed by the spec but not required; this is the safe reading. A later task may add exact folding by sharing `sf_*`.
3. **Float `const` items** still hit `AX_TYPE_UNSUPPORTED_IN_BOOTSTRAP` (typeck, outside paths); the comptime `CONST_FLOAT` result path is implemented but unreachable until T458b.
