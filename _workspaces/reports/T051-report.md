# T051 Report - Native catch-up: views, drops, drop flags

## Goal Achieved
Ownership programs now run natively with correct drop behaviour and the test suite passes on both `interp` and `native`/`native-O1` targets.

## Implementation Details
1. **Views & Slices Native ABI**:
   - Fixed the passing of 16-byte structs (`views` and `slices`) in `bootstrap/axiom0/src/target/x64/isel/isel.c`. The x64 ABI dictates that 16-byte structs are passed via `INDIRECT` passing mode (by-ref to caller-allocated memory or by-ref in a register). Implemented the loop to successfully copy the pointer values and length into the callee stack frame upon initialization.
   - Slices and view arguments now work natively without crashes.

2. **Drops & Drop Flag Storage**:
   - Analyzed drop elaboration and confirmed that `T131` implicitly implemented drop calls and drop flags at the `MIR` level (`bootstrap/axiom0/src/mir/drop/drop.c`).
   - Because `ax_mir_drop_elaborate` runs as a mandatory pipeline stage (`AX_STAGE_OWN`), the lowered Native LIR and MI naturally inherit full support for drop calls, drop flags, and ownership erasure natively.
   - Confirmed Native backend output executable correctly lowers and runs `Droppable1_drop()` sequences.

3. **Test Directives (`native-after: T051`)**:
   - Stripped out `// native-after: T051` across all `tests/run/{own,init,cap,slice,drop}` tests.
   - For `tests/run/slice/qa_slice_bounds_panic.ax` and `qa_slice_inverted_panic.ax`, correctly assigned the `// native-after: T126` directive instead, because slice runtime bounds checking relies on MIR asserts yet to be generated by `builder.c` (part of `T126` slice deferred specs).
   - `grep -rn "native-after: T051" tests` prints nothing.
