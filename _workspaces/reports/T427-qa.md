### 8. Boundary cross-check (step 5) — tests I added

Both run in interp, native and native-O1 and agree byte-for-byte with the oracle (loopback + Winsock):
- `tests/std/async/io/qa_net_edges.ax`: connect to a closed port -> `IoError.ConnectionRefused` (7); second `bind` of an in-use address ->
  `AddrInUse` (11); `read_exact(4)` after peer sent 2 bytes and half-closed -> `UnexpectedEof` (12); plain `read` after EOF -> `Ok(0)`;
  zero-length UDP datagram -> `recv_from` returns 0; UDP datagram larger than the receive buffer never overruns it.
  Result: `OK qa_net_edges refused=7 inuse=11 eof=12 zero_read=0 udp0=0 udp_trunc=ok` in all three legs. This also proves the new
  `io_error_from_code` mapping (-5..-11) is identical between the oracle backend and native Winsock error mapping.
- `tests/std/async/io/qa_file_edges.ax`: open of a missing file -> `NotFound`; sparse `write_at(100, ...)` then size 104; the 100-byte hole
  reads as zeros; `read_buf_at` returns exactly the 6 bytes available; `read_at` past EOF -> 0 bytes; zero-length `write_at` -> 0 and does not
  extend; `open_append_bytes` + `write_at(104)` -> size 106; explicit `close().await` on write handles.
  Result: `OK qa_file_edges notfound=1 size=104 hole=0 data=1 past_eof=0 zero_w=0 append=1` in all three legs.
Both test files remove their temp file (`build/qa_t427_edges.bin`) and, like the engineer's file test, assume `build/` exists in the
runner's cwd (true for the repo root and the snapshot).

Observations that did not become findings:
- Two `mut_view(client).read(...)` futures on one unsplit `AsyncTcpStream` can be outstanding at once (it type-checks): the futures do not
  hold the view. This follows SPEC-35 AXS-AIO-042 literally (receivers are `mut_view`, futures are plain return values), so REQ-CONC-152 is
  met at the signature level only. Architect may want to decide if the spec should say more (e.g. in-flight guard); no change requested here.
- `use after split()` was not reported by `axiomc2 check` (move analysis is not part of `check`); not pursued.

### 9. Spec check

- AXS-AIO-040..044 surface present: `Ipv4Addr`, `SocketAddr`, `AsyncTcpListener`/`AcceptFuture`, `AsyncTcpStream` (+`ShutdownMode`, `shutdown`,
  `split`, `close`), `TcpReadHalf`/`TcpWriteHalf` over refcounted `TcpStreamShared`, `tcp_rejoin`, `AsyncUdpSocket` (`send_to`/`recv_from`),
  `AsyncFile` with explicit fallible `close()` distinct from Drop. No `BOOTSTRAP-SHORTCUT` added.
- Documented deviations (engineer report): constructors take `*mut Reactor` rather than `view<Reactor>` (views cannot cross `.await`);
  `read_exact`/`write_all` are named future structs rather than `async fn`; `IoError` enum extended (variants inserted before `Other(i64)`,
  `@derive(Copy)` added; only std files match on `IoError`: grep over std/tests/compiler shows async_io, async_file, net, reactor, io only).
  Follow-up: architect should update SPEC-35 prose to the implemented signatures.
- Workaround in `std/sys/windows/iocp.ax`: `bind`/`shutdown` resolved at runtime via `GetModuleHandleA`/`GetProcAddress` because static `extern`
  names `bind`/`shutdown` collide with std method symbols in the native link. It works (all native legs PASS) but hides a real backend/linker
  bug; follow-up for a backend task: extern symbol names must not collide with Axiom method symbols.
- T426 files `std/async/timer.ax:459` and `std/async/timeout.ax:128` call `cx.waker()` without importing `std.asyn.waker`, so a program
  that imports `std.net`/`std.io.async_io` without any executor (which imports the waker module) fails with `AX_TYPE_UNKNOWN_FIELD` in std
  (repro: module that only does `use std.net.AsyncTcpStream` and `use std.net.SocketAddr` + `axiomc2 check`). Not reachable from any executor-based program and not
  in T427's paths; follow-up for the T426 owner (add `use std.asyn.waker...`).
