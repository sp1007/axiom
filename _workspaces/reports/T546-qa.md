### HEAD build issue (for the orchestrator; not a T546 finding)
The owner's claim that "stage1 build_axiomc.py crashes at HEAD" is a **configuration mistake, not a HEAD regression**. The evidence is below.
- `bootstrap/axiom0/CMakeLists.txt:16-17` forces `CMAKE_BUILD_TYPE=Debug` when none is given. The existing `build-snap-T546/build/CMakeCache.txt` was `Debug` with clang. A Debug axiom0 overflows the stack in stage1, and `_workspaces/T423j_build0.log` shows the same failure: `bootstrap: FAIL stage1 (axiom0 -> axiomc1) rc=3221225725` (0xC00000FD). The identical HEAD succeeded once configured `Release` (`T423j_build1.log`, `T540_build.log`, `T543_build.log`). The Release builds used `-DCMAKE_C_COMPILER=clang -DCMAKE_BUILD_TYPE=Release`, as `build-snap-T428m` also does. Rebuilt here that way, stage1 to stage3 pass and the fixed point hash is the same as in those logs (`ab15b62b...`).
- `-Wno-error=stringop-truncation` is only needed with **gcc**. The project's `-Werror` (CMakeLists.txt:36) fails gcc 15 `-O3` (Release) on `bootstrap/axiom0/src/link/pe/linker.c:169` and `:768` (`strncpy ... output may be truncated copying 8 bytes from a string of length 8`). I reproduced this in a throw-away build directory. clang builds the tree with 0 warnings, and clang is what the other gates use (CMakeCache `C:/msys64/ucrt64/bin/clang.exe`, Clang 22.1.4). The frozen file was last touched in T154 and T147. It is a latent gcc-only warning, not a HEAD regression. A follow-up, if wanted, is an AX0-FIX task (axiom0 is frozen) or a CMake `-Wno-error=stringop-truncation` for gcc. The gate convention should say: configure Release with clang.
- Recommendation: the orchestrator's `taskctl snapshot` or QA instructions should pass `-DCMAKE_BUILD_TYPE=Release -DCMAKE_C_COMPILER=clang`. The Debug default of the CMake file is what bit the T546 implementer, who then used gcc, which led to the `-Wno-error` workaround.
- Side note on the implementer's evidence: the report used `build-head-T428j/build/axiomc2.exe` because it could not build a compiler in the snapshot. This gate used a compiler built from the snapshot itself, and the results agree (10/10).
