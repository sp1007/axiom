### Findings
No FAIL findings.

Notes (not blocking):
- N1 behaviour change worth an architect look: `let r: i64 = -(~b8) + s64` with `b8: u8` was `AX_TYPE_NEG_UNSIGNED` before T499 and is now accepted (value 1256 for
  b8 = 255, s64 = 1000) because the `~b8` operand of `-` is itself a tree node typed i64. SPEC-40 rule 4 says unary `-` of an *unsigned operand* stays an error
  in a tree; `-(~b8)` has a signed (promoted) operand, so it follows rule 4 literally, but the spec does not mention it. I did not pin it in a test.
- N2 `thir` dump of the synthetic cast has no type child (the printer handles the null `cast_ty`); any future THIR consumer that assumes `cast_ty != null` must use
  `tc_is_promote_cast` semantics.
