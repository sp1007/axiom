### Defects

1. **Reassignment drops the old value BEFORE the rhs is evaluated (breaks SPEC-03 AXS-SEM-043, and rejects programs that used to compile).**
   `bootstrap/axiom0/src/mir/build/builder.c` (`AX_HIR_STMT_ASSIGN`, ~L2812-2826) and
   `compiler/mir/builder.ax` (`mir_build_stmt`, ~L7209-7229) emit `DROP(dest)` and only then
   `build_expr_into(rhs, dest)`. AXS-SEM-043 says: (1) evaluate rhs, ... (3) drop the old value,
   (4) store; "`x = transform(x)` reads the old x".
   Effects:
   - `let mut x = S{id:1}; x = transform(x);` (`S` with only scalar fields and an `impl Drop`) now
     fails with `error[AX_MOVE_USE_AFTER_MOVE]` in axiom0 and axiomc. The pre-fix axiom0 accepts it.
     Repro: `tests/run/drop/qa_t141_reassign_transform.ax`.
   - `x = S { id: x.id + 1u8 }` is rejected the same way, and the creation side effects of the rhs
     run after the old destructor. Repro: `tests/run/drop/qa_t141_reassign_eval_order.ax`
     (expected `5 6 1 2 9 3`).
   - Mutant M4 (reassignment drop removed) makes `qa_t141_reassign_transform.ax` pass, which
     confirms that this ordering is the cause.
   Fix: evaluate the rhs into a temporary, then drop the old value (the drop flag / elaboration
   handles the moved and uninitialised cases), then move the temporary into the place. Same in axiom0
   and the port.
2. **Selfhost bundles broken by the change.**
   - (a) `tests/selfhost/opt/qa_opt_unit.ax` does not compile (interp, native, native-O1):
     `AX_NAME_UNRESOLVED_IMPORT use compiler.mir.drop.mir_type_needs_drop` at L11298. The bundle embeds
     `compiler.verify.verifier` but not `compiler.mir.drop`. Regenerating with `gen_opt_tests.py`
     produces the same broken file, so the generator needs fixing (it is not in the report's file list).
   - (b) `tests/selfhost/verify/qa_verify_mir.ax` and
     `tests/selfhost/own_mir_verify/qa_own_mir_diff_diag_verify_mir.ax` fail in interp with
     `error[AX_UNSAFE_INTERP_UB]: null pointer dereference` (exit 125). Likely cause:
     `compiler/verify/verifier.ax:1770-1776` `verify_type_needs_drop_from_thir` builds
     `view(*zero_hir)` / `view(*zero_str)` from null pointers.
   - (c) `selfhost/driver/qa_driver_commands_a.ax` and `qa_driver_inspect_diff_a.ax` fail the same way
     in interp (these bundles are also stale, see 3).

5. **New axiom0/axiomc divergence in the port.** The axiomc_e2e oracle reports
   `REGRESSION tests/run/drop/qa_t141_aggregates.ax: obj O1: bytes differ (axiom0 10980, axiomc 9988); exe O1: bytes differ`.
   O0 is identical. Behaviour is the same: both print `9 1 2 3 4 5 6`. A scalar-impl-Drop struct
   inside an array, tuple, enum payload or wrapper struct lowers differently at -O1 in the port
   (ADR-0034 §2 parity). The other 2 REGRESSION lines are the defect-1 programs (both compilers reject
   them, with different diagnostic spans); they go away with fix 1.
6. **Assigning to a field does not drop the old value.** The new assignment drop is limited to
   `dest.proj_count == 0`. `let mut w = W{inner: S{id:1}, tag:0}; w.inner = S{id:2};` prints only
   `end d2`, so the old `S{1}` is never dropped (interp and native). AXS-SEM-043 step (3) applies to
   any place. Either implement it (same rhs-first order as fix 1) or record the limitation explicitly
   with an architect follow-up task. Right now the choice is silent.
7. **The mangle tests do not prove the ADR-0034 §6 change.** Mutant M3 (destructors named
   `<Type>_drop` again) passes every `run/mangle/` and `run/drop/` implementer test, including

   compiler fails these tests with `AX_LINK_DUPLICATE_SYMBOL` does not match the pre-fix run: they
   fail only because destructor output is missing. Add a test that pins the reserved form, e.g. a
   MIR/LIR/obj-symbol golden with `Foo$drop`, or a test that fails when the names collide. Correct
   the report's statement on whether §6 was needed.

### Findings

R1-1. **An assignment through a `view`/`mut_view` does not drop the old value (memory/destructor leak; the choice is made silently).**
   `bootstrap/axiom0/src/mir/build/builder.c:2825-2829` and `compiler/mir/builder.ax:7224`
   (`mb_place_is_deref`) skip the drop for any place that has a `Deref` projection. That covers
   auto-deref through a `mut_view`, not only raw pointers. The reason given ("std writes uninitialised
   slots with `*p = v`") applies only to raw-pointer stores. A view always points at an initialised
   value, so SPEC-03 AXS-SEM-043 step (3) applies there. The case is common: every
   `self.field = value` in a method with `self: mut_view<Self>`, where the field's type needs drop
   (`String`, `Vec`, `Box` now have a real `impl Drop`), leaks the old value. That also distorts the
   memory measurement T086 depends on (task Notes).
   Repro: `tests/run/drop/qa_t141_r1_assign_through_view.ax`. In `fn set_inner(w: mut_view<W>) { w.inner = S { id: 2u8 }; }`
   the expected output is `1\n9\n2\n`. The actual output in interp, native and native-O1 is
   `9\n2\n`, and axiomc O0/O1 gives the same `9\n2\n`, so the port has the same gap.
   Expected fix: emit the drop when the deref'd base is a `view`/`mut_view` (in axiom0 and the port).
   Keep the raw store for raw-pointer (`*mut T`/`*const T`) derefs, and record that rule explicitly:
   a sentence in SPEC-03/SPEC-12 through an architect follow-up, or an ADR note. A code comment is
   not enough. Add a test with a method `fn set(self: mut_view<Self>)` that reassigns a droppable
   field.
