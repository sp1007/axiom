## Options

### Baseline representation
1. Sample / isolate groups (the earlier rule). Rejected by the owner.
2. Mark the 87 tests `xfail` in place. Rejected: edits ~87 test files, several inside the running tasks' paths
   (`tests/selfhost`), and hides failures inside test sources where no gate looks at them.
3. **One named list `_workspaces/baseline-failures.txt` + one fix task per root-cause group (chosen).** Visible, owner
   path, mechanical subset check, each line traceable to a task.
4. One big "fix all baseline" task. Rejected: crosses four owners and several thousand lines; violates one-sitting.

### Making the complete run affordable
1. No cache, only more parallelism. Rejected: 4 shared cores.
2. Key on the hash of the whole repository tree. Sound, but every edit invalidates everything (~0 hit rate).
3. Key on test directory + the whole `std/` tree. Sound superset; still invalidates everything for every std task.
4. Scan `use` lines in Python to compute the loaded-module closure. Rejected: unsound (implicit loads: prelude, lang
   items such as `std/future` for `async`, `--std-root` overrides).
5. **The compiler reports every source file it actually loaded (`--dep-file`); the key covers exactly those bytes
   (chosen), with option 3 as the fallback when the compiler under test lacks the flag.**

## Decision

### §1 Baseline file and gate rule
- `_workspaces/baseline-failures.txt`: one id per line, columns `<test id>  <class>:<tag>  <fix task>`; `#` comments.
  Ids are the `axtest.py --list` ids; comparison is by id (all modes of an id share its line).
- A gate PASS requires `failing ids of the complete run ⊆ baseline ids`. A baseline id that now passes is reported as
  "baseline id now passing" and does not affect the verdict; the owning fix task deletes its line.
- Only the architect adds lines, always with an open fix task. A fix task's acceptance is "its ids pass in the complete
  run and its lines are removed from the baseline in the same commit". Every task that edits the file names it in
  `locks:` (the scheduler then never runs two of them together, so `accept` never commits another task's edit).

### §2 Classes and the 7 fix tasks
Classes: `regression` (the compiler/std behaviour is wrong; the test is right), `fixture-regen` (a generated or
committed expectation is stale and must be regenerated by its generator, never hand-edited), `undiagnosed` (cause not yet
known; the fix task diagnoses, then fixes or reports a split), `environment` (host toolchain/OS; none confirmed today).

### §3 Admission of pre-existing failures found later
The T421 gate did not run 155 `tests/selfhost` ids. When a complete run finds a failing id outside the baseline, the
gate re-runs that id on a snapshot without the task's change set (= HEAD). If it fails identically there, the gate's
verdict is **BLOCKED** (reason "pre-existing failure outside baseline", with the HEAD evidence), not FAIL and not PASS.
The architect then adds the id with a fix task (existing or new) and the gate re-concludes. If it passes at HEAD, it is
caused by the task: FAIL. The gate never edits the baseline.

### §4 Incremental per-test result cache (T437) — soundness conditions
A cache entry lets a later run report a result without executing the test. It is sound only if every condition holds:
- **S1 Key completeness.** `key = sha256` of a canonical encoding of: cache schema version; sha256 of the compiler
  binary; sha256 of `tools/axtest.py` and every runner module it imports; test id and mode (`interp`, `native`,
  `native-O1`, golden ext, …); the expanded compiler argv with temporary paths canonicalised; all runner options that
  change behaviour (`--std-root`, `--timeout-scale`, `--exe-suffix`, `--exclude-requires`, env vars the runner sets or
  the compiler reads, e.g. `AXIOM_STD`); the test file bytes; every expectation file (golden, `.stdout`, `.stderr`);
  every file in the compiler-reported dependency list with its sha256 (paths relative to the repo root or std root);
  the host platform tag (OS build, architecture).
- **S2 Dependency list from the same run.** The compiler writes `--dep-file=<path>`: every source file its source
  database loaded (root, multi-file modules, std, prelude, lang-item modules, `axiom.toml`), one `path sha256` per line,
  sorted. The runner hashes those files again after the run; any mismatch (file changed during the run) stores nothing.
  A compiler without `--dep-file` falls back to the sound superset "test directory tree + whole std root".
- **S3 Only passes.** Only PASS results are stored. FAIL, SKIP, XFAIL, timeouts, crashes, WEAK-NATIVE results are never
  stored. A native entry covers the whole compile + execute + compare result.
- **S4 Deterministic tests only.** Never cached: `cmd:` tests (inputs not known to the runner) unless they declare
  `cache-inputs:` naming every input file/dir; tests with any `requires:` host feature; tests whose dependency list
  contains a file under `std/thread`, `std/sync`, `std/async`, `std/time` or OS thread/timer bindings (scheduling and
  timing are not inputs); tests marked `nocache:`.
- **S5 Gate provenance.** Each entry records its producer: snapshot id, the snapshot's base commit and the sha256 of its
  change set. A gate may use an entry only if (a) the key matches exactly, (b) the entry was produced inside a
  `build-snap-*` snapshot whose base commit is an ancestor of, or equal to, the current HEAD, and (c) the compiler binary
  was built in a snapshot by `tools/build_axiomc.py` (entries made with a hand-built compiler or in the main working tree
  are `origin: local` and are used only for local speed, never by a gate).
- **S6 Verification sample.** A gate using the cache re-runs fresh a random sample of max(20, 5 %) of its hits, with the
  seed printed in the QA file. Any mismatch disables the cache for that gate (complete `--no-cache` rerun) and is a QA
  finding against the cache.
- **S7 Integrity.** One file per entry named by the key hash, written atomically (temp + rename), holding the key
  material and a sha256 of the record; an unreadable or inconsistent entry is a miss and is deleted (REQ-TST-057).
  Location `_workspaces/artifacts/axtest-cache/` (already git-ignored), shared by snapshots via an absolute
  `--cache-dir`; size-bounded LRU pruning.
- **S8 Transparency and fresh runs.** The summary prints `CACHED n` next to PASS/FAIL; the QA file records hits,
  misses and the sample. `--no-cache` forces a fresh run. Phase gates (T3NN) and the first gate after a cache-format
  change run with `--no-cache`.

Compile cost of `tests/selfhost` bundles: T437 measures one heavy bundle (e.g. `tests/selfhost/opt/qa_opt_pipeline.ax`)
with `--time-passes` under `axiomc2` in `--interp`, `-O0` and `-O1`, records the per-pass table in its report, and adds
longest-first scheduling (durations recorded from previous runs) so `-j N` wall time is not dominated by a late heavy
bundle. A pass that takes > 30 % of the compile time or grows super-linearly becomes an architect follow-up task; T437
does not optimise compiler passes itself.

### §5 Process rule
`axiom-tasks` SKILL.md gains one rule: every task's acceptance includes the complete-suite baseline rule; a task cannot
be accepted while its gate's failing ids are not a subset of the baseline (the gate verdict is FAIL or BLOCKED per §3).
`taskctl accept` already refuses a non-PASS verdict, so no script change is needed. T437 adds `axtest.py --baseline
<file>` to print the subset check mechanically (`BASELINE OK` / `NEW FAILURES: …`).

### §6 Addendum (2026-11-13): split of T437 for the per-task gate scope
Context: the owner then limited the per-task gate to about 60-90 minutes (task tests + affected set + smoke set +
archcheck; periodic full runs cover the rest; `.claude/agents/axiom-qa.md` "Per-task gate scope", "Periodic full run")
and asked for T437 first in line. T437 depended on T452 and locked `tests/selfhost`, `compiler/driver`,
`compiler/source` only because of the compiler `--dep-file` flag and bundle regeneration; its runner part touches only
`tools/`.
Options: (1) keep T437 whole, wait for T452 — rejected, delays the tool that makes every gate cheaper; (2) start T437
now with `--force` — rejected, collides with T452's `tests/selfhost` lock; (3) **split by file ownership (chosen)**:
- **T437a** (axiom-qa, opus, no dependency, priority 10, paths only `tools/` + `tools/tests/` + `tests/smoke.list`):
  §4 S1-S8 with the superset fallback and a stub-tested exact path; `--affected` (exact dep lists when cached, else the
  grep rule + a checked-in `tools/affected_map.txt` compiler-module → test-group table, derivation printed);
  `--smoke` (checked-in `tests/smoke.list`: `always:` cases + per-group pools of light ids, one per group drawn with a
  printed seed, `--smoke --check` bounds it to ~20 min at `-j 2`); durations + longest-first; selfhost bundle
  `--time-passes` profile; `--baseline`; `tools/taskgate.py` = whole per-task gate in one command with a Markdown +
  JSON summary for the QA file. Named `taskgate.py` to stay distinct from the phase-gate checker `tools/gatecheck.py`.
- **T437b** (axiom-stdlib, opus, depends T452 + T437a, priority 11, locks `compiler/driver`, `compiler/source`,
  `tests/selfhost`): the `--dep-file` flag, bundle regeneration, warm/cold measurements with exact deps.
Priority 10 is the lowest non-critical value (critical is < 10, which would drain the other slots), so T437a is the
first pick when a slot frees and is not forced to run alone. T437 is closed as superseded; no other task depended on it.
Rationale: the cache alone cannot shorten a per-task gate whose compiler changed (binary hash in the key); the
selection tooling (`--affected`, `--smoke`, `taskgate.py`) is what makes the 60-90 minute target mechanical and
auditable, and it needs no compiler change.
Revisit: no.

## Consequences
- The T452 and T422 gates apply the subset rule by hand against this file; from T437 on, by `--baseline`.
- Feature work is not frozen: fix tasks have lower priority numbers, so the scheduler picks them first whenever their
  dependencies and locks allow. Because they all lock `tests/selfhost` and the baseline file, they run one at a time
  (except T430 and the non-overlapping feature tasks).
- The baseline must only shrink, except for §3 admissions; every admission is recorded in the ROADMAP change log.
- Affected files: `_workspaces/baseline-failures.txt`, `.claude/skills/axiom-tasks/SKILL.md`, `spec/ROADMAP.md` (change
  log), board tasks T434–T437, T430–T433, T311 (depends).
- Revisit: yes — D4 (prelude `Ordering`) if lang-item lookup requires the prelude placement; §4 if a verification
  sample ever mismatches.
