# ADR-0016 — VS0 gate fix tasks (unblock of T022)

Status: accepted (2026-10-06) · Class: plan change (TYPE A bugs routed to owners; no semantic change)
Revisit: no

## Tóm tắt
Cổng VS0 (T022) bị chặn vì 68 test vs0 thất bại do lỗi cài đặt — không phải lỗ hổng đặc tả — ở
parser, typeck/driver, MIR builder và interpreter, cộng thêm một vi phạm quy tắc (d) của bảng
(F-CONST.SCALAR do T061 cung cấp nhưng T069 không phụ thuộc T061).
Quyết định: tạo bốn task sửa lỗi theo đúng chủ sở hữu module, đường dẫn tách rời để chạy song song:
T114 (parser, frontend), T115 (typeck/driver, frontend), T116 (MIR builder, semantics) và T117
(interpreter, semantics, chạy sau T116 vì phải thực thi `Assert` do T116 sinh ra). T022 phụ thuộc cả
bốn; bộ test vs0 giữ nguyên, không nới tiêu chí nghiệm thu, không dùng xfail.
T069 thêm phụ thuộc T061. `tools/ci.ps1` được đưa vào `paths` của T022 để căn chỉnh với `ci.sh`.
Không có yêu cầu OWNER.md nào bị bỏ; T224 vẫn deferred.

## Context
T022 attempt 1 delivered the VS0 suite (`tests/conformance/vs0`), `tools/gatecheck.py` and its
self-tests; `gatecheck --gate T022` reports MS-P3 BLOCKED. `_workspaces/reports/T022-report.md`
isolates every failure to one stage: parser P1–P5 (`syntax/parse.c`), typeck/driver T1–T5
(`types/typeck.c`, `driver/pipeline.c`), MIR builder M1–M3 (`mir/build/builder.c`), interpreter
I1–I5 (`interp/interp.c`), plus board rule (d) at `spec/selfhost-subset.tsv:45`. All bugs contradict
existing canonical rules (SPEC-02 precedence/associativity, SPEC-03 AXS-SEM-010/021/071, FP-03,
AXS-LEX-054); none is a spec gap. The delivering tasks (T011/T012, T016/T017, T019, T021) are done.

## Options
1. **Relax T022** (xfail the failing tests). Rejected: ROADMAP R9 / ADR-0005 §3 allow xfail only for
   spec gaps with an ADR; implementation bugs must be fixed before a gate closes.
2. **Widen T022's paths** so the QA owner fixes compiler code. Rejected: the gate's owner (axiom-qa)
   would grade its own fixes, and one task would span four modules (> one sitting).
3. **Reopen the done tasks** T011/T017/T019/T021. Rejected: done tasks are committed history; the
   board has no reopen, and their scope differs from the bug lists.
4. **One fix task per owning area, disjoint paths, gate depends on all** (chosen).

## Decision
- T114 `VS0 fix: parser…` — axiom-frontend, P2, paths `syntax`, `tests/parse`, `tests/ui/parse`,
  `tests/hir`, `tests/resolve`; lock `PARSE.def`.
- T115 `VS0 fix: typeck…` — axiom-frontend (per the unblock brief: frontend owns typeck/driver
  fixes), P3, paths `types`, `tests/typeck`, `tests/ui/typeck`, `driver/cmd_check.c`,
  `tests/driver`; locks `TYPE.def`, `driver/pipeline.c`.
- T116 `VS0 fix: MIR builder…` — axiom-semantics, P3, paths `mir/build`, `tests/mir/build`; lock
  `interp/interp.c` only for `AX_MIR_TERM_ASSERT` dispatch so the full suite stays green.
- T117 `VS0 fix: interpreter…` — axiom-semantics, P3, depends T116, paths `interp`,
  `tests/run/basic`, `driver/cmd_run.c`; locks `driver/pipeline.c`, `DRIVER.def`.
- T114, T115 and T116 run in parallel (priority 11, not architecture-critical); T115 and T117
  serialise on the `pipeline.c` lock. T022 depends on T114–T117 and keeps its attempt-1 suite
  unchanged; it also owns `tools/ci.ps1` to align it with `tools/ci.sh` (CI scripts are gate-editable
  per T004).
- Board rule (d): T069 depends on T061 (option "add T061 to T069" from the report; changing the
  consumer would hide the real need of std core for MIN/MAX and hash constants, BC-01).

## Consequences
- T022 becomes ready only after the four fix tasks are accepted; T023 (and the P4 chain) waits as
  before.
- The FP-03 MIR golden `tests/mir/build/first_mir.mir` is regenerated by T116 (checked Add + assert
  edge), which T023 relies on (AXS-BOOT-007).
- T069 now waits for T061 as well; no phase change (both P7/P9 already ordered).
