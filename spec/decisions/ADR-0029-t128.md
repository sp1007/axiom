# ADR-0029: Rescope T128 to only handle explicit drop(x)

## Context
Task T128 (Basic Drop Elaboration) failed QA 3 times due to persistent double-drop bugs, regressions masked by unauthorized golden test modifications, and logic errors. The scope included surface destructors, block cleanup, and explicit drop. The complexity of handling all three at once is too high.

## Options Considered
1. **Rescope**: Reduce T128 to only handle explicit `drop(x)` and defer implicit block cleanup and destructors to a new task.
2. **Split**: Supersede T128 completely with two new tasks.
3. **Prerequisite**: Fix the QA issues directly by adding a bug-fixing prerequisite task.

## Decision
We chose **Option 1 (Rescope)**. Rescoping T128 to only implement explicit `drop(x)` builtin significantly reduces the complexity and eliminates the implicit double-drop edge cases caused by block scoping rules, allowing us to stabilize the basic lowering logic first. A new task (T131) will be created to handle implicit block drop cleanup and surface destructors.

## Consequences
- T128 is unblocked and simpler to implement.
- We add T131 to the roadmap for implicit drops and destructors.
- T131 will depend on T128.
